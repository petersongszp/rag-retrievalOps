# 早日上岸AI智能面试平台后端架构设计

## 1. 架构概述

基于需求文档和技术选型，我们设计了一个基于字节跳动Hertz框架和Eino框架的微服务架构，用于实现早日上岸AI智能面试平台。该架构充分利用了Hertz框架的高性能HTTP服务能力和Eino框架的AI应用开发优势，实现了面试流程管理、AI交互、评估分析等核心功能。

### 1.1 技术栈选择评估

#### Hertz框架评估
- **优势**：高性能HTTP框架，字节跳动开源，具有高易用性、高性能和高扩展性
- **适用场景**：作为API网关和微服务间通信的HTTP框架
- **合理性**：完全满足面试平台的API服务需求，特别是在处理并发请求方面表现优异

#### Eino框架评估
- **优势**：专为大模型应用开发设计，提供组件化设计、图编排引擎、流式处理机制等
- **适用场景**：实现AI面试对话、简历分析、问题生成、答案评估等核心AI功能
- **合理性**：与面试平台的AI交互需求高度匹配，可以显著简化AI功能的开发复杂度

#### 组合使用评估
- **互补性**：Hertz负责HTTP服务和路由，Eino负责AI逻辑处理，形成良好的职责分离
- **技术生态**：均为字节跳动开源产品，技术栈一致性高，便于维护
- **性能优势**：两个框架都经过字节跳动内部大规模验证，性能表现优异

## 2. 系统架构设计

### 2.1 总体架构图

```
用户层
  ↓
API网关层 (Hertz)
  ↓
服务层
  ├── 用户服务 (Hertz)
  ├── 面试管理服务 (Hertz)
  ├── 简历分析服务 (Eino + Hertz)
  ├── 题库管理服务 (Hertz)
  ├── AI交互服务 (Eino + Hertz)
  └── 评估报告服务 (Eino + Hertz)
  ↓
数据层
  ├── MySQL (用户、面试记录等结构化数据)
  ├── Redis (缓存、会话管理)
  └── 对象存储 (简历文件)
```

### 2.2 微服务拆分

#### 2.2.1 用户服务
- **职责**：用户注册、登录、信息管理
- **技术栈**：Hertz + MySQL
- **核心API**：
  - POST /api/users/register - 用户注册
  - POST /api/users/login - 用户登录
  - GET /api/users/profile - 获取用户信息
  - PUT /api/users/profile - 更新用户信息

#### 2.2.2 面试管理服务
- **职责**：面试创建、管理、状态追踪
- **技术栈**：Hertz + MySQL + Redis
- **核心API**：
  - POST /api/interviews - 创建面试
  - GET /api/interviews/{id} - 获取面试详情
  - GET /api/interviews - 获取用户面试列表
  - PUT /api/interviews/{id}/status - 更新面试状态

#### 2.2.3 简历分析服务
- **职责**：简历上传、解析、关键信息提取
- **技术栈**：Hertz + Eino + 对象存储
- **核心API**：
  - POST /api/resumes - 上传简历
  - GET /api/resumes/{id} - 获取简历信息
  - POST /api/resumes/{id}/analyze - 分析简历
  - GET /api/resumes/{id}/keywords - 获取简历关键词

#### 2.2.4 题库管理服务
- **职责**：题目管理、分类、检索
- **技术栈**：Hertz + MySQL
- **核心API**：
  - GET /api/questions/categories - 获取题目分类
  - GET /api/questions - 查询题目
  - POST /api/questions - 新增题目
  - PUT /api/questions/{id} - 更新题目

#### 2.2.5 AI交互服务
- **职责**：面试对话、问题生成、追问处理
- **技术栈**：Hertz + Eino + 外部AI模型
- **核心API**：
  - POST /api/interviews/{id}/questions/generate - 生成问题
  - POST /api/interviews/{id}/answers/submit - 提交答案
  - GET /api/interviews/{id}/conversation - 获取对话历史

#### 2.2.6 评估报告服务
- **职责**：答案评估、报告生成、技能分析
- **技术栈**：Hertz + Eino + MySQL
- **核心API**：
  - POST /api/interviews/{id}/evaluate - 评估面试
  - GET /api/interviews/{id}/report - 获取面试报告
  - GET /api/users/{id}/stats - 获取用户统计数据

### 2.3 数据流设计

```
用户 -> API网关 -> 面试管理服务(创建面试) -> 简历分析服务(分析简历)
  ↓
AI交互服务(生成问题) -> 用户(回答问题) -> AI交互服务(提交答案)
  ↓
评估报告服务(评估答案) -> 生成面试报告 -> 用户(查看报告)
```

```go
// 创建面试工作流
func CreateInterviewWorkflow() *eino.Workflow {
    workflow := eino.NewWorkflow("interview_process")
    
    // 添加节点
    resumeNode := workflow.AddNode("analyze_resume", resumeAnalyzer)
    questionNode := workflow.AddNode("generate_question", questionGenerator)
    evaluateNode := workflow.AddNode("evaluate_answer", answerEvaluator)
    reportNode := workflow.AddNode("generate_report", reportGenerator)
    
    // 定义流程
    workflow.Connect(resumeNode, questionNode)
    workflow.Loop(questionNode, evaluateNode, 5) // 循环5轮问答
    workflow.Connect(evaluateNode, reportNode)
    
    return workflow
}
```

## 4. Hertz框架应用设计

### 4.1 API路由设计

```go
// 初始化Hertz路由
func InitRouter() *hertz.Hertz {
    h := hertz.New()
    
    // 中间件
    h.Use(middleware.Logger())
    h.Use(middleware.Recovery())
    h.Use(middleware.CORS())
    
    // API路由组
    api := h.Group("/api")
    
    // 用户相关路由
    users := api.Group("/users")
    {
        users.POST("/register", userService.Register)
        users.POST("/login", userService.Login)
        users.GET("/profile", middleware.Auth(), userService.GetProfile)
        users.PUT("/profile", middleware.Auth(), userService.UpdateProfile)
    }
    
    // 面试相关路由
    interviews := api.Group("/interviews", middleware.Auth())
    {
        interviews.POST("", interviewService.Create)
        interviews.GET("", interviewService.List)
        interviews.GET("/:id", interviewService.Get)
        interviews.PUT("/:id/status", interviewService.UpdateStatus)
        interviews.POST("/:id/questions/generate", aiService.GenerateQuestion)
        interviews.POST("/:id/answers/submit", aiService.SubmitAnswer)
        interviews.POST("/:id/evaluate", reportService.Evaluate)
        interviews.GET("/:id/report", reportService.GetReport)
    }
    
    // 简历相关路由
    resumes := api.Group("/resumes", middleware.Auth())
    {
        resumes.POST("", resumeService.Upload)
        resumes.GET("", resumeService.List)
        resumes.GET("/:id", resumeService.Get)
        resumes.POST("/:id/analyze", resumeService.Analyze)
    }
    
    return h
}
```

### 4.2 中间件设计

```go
// 认证中间件
func Auth() app.HandlerFunc {
    return func(c context.Context, ctx *app.RequestContext) {
        token := ctx.GetHeader("Authorization")
        if token == "" {
            ctx.AbortWithStatusJSON(401, map[string]string{"error": "未授权"})
            return
        }
        
        // 验证token
        userID, err := authService.ValidateToken(token)
        if err != nil {
            ctx.AbortWithStatusJSON(401, map[string]string{"error": "无效的token"})
            return
        }
        
        // 设置用户ID到上下文
        ctx.Set("userID", userID)
        ctx.Next(c)
    }
}
```

## 5. 数据库设计

### 5.1 数据库表结构

#### 5.1.1 users表
```sql
CREATE TABLE users (
    id VARCHAR(36) PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    avatar_url VARCHAR(255),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

#### 5.1.2 interviews表
```sql
CREATE TABLE interviews (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(36) REFERENCES users(id),
    resume_id VARCHAR(36) REFERENCES resumes(id),
    interview_type VARCHAR(50) NOT NULL,
    category VARCHAR(50) NOT NULL,
    difficulty VARCHAR(50) NOT NULL,
    duration INT, -- 分钟
    overall_score FLOAT,
    status VARCHAR(20) DEFAULT 'created', -- created, in_progress, completed, cancelled
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    completed_at TIMESTAMP
);
```

#### 5.1.3 resumes表
```sql
CREATE TABLE resumes (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(36) REFERENCES users(id),
    file_url VARCHAR(255) NOT NULL,
    filename VARCHAR(255) NOT NULL,
    content TEXT,
    analyzed_data JSON,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 5.1.4 questions表
```sql
CREATE TABLE questions (
    id VARCHAR(36) PRIMARY KEY,
    interview_id VARCHAR(36) REFERENCES interviews(id),
    content TEXT NOT NULL,
    question_type VARCHAR(50) NOT NULL,
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 5.1.5 answers表
```sql
CREATE TABLE answers (
    id VARCHAR(36) PRIMARY KEY,
    question_id VARCHAR(36) REFERENCES questions(id),
    content TEXT NOT NULL,
    score FLOAT,
    evaluation_data JSON,
    submitted_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 5.1.6 reports表
```sql
CREATE TABLE reports (
    id VARCHAR(36) PRIMARY KEY,
    interview_id VARCHAR(36) REFERENCES interviews(id),
    overall_score FLOAT,
    skills_json JSON, -- 各技能评分
    strengths TEXT, -- 优点，JSON数组
    weaknesses TEXT, -- 不足，JSON数组
    suggestions TEXT, -- 建议，JSON数组
    detailed_feedback TEXT,
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 10. 结论

该架构具有良好的可扩展性、可维护性和性能表现，能够支持平台的快速迭代和用户量的增长。通过微服务的拆分，各个功能模块可以独立开发和部署，提高了开发效率和系统稳定性。
