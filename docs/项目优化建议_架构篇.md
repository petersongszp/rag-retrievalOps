## 1. 模块边界优化 🔴 P0

### 问题描述

**当前存在的问题**:
1. `internal/service/interviews` 直接调用 `chatApp/agent/ext` → 循环依赖风险
2. 模块命名不一致：`ai-eino-agent` vs `ai-eino-interview-agent`
3. chatApp 既是独立应用又被其他模块依赖 → 职责混乱

### 建议的目录结构

```
backend/
├── cmd/                    # 应用入口（新增）
│   ├── server/            # HTTP API 服务器
│   │   └── main.go
│   └── chatcli/           # 命令行工具（可选）
│       └── main.go
│
├── internal/              # 内部业务逻辑
│   ├── domain/           # 领域模型（新增）
│   ├── repository/       # 数据访问层
│   ├── service/          # 业务服务层
│   ├── handler/          # HTTP 处理器
│   ├── middleware/       # 中间件
│   └── config/           # 配置管理
│
├── pkg/                   # 可复用的公共包（新增）
│   ├── agent/            # Agent 框架（从 chatApp/agent 迁移）
│   ├── errors/           # 统一错误处理
│   ├── logger/           # 日志封装
│   └── cache/            # 缓存封装
│
├── api/                   # API 定义
├── modelmgr/             # 模型管理器
└── configs/              # 配置文件
```

### 实施步骤

1. **创建新目录结构**（1天）
2. **重构 chatApp/agent 为 pkg/agent**（2-3天）
3. **在 internal/service 中使用 pkg/agent**（1天）
4. **统一模块命名**（1天）

```bash
# Step 1: 创建目录
mkdir -p cmd/server pkg/agent pkg/errors pkg/logger
mv backend/main.go cmd/server/main.go

# Step 4: 统一模块名
find . -type f -name "*.go" -exec sed -i '' 's/ai-eino-agent/ai-eino-interview-agent/g' {} +
go mod tidy
```

## 2. 启用已有组件 🔴 P0

### 问题描述

`main.go` 中大量组件被注释掉：
- Redis 初始化（54-59行）
- Eino 框架初始化（61-67行）
- Milvus 初始化（69-80行）

### 为什么需要这些组件？

- **Redis**: 缓存、会话管理 → 提升性能
- **Milvus**: 向量检索 → 简历分析、问题匹配
- **Eino**: AI 框架 → 可能通过其他方式初始化

### 解决方案：特性开关

**修改 config.yaml**:
```yaml
# 特性开关
features:
  enable_redis: true
  enable_milvus: true
  enable_metrics: true
  enable_swagger: true
```

**修改 main.go**:
```go
func main() {
    cfg, _ := config.LoadConfig("configs/config.yaml")
    
    // 数据库（必需）
    repository.InitDatabase(cfg.Database)
    
    // Redis（可选）
    if cfg.Features.EnableRedis {
        log.Println("Initializing Redis...")
        repository.InitRedis(cfg.Redis)
        log.Println("✓ Redis initialized")
    } else {
        log.Println("⊘ Redis disabled")
    }
    
    // Milvus（可选）
    var milvusMgr *milvus.Manager
    if cfg.Features.EnableMilvus {
        log.Println("Initializing Milvus...")
        milvusMgr, _ = milvus.InitMilvusManager(ctx, cfg)
        log.Println("✓ Milvus initialized")
        defer milvusMgr.Close()
    }
    
    // 启动服务器...
}
```

## 3. 微服务拆分准备 🟡 P2

### 当前策略：保持单体架构

**原因**:
1. 团队规模小，微服务管理成本高
2. 业务未稳定，过早拆分增加重构成本
3. 单体架构更易调试

### 但需要做准备

**设计原则**:
- ✅ 模块化：低耦合
- ✅ 接口化：模块间通过接口通信
- ✅ 配置化：独立配置
- ✅ 可观测：日志、指标、追踪

**未来架构规划**:
```
API Gateway
    ↓
┌───────────┬──────────────┬────────────┐
│User Service│Interview Svc │ AI Service │
└───────────┴──────────────┴────────────┘
```

**现在要做的**:
1. 定义清晰的模块边界
2. 使用依赖注入
3. 用 Context 传递请求信息

```go
// 依赖注入容器示例
type Container struct {
    UserRepo      repository.UserRepository
    InterviewRepo repository.InterviewRepository
    UserService   service.UserService
    Cache         cache.Cache
}
```

## 4. 配置管理优化 🟠 P1

### 当前问题

1. config.yaml 包含示例密钥 → 安全风险
2. 环境变量使用不统一
3. 缺少配置验证

### 优化方案

**1. 配置分层**:
```
configs/
├── config.yaml          # 基础配置
├── config.dev.yaml      # 开发环境
├── config.prod.yaml     # 生产环境
└── config.example.yaml  # 示例（不含敏感信息）
```

**2. 环境变量规范**:
```yaml
# 支持默认值语法
server:
  host: "${SERVER_HOST:0.0.0.0}"
  port: "${SERVER_PORT:8888}"

# 必需环境变量（无默认值）
database:
  dsn: "${DATABASE_DSN}"

security:
  jwt_secret: "${JWT_SECRET}"
```

**3. 配置验证**:
```go
func (c *Config) Validate() error {
    if c.Database.DSN == "" {
        return errors.New("database.dsn is required")
    }
    if c.Security.JWTSecret == "change-this-secret" {
        return errors.New("jwt_secret must be changed")
    }
    return nil
}
```

**4. 加载流程**:
```go
func LoadConfig(path string) (*Config, error) {
    // 1. 加载基础配置
    cfg := &Config{}
    loadYAML(path, cfg)
    
    // 2. 加载环境覆盖配置
    env := os.Getenv("APP_ENV") // dev/prod
    loadYAML(fmt.Sprintf("config.%s.yaml", env), cfg)
    
    // 3. 展开环境变量
    cfg.ExpandEnv()
    
    // 4. 验证
    return cfg, cfg.Validate()
}
```
