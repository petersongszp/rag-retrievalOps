# 项目目录优化建议（渐进式落地方案）

## 目标
- 提升目录可读性与可维护性，降低跨团队协作成本
- 统一命名与职责边界，为后续自动化与发布奠定基础
- 在不影响现有开发的前提下，分阶段完成重组

## 现状诊断
- 顶层混杂：代码（backend、frontend）、书稿与文档（co-write、doc、.qoder/repowiki）并存，命名中英文混用，入口不清晰
- 后端层级不统一：`chatApp` 与 `cmd` 并存，[backend/main.go](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/backend/main.go) 与 [backend/chatApp/main.go](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/backend/chatApp/main.go)存在重复角色
- 目录拼写问题：`mcp-moduel` 应为 `mcp-module`（影响认知与检索）
- 配置分散：根目录与 backend 下同时存在 `config.yaml/.env`，且 [frontend/README.md](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/frontend/README.md) 与根 [README.md](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/README.md) 未形成统一入口
- 文档分散且层次不一：`doc`、`.qoder/repowiki`、`co-write` 各自成系，缺少统一导航与索引
- Compose 多版本并存：`docker-compose-example.yml`、`docker-compose-prod.yml`、`docker-compose.yml`，环境切换策略不清晰

## 建议的目标结构（不一次性重构，允许过渡）
- 顶层分域
  - [ ] `/apps/backend`：后端服务（由现 `/backend` 迁移）
  - [ ] `/apps/frontend`：前端应用（由现 `/frontend` 迁移）
  - [ ] `/docs`：合并 `doc` 与 `.qoder/repowiki`，形成统一知识库与书稿区
  - [ ] `/configs`：环境与模板配置（例如 `config.example.yaml`、`compose` 的环境文件）
  - [ ] `/scripts`：通用脚本（如生成、数据导入、CI 辅助）
  - [ ] `/tools`：开发工具与代码生成产物（如 Thrift/Swagger 生成器）
  - [ ] `/packages`：未来共享库（如跨服务的 Go 包、前端共享模块）
- 立即可执行的轻量改进
  - [x] 修正 `mcp-moduel` 为 `mcp-module`
  - [ ] 根 README 强化导航，明确后端/前端/文档入口
  - [ ] 为现状编写结构说明文档（STRUCTURE.md），降低迁移期间认知成本

## 后端重构细化（渐进）
- 统一二进制入口
  - 将 `chatApp`、`cmd/debug_network` 统一到 `cmd/<service>` 格式
  - 保留一个清晰的主入口，例如 `cmd/server/main.go`，替代多处 `main.go`
- 目录职责边界
  - `internal/`：仅对本仓库可见的实现与子模块
  - `pkg/`：可被外部或多服务复用的库（已存在，可继续沉淀）
  - `api/` 与 `router/`：建议统一命名（如 `server/api`、`server/router`）或合并为 `server/http`
  - `idl/`：保留 Thrift 源文件，并将生成代码输出至 `backend/gen/thrift`
- 配置规范
  - 根 `.env` 禁止提交敏感信息；`config.example.yaml` 作为模板，运行时读取 `CONFIG_PATH` 或约定目录
  - 单一配置入口，避免前后端各自复制环境变量
- 参考链接
  - Eino/Milvus 模块说明：[readme.md](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/backend/internal/eino/milvus/readme.md)

  - 关键文档示例：后端架构 [后端架构设计.md](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/doc/后端架构设计.md)、功能分析 [AI功能分析与实现架构设计.md](file:///Users/wangzhongyang/go/code/go-eino-interview-agent-co-write/doc/AI功能分析与实现架构设计.md)

## DevOps 与工程化
- Makefile（建议新增）
  - `make backend`、`make frontend`、`make run`、`make test`、`make lint`
  - 与 `docker-compose`、环境变量集成，降低启动与联调成本
- Docker/Compose
  - 统一命名为 `docker-compose.yml`，结合 `compose.override.yml` 管理开发/生产差异
  - 使用 `.env` + `configs/` 管理不同环境参数

## 风险控制与回退
- 引用断裂风险：为被外部引用的文档保留重定向/指引页
- 多入口服务风险：在 `cmd/` 收敛前，保留原 `main.go` 并加启动提示
- 配置变更风险：通过 `CONFIG_PATH`、`.env` 兼容旧路径；提供迁移工具脚本
