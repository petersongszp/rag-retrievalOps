# 意图识别、推理与决策：现状与改进建议

## 结论概览
- 意图识别：当前以入参路由为主，未做自然语言意图分类与动态路由
- 逻辑推理：通过面试循环与上下文滚动实现，无显式 Graph/Chain 编排
- 决策/工具选择：依赖模型隐式 Planner 与布尔开关，缺少统一策略层

## 现有实现位置
- 路由与会话
  - engine.go:selectAgentType（按 Type/Domain 映射智能体）
  - types.go:InterviewSession（Type、Domain、Difficulty 等作为路由依据）
  - interview_agent_service.go:GetInterviewAgent（“路由→实例化”入口）
- 推理与迭代
  - engine.go:RunInterviewLoop（逐题生成，保留最近5题历史；SSE交互与数据库保存）
  - interview_agent_service.go:runAgentWithIterator（Eino Runner 事件迭代）
  - pkg/eino/callbacks/monitoring.go（组件开始/结束、耗时、错误与token观测）
- 工具与检索
  - chatApp/tool 下简历与面试记录工具（get_resume_info_tool.go、get_mianshi_info_tool.go）
  - RAG/Milvus 检索（milvus_retriever_tool.go、internal/eino/milvus/retrieval/retriever.go）

## 关键缺口
- 意图识别：未对自然语言 Query 做分类映射至 AgentType/Domain；无置信度与回退
- 推理编排：未用显式 Graph/Chain，对节点数据流不可视、难扩展与测试
- 决策策略：缺少统一 Policy/Planner 层，工具选择与重试/降级缺少裁决逻辑

## 已补充的基础实现（默认关闭，零侵入）
- 意图与策略骨架
  - internal/agent/intent/classifier.go：根据 Type/Domain/Query 做轻量规则分类，输出 AgentType 与置信度
  - internal/agent/policy/planner.go：统一决策接口，包含智能体选择与是否启用简历工具
- 引擎接入（保留原逻辑兜底）
  - backend/api/handler/interview/mianshi/engine.go：在 RunInterviewLoop 中增加 Planner 可选分支；未开启时沿用 selectAgentType 与 HasResume
- 启用方式
  - 环境变量 INTENT_PLANNER_ENABLED=1 开启策略层；默认关闭不影响现有行为

## 下一步强化建议
- 意图识别
  - 引入分类模型或零样本分类，将 Query/上下文映射到 AgentType/Domain，并暴露置信度与解释
  - 增加可配置路由策略（YAML/DB）与回退规则（低置信度→保守选择）
- 决策与编排
  - 统一 Policy/Planner：定义“选 Agent”“选工具”“并发候选”“重试与降级”的评分函数与阈值
  - 使用 Eino Graph/compose 显式编排“问题生成→检索→评估→下一题规划”，提升可视化与可测试性
- 工具选择
  - 多工具并发与结果聚合，基于信心与代价裁决；将 needResumeTool 从布尔开关升级为策略规则与上下文判定
