## 开发流程指南

### 🚀 完整开发流程

```
1. 认领任务 → 2. 阅读教程 → 3. 本地开发 → 4. 单元测试 → 5. 提交 PR → 6. 代码评审 → 7. 合并主分支
```

### 📝 详细步骤

#### Step 1: 认领任务
- 在任务看板中选择感兴趣的任务
- 每个任务限 1-2 人组队完成
- 确认任务没有被他人认领

#### Step 2: 阅读详细教程
- 每个任务都有配套的详细教程文档
- 教程包含：需求说明、技术原理、实现步骤、验证方法
- 有问题先查文档，再问导师

#### Step 3: 本地开发
```bash
# 1. 拉取最新代码
git checkout main
git pull origin main

# 2. 创建功能分支
git checkout -b feature/TASK-001-semantic-cache

# 3. 开发...
# 按照教程实现功能

# 4. 运行本地测试
make test
```

#### Step 4: 单元测试
- 必须编写单元测试
- 测试覆盖率不低于 70%
- 通过所有现有测试

#### Step 5: 提交 Pull Request
```bash
# 1. 提交代码
git add .
git commit -m "feat: TASK-001 实现语义缓存功能"

# 2. 推送分支
git push origin feature/TASK-001-semantic-cache

# 3. 在 GitHub/GitLab 创建 PR
```

**PR 模板（必填）：**
```markdown
## 任务说明
- 任务 ID：TASK-001
- 功能：语义缓存
- 实现人：张三、李四

## 实现方案
- 使用 Redis 存储缓存
- 余弦相似度阈值 0.95
- TTL：24小时

## 验证结果
- [x] 单元测试通过
- [x] 本地手动测试通过
- [x] 评估指标提升：缓存命中率 40%+

## 相关文档
- 教程文档：./TASK-001-semantic-cache.md
```

#### Step 6: 代码评审
- 至少 1 位导师评审  龙哥 少帅 阳哥
- 评审通过才能合并
- 有修改意见及时修改

#### Step 7: 合并主分支
- 导师点击合并
- 删除功能分支
- 更新本地 main

---

## 💡 导师提示

### 🎯 推荐学习路径（按顺序）

#### RAG 核心优化路径
1. **先看**：Semantic Cache（简单，容易上手）
2. **再学**：RRF 融合（算法简单，效果明显）
3. **进阶**：Cross-Encoder（涉及 ML，有趣）
4. **挑战**：OpenTelemetry（可观测性，生产必备）

#### 多语言 SDK 路径
1. **Python SDK**：最常用，生态好（LangChain、AutoGen）
2. **TypeScript SDK**：前端必备，支持浏览器和 Node.js
3. **Java SDK**：企业级应用首选
4. **SDK 集成示例**：展示如何与主流框架集成

#### RAG 高级优化路径（市场热点）
1. **查询分解与多步检索**：提升复杂查询准确率
2. **自适应 RAG**：根据查询动态选择策略
3. **多模态 RAG**：支持图像/视频检索（2024 热点）

#### 生产化增强路径
1. **限流熔断**：保证系统稳定性
2. **评估体系**：持续优化效果
3. **成本优化**：降低运营成本

#### 企业落地治理路径
1. **文档清洗与切片质量治理**：提升入库数据质量
2. **元数据过滤与分层召回**：提升精确召回能力
3. **权限感知检索**：保证企业数据安全
4. **索引生命周期运维**：支持长期稳定运营
