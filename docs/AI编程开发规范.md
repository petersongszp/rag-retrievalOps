### 提示词：AI相关模块开发规范（强制约束版）

请在「牛面AI面试平台」（前端+后端）所有涉及AI生成的模块开发中，**严格遵守以下强制规范**，确保代码模块化复用、最小化冗余，任何代码交付必须通过规范校验方可交付：


#### 一、核心原则（必须优先遵守）
1. **复用优先，杜绝重复**  
   - 所有AI相关逻辑（如模型调用、文本生成、流式响应、结果解析、评分算法等），必须抽象为独立可复用模块，禁止在业务代码中重复编写相同逻辑。  
   - 检查标准：相同功能的代码片段不得出现2次及以上，若发现重复，必须立即合并为公共模块。

2. **单一职责，最小粒度**  
   - 每个AI模块仅负责一项核心功能（如“AI题生成”“流式响应处理”“简历内容提取”需拆分为独立模块），禁止一个模块包含多场景逻辑。  
   - 代码量控制：核心复用模块的代码行数需≤300行（工具类模块≤100行），超出需拆分。

3. **接口标准化，低耦合**  
   - AI模块对外提供统一格式的调用接口（函数/API），输入参数（如`prompt`、`modelType`、`timeout`）和输出结构（如`{ success: boolean, data: any, error: string }`）必须标准化。  
   - 模块内部逻辑不得依赖业务场景细节（如UI状态、特定页面参数），仅通过接口参数接收外部输入。


#### 二、前端AI模块开发规范（强制执行）
1. **模块目录强制结构**  
   ```
   src/
   ├── ai/                  # 所有AI复用模块的根目录（必须存在）
   │   ├── core/            # 核心逻辑模块（模型调用、流式处理等）
   │   │   ├── generate.ts  # AI生成通用函数（如统一处理prompt、调用API）
   │   │   └── stream.ts    # 流式响应处理工具（解析SSE、打字机效果等）
   │   ├── hooks/           # 可复用Hook（供组件调用）
   │   │   ├── useAIGenerate.ts  # 封装生成逻辑的Hook
   │   │   └── useAIStream.ts    # 封装流式响应的Hook
   │   └── components/      # 可复用UI组件
   │       ├── AIResponse.tsx   # 通用AI响应展示组件
   │       └── AILoader.tsx     # 通用AI加载状态组件
   ```

2. **代码复用强制要求**  
   - 所有页面/组件中涉及AI生成的功能（如面试题展示、简历分析结果），必须调用`ai/core/`或`ai/hooks/`中的模块，禁止在组件内直接写`fetch`/`axios`调用AI接口。  
   - UI层必须使用`ai/components/`中的通用组件，禁止每个页面单独开发“AI响应展示”“加载动画”等重复UI。  
   - 示例：面试页面需展示AI生成的问题，必须调用`useAIGenerate` Hook + `AIResponse`组件，不允许单独编写逻辑。

3. **状态管理约束**  
   - AI相关的全局状态（如生成状态`loading`、历史记录`history`）必须集中在`store/aiStore.ts`中管理，禁止在多个组件中分散定义相同状态。  


#### 三、后端AI模块开发规范（强制执行）
1. **模块目录强制结构**  
   ```
   backend/
   ├── ai/                  # 所有AI复用模块的根目录（必须存在）
   │   ├── services/        # 核心服务（模型调用、业务逻辑）
   │   │   ├── base_service.py  # 基类（封装通用模型调用、重试逻辑）
   │   │   ├── interview_service.py  # 面试相关AI服务（继承基类）
   │   │   └── resume_service.py     # 简历相关AI服务（继承基类）
   │   ├── utils/           # 工具函数（参数校验、结果格式化等）
   │   └── config.py        # 全局配置（模型参数、超时设置等）
   ```

2. **代码复用强制要求**  
   - 所有AI模型调用（如调用OpenAI、内部模型）必须通过`ai/services/base_service.py`基类实现，子类仅补充场景化`prompt`或参数，禁止重复编写认证、请求、重试逻辑。  
   - 通用配置（如模型名称、温度参数`temperature`、超时时间）必须定义在`ai/config.py`中，禁止在接口中硬编码。  
   - 示例：生成面试题和生成简历建议，必须复用`base_service`的`generate`方法，仅传递不同`prompt`，不允许单独写请求逻辑。

3. **接口输出约束**  
   - 所有AI服务的返回格式必须统一（如`{ "code": 0, "data": {}, "msg": "" }`），由基类统一处理异常和格式化，子类不得自定义返回结构。  


#### 四、交付验收强制标准（不满足则需重构）
1. **复用率校验**：核心AI模块（如前端`ai/core/generate.ts`、后端`base_service.py`）必须被至少2个及以上业务场景引用（如面试、简历模块），否则视为设计冗余。  
2. **无重复代码**：通过全局搜索确认，不存在相同的AI逻辑代码片段（如相同的流式解析、模型调用参数处理）。  
3. **文档完整性**：每个复用模块必须包含注释文档，说明：  
   - 功能描述  
   - 输入/输出参数（类型、必填项）  
   - 复用场景（哪些模块在调用）  
   - 扩展方式（如何新增场景而不修改模块本身）  


#### 五、违规处理
若提交的代码违反以上任何一条规范，必须立即停止开发，优先重构代码至符合规范后，方可继续开发新功能。请在每次交付代码时，附带一份「规范自检报告」，说明本次开发如何遵守上述规范。

请严格执行本规范，确保AI相关模块的可维护性和扩展性。
