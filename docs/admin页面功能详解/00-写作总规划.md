# Admin 前端使用说明写作总规划

> 目标：按 Admin 左侧菜单顺序，为“面试吧”RAG Admin 管理台编写一套给小白看的中文使用说明。每份文档都解释：页面用途、适合谁看、页面区域、可操作按钮、可展开/弹窗内容、参数含义、常见操作流程、注意事项。

## 一、写作原则

1. **面向小白**：先说“这个页面解决什么问题”，再解释每个字段；少用术语，必须用术语时给一句话解释。
2. **按左侧菜单顺序**：文档编号与 Admin 左侧导航一致，方便新人边点边看。
3. **参数逐项解释**：表格列、筛选框、表单项、弹窗项、可展开详情都要说明。
4. **避免只翻译字段名**：每个字段要说明“看它有什么用 / 数值高低代表什么 / 填错会怎样”。
5. **以源码为准**：页面内容以 `admin/src/components/admin/*.tsx`、`admin/src/types/kb.ts`、`admin/src/config/api.ts` 为依据。
6. **文档命名规范**：统一放到 `docs/admin前端使用说明/`，文件名使用中文并带编号，例如 `01-概览使用说明.md`。

## 三、每篇详细文档统一结构

每个模块文档建议按以下结构写：

1. **页面一句话说明**：这个页面是干嘛的。
2. **适合谁使用**：运营、研发、内容管理员、测试同学等。
3. **进入路径**：左侧菜单怎么点、路由是什么。
4. **页面区域说明**：顶部卡片、筛选区、列表、详情区、图表区等。
5. **字段/参数解释**：逐项说明表格列、统计指标、表单参数。
6. **按钮/操作说明**：刷新、创建、查看详情、导出、重试、回滚等。
7. **展开项/弹窗/详情页说明**：只要页面里有展开、弹窗、详情页，都要单独解释。
8. **常见使用流程**：用 3-5 个步骤教新人完成典型任务。
9. **注意事项**：风险操作、数据缺失、只读页面、权限/后端接口依赖等。
10. **术语速查**：把页面内英文/技术词翻译成人话。

## 五、审核标准

最终审核时逐篇检查：

- 是否覆盖对应组件中的主要区域、表格列、筛选参数、弹窗参数。
- 是否说明了可展开详情/详情页/跳转页面。
- 是否和左侧菜单顺序、路由、源码一致。
- 是否语言足够简单，不只是字段翻译。
- 是否文件都在 `docs/admin前端使用说明/` 且中文命名。
- 是否存在明显臆测；对源码未明确实现的地方要写“页面当前展示/接口返回后展示”，不要编造。
