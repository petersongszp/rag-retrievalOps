# 05-评测使用说明

本文说明 Admin 前端里的「评测」相关页面，适合第一次使用的人阅读。

评测模块主要分 3 个页面：

1. **评测集页面**：准备评测数据，也就是一批要测试的问题和标准答案线索。
2. **评测运行页面**：选择评测集，配置 baseline / candidate 策略，然后启动一次离线评测。
3. **评测报告详情页**：查看 baseline 和 candidate 的对比结果、门禁结果、失败样本明细。

> 说明：本文只根据前端源码整理。策略是否真的合法、评测如何计算、门禁如何判断，最终由后端接口负责。

---

## 一、评测集页面

页面入口对应前端组件：`evaluation-datasets-page.tsx`。

这个页面用于管理评测集和评测样本。评测集可以理解为一个「测试题库」，里面每条样本是一道要拿来检索测试的问题。

### 1. 页面顶部操作

页面顶部有两个按钮：

- **刷新**：重新加载评测集列表。
- **新建评测集**：打开新建评测集弹窗。

页面说明文字是：管理离线评测数据集、样本导入导出与校验状态，为后续评测运行准备可回归的资产。

### 2. 评测集筛选区

筛选区可以按下面条件查询评测集：

| 字段 | 说明 |
| --- | --- |
| 知识库 | 选择某个知识库，只看绑定这个知识库的评测集。默认会跟随当前选中的知识库。 |
| 状态 | 可选 `draft`、`ready`、`invalid`、`archived`。 |
| 关键词 | 按评测集名称或描述搜索。 |

按钮说明：

- **查询评测集**：按当前条件查询。
- **重置**：清空筛选条件，并恢复到当前选中知识库。

### 3. 评测集状态含义

前端展示的评测集状态有 4 种：

| 状态 | 前端颜色 | 含义说明 |
| --- | --- | --- |
| `draft` | 黄色 | 草稿状态，通常还没有准备好运行。 |
| `ready` | 绿色 | 已准备好，可以创建评测运行。 |
| `invalid` | 红色 | 校验不通过，需要处理样本问题。 |
| `archived` | 默认灰色 | 已归档。 |

> 注意：只有状态是 `ready` 的评测集，「创建运行」按钮才可用。

### 4. 评测集列表字段

评测集列表每页 10 条，表格列如下：

| 列名 | 说明 |
| --- | --- |
| 评测集 | 显示评测集名称和描述。点击名称可以选中该评测集，并在下方查看样本。没有描述时显示「暂无描述」。 |
| 知识库 | 显示绑定的知识库名称和 ID；如果没有绑定，则显示「未绑定」。 |
| 样本数 | 这个评测集中有多少条样本。 |
| 状态 | 显示 `draft` / `ready` / `invalid` / `archived`。 |
| 更新时间 | 显示最后更新时间，格式为 `YYYY-MM-DD HH:mm:ss`。 |
| 操作 | 包含查看样本、校验、导出、创建运行。 |

操作按钮说明：

| 按钮 | 说明 |
| --- | --- |
| 查看样本 | 选中当前评测集，在下方打开样本管理区域。 |
| 校验 | 调用校验接口，检查评测集样本是否有效。 |
| 导出 | 导出当前评测集样本 JSON。 |
| 创建运行 | 跳转到评测运行页面，并带上当前 `dataset_id`。只有 `ready` 状态可点击。 |

点击表格整行，也会选中当前评测集。

### 5. 新建评测集弹窗

点击「新建评测集」后打开弹窗。

可填写字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | 评测集名称。占位示例：`phase2-core-regression`。 |
| 描述 | 选填 | 评测集用途、范围或维护说明。 |
| 绑定知识库 | 选填 | 可以选择一个知识库。前端提示：绑定后校验会检查样本 `kb_ids`。 |

提交后会调用创建评测集接口。成功后：

1. 关闭弹窗。
2. 清空表单。
3. 刷新评测集列表。
4. 自动选中新创建的评测集。

### 6. 编辑评测集说明

当前源码里只看到「新建评测集」，没有看到「编辑评测集」按钮、编辑弹窗或更新接口调用。

所以从当前 Admin 前端看：

- 可以创建评测集。
- 可以查看、校验、导出、创建运行。
- **没有提供编辑评测集名称、描述、绑定知识库的前端入口。**

## 二、样本管理区域

选中一个评测集后，页面下方会显示「样本管理 · 评测集名称」。

### 1. 样本管理顶部操作

如果已经选中评测集，右上角会显示这些按钮：

| 按钮 | 说明 |
| --- | --- |
| 新增样本 | 手动添加一条评测样本。 |
| 导入 JSON | 上传 JSON 文件批量导入样本。 |
| 校验评测集 | 校验当前评测集。 |
| 导出 JSON | 导出当前评测集样本。 |
| 创建运行 | 跳转到评测运行页面。只有当前评测集状态是 `ready` 时可点击。 |

### 2. 评测集基本信息

样本管理区域会先展示当前评测集信息：

| 字段 | 说明 |
| --- | --- |
| 评测集名称 | 当前选中的评测集名称。 |
| 状态 | 当前评测集状态。 |
| 知识库 | 绑定的知识库名称；未绑定时显示「未绑定」。 |
| 样本数 | 当前评测集样本数量。 |
| 描述 | 当前评测集描述；没有时显示「暂无描述」。 |

### 3. 最近一次校验结果

如果刚刚对当前评测集执行过校验，会显示一个提示框：

| 字段 | 说明 |
| --- | --- |
| 最近一次校验结果 | 显示校验后的评测集状态，例如 `ready`。 |
| 总样本 | `case_count`。 |
| 有效 | `valid_count`。 |
| 无效 | `invalid_count`。 |
| 未检查 | `unchecked_count`。 |

如果校验结果状态是 `ready`，提示框是成功样式；否则是警告样式。

### 4. 样本筛选区

样本列表可以按下面条件筛选：

| 字段 | 说明 |
| --- | --- |
| Query Type | 按查询类型筛选，例如 `factual`、`multi-hop`。 |
| Tag | 按单个标签筛选。 |
| 校验状态 | 可选 `unchecked`、`valid`、`invalid`。 |
| 关键词 | 匹配 `case_key`、`query`、`notes`。 |

按钮说明：

- **查询样本**：按当前条件查询。
- **重置**：清空样本筛选条件，重新加载第一页。

### 5. 样本列表字段

样本列表每页 20 条，表格列如下：

| 列名 | 说明 |
| --- | --- |
| Case Key | 样本唯一标识，例如 `faq-login-001`。 |
| Query | 要测试的查询问题。表格里会省略过长内容。 |
| Query Type | 查询类型，没有则显示 `-`。 |
| Tags | 标签列表，没有则显示 `-`。 |
| Top K | 检索时取前多少条结果。 |
| Relevant IDs | 标准相关结果 ID 的数量。 |
| Citation Targets | 标准引用目标数量。 |
| 校验状态 | `unchecked`、`valid`、`invalid`。 |
| 更新时间 | 样本更新时间。 |

样本校验状态颜色：

| 状态 | 前端颜色 | 说明 |
| --- | --- | --- |
| `valid` | 绿色 | 样本有效。 |
| `invalid` | 红色 | 样本有问题。 |
| `unchecked` | 黄色 | 还没有检查。 |

### 6. 样本可展开详情

某些样本行左侧可以展开。只要满足下面任一条件，就可以展开：

- 有校验错误 `validation_errors`。
- 有 `relevant_ids`。
- 有 `citation_targets`。
- 有 `notes`。
- 有 `kb_ids`。

展开后会看到：

| 区域 / 字段 | 说明 |
| --- | --- |
| 校验错误 | 如果有错误，会用红色提示框逐条列出。 |
| Relevant IDs | 展示标准相关结果 ID；多个 ID 以换行展示。 |
| Citation Targets | 以 JSON 格式展示标准引用目标。 |
| KB IDs | 展示样本指定的知识库 ID 列表。 |
| Collection | 展示样本指定的 collection 名称。 |
| Notes | 展示备注说明。 |

### 7. 新增样本弹窗

点击「新增样本」后打开弹窗。

字段说明：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| Case Key | 必填 | 样本唯一标识。占位示例：`faq-login-001`。 |
| Top K | 必填 | 检索取前多少条。默认值是 `5`，最小值是 `1`，只能填整数。 |
| Query | 必填 | 用于检索回归的查询问题。 |
| Query Type | 选填 | 查询类型，例如 `factual`、`multi-hop`。 |
| Collection | 选填 | collection 名称。 |
| Tags | 选填 | 标签，支持逗号或换行分隔，例如 `core, faq`。 |
| KB IDs | 选填 | 知识库 ID，支持逗号或换行分隔，例如 `1,2`。必须是大于 0 的整数。 |
| Relevant IDs | 选填 | 标准相关结果 ID，支持一行一个，也支持逗号分隔。 |
| Citation Targets JSON | 选填 | 标准引用目标，必须是 JSON 数组。 |
| Notes | 选填 | 补充样本背景、预期或人工标注说明。 |

`Citation Targets JSON` 的前端示例：

```json
[
  {
    "document_id": 1,
    "chunk_id": "chunk-1",
    "file_name": "faq.md"
  }
]
```

前端会做这些基础检查：

- `Tags`、`Relevant IDs`：按逗号或换行拆成字符串数组。
- `KB IDs`：按逗号或换行拆分，并要求每个值都是大于 0 的整数。
- `Citation Targets JSON`：必须能解析成 JSON 数组。
- `Citation Targets JSON` 每个对象允许字段：
  - `document_id`：数字，且不能小于 0。
  - `chunk_id`：字符串。
  - `file_name`：字符串。

提交成功后会刷新评测集列表和样本列表。

### 8. 导入 JSON 弹窗

点击「导入 JSON」后打开弹窗。

弹窗说明：

- 只能选择 1 个 JSON 文件。
- 接受 `.json` 或 `application/json`。
- 前端提示：上传与 `backend/scripts/evaluation/dataset.json` 兼容的 JSON 数组。
- `case_key` 将取自每条记录的 `id` 字段。

导入完成后会显示结果：

| 字段 | 说明 |
| --- | --- |
| 成功 | 成功导入条数 `imported`。 |
| 失败 | 失败条数 `failed`。 |
| 错误列表 | 如果有错误，会显示第几条、case_key 和错误信息。 |

导入后会刷新评测集列表和样本列表。

## 三、评测运行页面

页面入口对应前端组件：`evaluation-runs-page.tsx`。

这个页面用于启动评测任务、查看运行状态，并在成功后进入报告页。

### 1. 页面顶部操作

顶部有两个按钮：

| 按钮 | 说明 |
| --- | --- |
| 刷新 | 重新加载运行列表。 |
| 新建运行 | 打开新建评测运行弹窗。 |

页面说明文字是：触发离线评测任务、轮询运行状态、查看错误信息，并在成功后进入完整报告页面。

### 2. 运行筛选区

可以按下面条件筛选运行：

| 字段 | 说明 |
| --- | --- |
| 评测集 | 选择某个评测集，只看这个评测集的运行。下拉选项显示 `评测集名称 (#ID)`。 |
| 状态 | 可选 `pending`、`running`、`succeeded`、`failed`、`canceled`。 |
| 时间范围 | 按开始和结束时间筛选，支持选择具体时间。 |

按钮说明：

- **查询运行**：按条件查询，并把 `dataset_id`、`status` 写到页面 URL 中。
- **重置**：清空筛选条件，并回到 `/evaluation/runs`。

### 3. 运行状态说明

前端支持的运行状态：

| 状态 | 前端颜色 | 说明 |
| --- | --- | --- |
| `pending` | 黄色 | 等待运行。 |
| `running` | 蓝色处理中 | 正在运行，会显示进度条。 |
| `succeeded` | 绿色 | 运行成功，可以查看报告。 |
| `failed` | 红色 | 运行失败，可在详情里看错误信息。 |
| `canceled` | 灰色 | 已取消。 |

如果列表里有 `pending` 或 `running` 的任务，前端会每 4 秒自动刷新一次列表；如果当前打开的详情也是运行中，也会同步刷新详情。

### 4. 运行列表字段

运行列表每页 10 条，表格列如下：

| 列名 | 说明 |
| --- | --- |
| Run ID | 本次评测运行的唯一 ID。 |
| 评测集 | 显示评测集名称和 `dataset_id`。如果找不到名称，则显示 `#ID`。 |
| Baseline | baseline profile 名称。 |
| Candidate | candidate profile 名称。 |
| 状态 | 运行状态。`running` 时额外显示进度条。 |
| 进度 | 格式为 `已完成样本数/总样本数 (百分比)`。 |
| 开始时间 | 运行开始时间。 |
| 结束时间 | 运行结束时间。 |
| 操作 | 成功时可查看报告；任何状态都可查看详情。 |

操作按钮：

| 按钮 | 出现条件 | 说明 |
| --- | --- | --- |
| 查看报告 | 只有 `succeeded` 状态显示 | 进入 `/evaluation/reports/{run_id}` 报告页。 |
| 查看详情 | 所有运行都显示 | 打开右侧运行详情抽屉。 |

点击表格整行，也会打开运行详情。

### 5. 新建评测运行弹窗

点击「新建运行」后打开弹窗。

弹窗顶部有提示：

> profiles 和 gate_thresholds 只做 JSON 语法校验。策略是否合法、门禁是否通过以及任务执行结果由后端负责。

字段说明：

| 字段 | 是否必填 | 默认值 / 示例 | 说明 |
| --- | --- | --- | --- |
| 评测集 | 必填 | 当前筛选的评测集，或列表第一个评测集 | 选择一个评测集。下拉里会显示 `评测集名称 (#ID) - 状态`。占位提示是「选择一个 ready 评测集」。 |
| Baseline Profile | 必填 | `dense_only` | baseline 策略名称。 |
| Candidate Profile | 必填 | `hybrid` | candidate 策略名称。 |
| Profiles JSON | 必填 | 自动生成默认 JSON | 策略配置数组。必须是非空 JSON 数组。 |
| Gate Thresholds JSON | 选填 | 默认带两个门禁字段 | 门禁阈值配置。填写时必须是 JSON 对象。 |

提交时，前端会发送：

```json
{
  "dataset_id": 评测集ID,
  "baseline_profile": "baseline名称",
  "candidate_profile": "candidate名称",
  "profiles": [],
  "gate_thresholds": {}
}
```

其中 `gate_thresholds` 只有填写并解析成功时才会发送。

### 6. Profiles / 策略配置说明

`profiles` 是一个策略数组，每个策略对象的类型来自 `EvalStrategyProfile`。

前端默认生成两个策略：

```json
[
  {
    "name": "dense_only",
    "label": "dense_only",
    "baseline": true,
    "mode": "dense"
  },
  {
    "name": "hybrid",
    "label": "hybrid",
    "candidate": true,
    "mode": "hybrid"
  }
]
```

策略对象支持的字段包括：

| 字段 | 说明 |
| --- | --- |
| `name` | 策略名称。 |
| `label` | 展示名称，可选。 |
| `baseline` | 是否标记为 baseline。 |
| `candidate` | 是否标记为 candidate。 |
| `mode` | 策略模式，例如 `dense`、`hybrid`。 |
| `enable_query_rewrite` | 是否启用查询改写。 |
| `enable_dynamic_topk` | 是否启用动态 topK。 |
| `enable_advanced_rerank` | 是否启用高级 rerank。 |
| `candidate_top_k` | candidate 使用的 topK。 |
| `dense_weight` | dense 权重。 |
| `sparse_weight` | sparse 权重。 |
| `min_top_k` | 最小 topK。 |
| `max_top_k` | 最大 topK。 |
| `token_budget` | token 预算。 |
| `rewrite_max_expansions` | 查询改写最大扩展数。 |
| `rerank_timeout_ms` | rerank 超时时间，单位毫秒。 |
| `rerank_model` | rerank 模型名称。 |

前端只检查：

- JSON 能不能解析。
- 解析结果必须是非空数组。

不检查具体字段是否合法，具体策略是否合法由后端判断。

### 7. Gate Thresholds / 门禁阈值说明

`gate_thresholds` 是评测通过与否的门槛配置，对应类型 `EvalGateThresholds`。

支持字段：

| 字段 | 说明 |
| --- | --- |
| `min_recall_delta` | Recall@K 提升值的最低要求。 |
| `min_mrr_delta` | MRR 提升值的最低要求。 |
| `min_ndcg_delta` | nDCG 提升值的最低要求。 |
| `min_citation_accuracy_delta` | Citation Accuracy 提升值的最低要求。 |
| `max_p95_latency_regression_ms` | P95 延迟最多允许增加多少毫秒。 |
| `max_p95_latency_regression_ratio` | P95 延迟最多允许增加的比例。 |

前端默认值：

```json
{
  "min_recall_delta": 0,
  "max_p95_latency_regression_ratio": 0.2
}
```

前端只检查：

- 如果填写了，必须能解析成 JSON。
- 解析结果必须是 JSON 对象，不能是数组。

实际门禁是否通过由后端报告里的 `gate` 结果决定。

### 8. 运行详情抽屉

点击运行行或「查看详情」后，右侧打开抽屉。

详情字段：

| 字段 | 说明 |
| --- | --- |
| Run ID | 当前运行 ID。 |
| 评测集 | 评测集名称；找不到名称时显示 `#dataset_id`。 |
| Baseline | baseline profile。 |
| Candidate | candidate profile。 |
| 状态 | 当前运行状态。 |
| 进度 | 已完成数、总数、百分比和进度条。失败显示异常进度样式，成功显示成功样式。 |
| 开始时间 | `started_at`。 |
| 结束时间 | `finished_at`。 |
| 创建时间 | `created_at`。 |
| 错误信息 | `error_msg`，没有则显示 `-`。 |
| 报告路径 | `report_path`；如果没有返回则显示 `Contract gap`。 |

详情抽屉还有两个卡片：

#### Gate Thresholds

- 如果后端返回了 `gate_thresholds`，用 JSON 格式展示。
- 如果没有配置，显示「未配置 gate thresholds」。

#### Profiles

- 如果后端返回了 `profiles`，用 JSON 格式展示。
- 如果后端没返回，显示警告：`Contract gap`，说明「后端未返回 profiles，前端无法展示完整策略配置。」

如果运行状态是 `succeeded`，底部会出现「进入报告页」按钮。

## 四、评测报告详情页

页面入口对应前端组件：`evaluation-report-page.tsx`。

报告页用于展示 baseline 与 candidate 的离线评测对比、门禁结果、贡献分析以及失败样本下钻。

### 1. 页面顶部操作

顶部按钮：

| 按钮 | 说明 |
| --- | --- |
| 返回运行列表 | 返回 `/evaluation/runs`。 |
| 刷新 | 重新加载运行信息和报告信息。 |
| 导出 JSON | 导出当前报告 JSON。 |
| 导出 Markdown | 导出当前报告 Markdown。 |

导出会打开后端导出地址，并提示「已发起 JSON 导出」或「已发起 MARKDOWN 导出」。

### 2. 报告基础信息

报告加载后，会显示基础信息：

| 字段 | 说明 |
| --- | --- |
| Run ID | 当前运行 ID。 |
| Gate | 总体门禁结果，`passed` 或 `failed`。 |
| Dataset Size | 评测集样本数量。 |
| Generated At | 报告生成时间。 |
| Baseline | baseline 策略名称。 |
| Candidate | candidate 策略名称。 |
| Run Status | 运行状态。如果没有运行信息，则显示 `Contract gap`。 |
| Error | 运行错误信息；没有则显示 `-`。 |

如果当前运行还没有可用报告，页面会显示「当前运行还没有可用报告」。

### 3. 指标卡片

报告顶部会展示 8 个统计卡片：

| 指标 | 说明 |
| --- | --- |
| Recall@K Delta | candidate 相比 baseline 的 Recall@K 变化。 |
| MRR Delta | candidate 相比 baseline 的 MRR 变化。 |
| nDCG Delta | candidate 相比 baseline 的 nDCG 变化。 |
| Citation Delta | candidate 相比 baseline 的引用准确率变化。 |
| Baseline P50 | baseline 的 P50 延迟，单位 ms。 |
| Candidate P50 | candidate 的 P50 延迟，单位 ms。 |
| Baseline P95 | baseline 的 P95 延迟，单位 ms。 |
| Candidate P95 | candidate 的 P95 延迟，单位 ms。 |

### 4. 指标对比表

「指标对比」表展示 baseline 与 candidate 的详细对比。

表格列：

| 列名 | 说明 |
| --- | --- |
| 指标 | 指标名称。 |
| Baseline | baseline 的指标值。 |
| Candidate | candidate 的指标值。 |
| Delta | candidate - baseline 的变化值。 |
| Delta Ratio | 变化比例；没有则显示 `-`。 |

表格行：

| 指标 | 说明 |
| --- | --- |
| Recall@K | 召回率。 |
| MRR | Mean Reciprocal Rank。 |
| nDCG | 排序质量指标。 |
| Citation Accuracy | 引用准确率。 |
| P50 Latency | P50 延迟，单位 ms。 |
| P95 Latency | P95 延迟，单位 ms。 |
| Avg Latency | 平均延迟，单位 ms。 |

颜色规则：

- 普通质量指标：Delta 大于 0 显示为好，小于 0 显示为差。
- 延迟指标：越低越好，所以 Delta 大于 0 表示延迟增加，会显示为差；Delta 小于 0 表示延迟降低，会显示为好。

### 5. 贡献分析

「贡献分析」表展示不同策略相对另一个策略的变化。

如果报告没有贡献分析数据，会显示「当前报告没有贡献分析数据」。

表格列：

| 列名 | 说明 |
| --- | --- |
| Strategy | 当前策略名称。 |
| Compared To | 对比对象。 |
| Recall Delta | Recall 变化。 |
| MRR Delta | MRR 变化。 |
| nDCG Delta | nDCG 变化。 |
| Citation Delta | 引用准确率变化。 |
| P95 Latency Delta | P95 延迟变化，单位 ms。延迟增加为差，降低为好。 |

### 6. Gate 检查

「Gate 检查」卡片右上角显示总体结果：`passed` 或 `failed`。

表格列：

| 列名 | 说明 |
| --- | --- |
| Name | 检查项名称。 |
| Actual | 实际值。 |
| Expected | 期望值 / 阈值。 |
| Passed | 单项是否通过，显示 `passed` 或 `failed`。 |
| Message | 后端返回的说明信息。 |

Gate 结果来自报告的 `report.gate`：

- `report.gate.passed`：总体是否通过。
- `report.gate.thresholds`：使用的门禁阈值。
- `report.gate.checks`：每一条检查项。

### 7. 失败样本查询区

「失败样本」区域可以查询表现不好的样本。

筛选字段：

| 字段 | 说明 |
| --- | --- |
| Failure Reason | 失败原因。 |
| Query Type | 查询类型，例如 `factual`、`multi-hop`。 |
| Tag | 单个标签。 |

支持的失败原因：

| 原因 | 说明 |
| --- | --- |
| `recall_miss` | 召回未命中。 |
| `citation_miss` | 引用未命中。 |
| `mrr_drop` | MRR 下降。 |
| `ndcg_drop` | nDCG 下降。 |
| `latency_regression` | 延迟变差。 |
| `gate_failed` | 门禁失败。 |
| `trace_missing` | 缺少 trace。 |

按钮：

- **查询失败样本**：按当前条件查询。
- **重置**：清空筛选条件，重新查询第一页。

### 8. 失败样本表格

失败样本每页 10 条，表格列：

| 列名 | 说明 |
| --- | --- |
| Case ID | 样本 ID。 |
| Query | 查询问题，过长会省略。 |
| Reason | 失败原因。 |
| Recall Delta | 当前样本 Recall 变化。 |
| MRR Delta | 当前样本 MRR 变化。 |
| nDCG Delta | 当前样本 nDCG 变化。 |
| Citation Delta | 当前样本引用准确率变化。 |
| Latency Delta | 当前样本延迟变化，单位 ms。延迟增加为差，降低为好。 |
| Trace | 查看 baseline / candidate 的 Debug 或 Trace 链接。 |

失败原因颜色：

| 原因 | 前端颜色 |
| --- | --- |
| `gate_failed` | 红色 |
| `latency_regression` | 火山色 |
| `trace_missing` | 黄色 |
| 其他原因 | 警告色 |

### 9. Trace / Debug 链接

失败样本的 Trace 列会分别展示 Baseline 和 Candidate 的查看入口。

前端逻辑如下：

1. 如果有 debug request id，并且 debug 没有被标记为不可用：
   - 显示 `Baseline Debug` 或 `Candidate Debug` 按钮。
   - 跳转到 `/retrieval-lab/debug?request_id=...`。
   - 如果同时有普通 request id，还会显示 `Trace Logs` 链接，跳转到 `/trace-logs/retrieval?request_id=...`。
2. 如果 debug 不可用，但有普通 request id：
   - 显示 `Baseline Trace` 或 `Candidate Trace`。
   - 跳转到 `/trace-logs/retrieval?request_id=...`。
   - 如果是从 debug 降级过来的，会显示 `P3 unavailable`。
3. 如果 request id 也没有：
   - 显示 `Baseline trace unavailable` 或 `Candidate trace unavailable`。

### 10. 失败样本可展开详情

失败样本行在下面条件满足时可以展开：

- 有 `query_type`。
- 有 `tags`。
- 有 `baseline_request_id`。
- 有 `candidate_request_id`。

展开后显示：

| 字段 | 说明 |
| --- | --- |
| Query Type | 查询类型，没有则显示 `-`。 |
| Tags | 标签列表，没有则显示 `-`。 |
| Baseline Metrics | baseline 在该样本上的指标 JSON。 |
| Candidate Metrics | candidate 在该样本上的指标 JSON。 |

`Baseline Metrics` 和 `Candidate Metrics` 包括：

| 字段 | 说明 |
| --- | --- |
| `recall_at_k` | Recall@K。 |
| `mrr` | MRR。 |
| `ndcg` | nDCG。 |
| `citation_accuracy` | 引用准确率。 |
| `latency_ms` | 延迟，单位 ms。 |

## 五、相关接口路径

前端使用的评测相关接口统一来自 `KB_ADMIN_API`。

| 功能 | 接口路径 |
| --- | --- |
| 评测集列表 | `GET /admin/kb/eval/datasets` |
| 创建评测集 | `POST /admin/kb/eval/datasets` |
| 样本列表 | `GET /admin/kb/eval/datasets/{datasetId}/items` |
| 新增样本 | `POST /admin/kb/eval/datasets/{datasetId}/items` |
| 导入样本 | `POST /admin/kb/eval/datasets/{datasetId}/items/import` |
| 导出样本 | `GET /admin/kb/eval/datasets/{datasetId}/items/export` |
| 校验评测集 | `POST /admin/kb/eval/datasets/{datasetId}/validate` |
| 运行列表 | `GET /admin/kb/eval/runs` |
| 创建运行 | `POST /admin/kb/eval/runs` |
| 运行详情 | `GET /admin/kb/eval/runs/{runId}` |
| 评测报告 | `GET /admin/kb/eval/runs/{runId}/report` |
| 失败样本 | `GET /admin/kb/eval/runs/{runId}/cases` |
| 导出报告 | `GET /admin/kb/eval/runs/{runId}/report/export?format=json|markdown` |

接口会拼在 `API_BASE_URL` 后面。`API_BASE_URL` 默认是 `/api`，也可以由环境变量 `NEXT_PUBLIC_API_BASE_URL` 指定。

## 六、推荐使用流程

适合小白按下面顺序操作：

1. 进入「评测集」页面。
2. 新建一个评测集，必要时绑定知识库。
3. 手动新增样本，或导入 JSON 样本。
4. 点击「校验评测集」。
5. 确认评测集状态变成 `ready`。
6. 点击「创建运行」。
7. 在「评测运行」页面确认 baseline、candidate、profiles、gate thresholds。
8. 提交新建运行。
9. 等待状态从 `pending` / `running` 变成 `succeeded`。
10. 点击「查看报告」。
11. 在报告页查看指标对比、贡献分析、Gate 检查和失败样本。
12. 如果需要复盘单条失败样本，点击 Trace / Debug 进入检索调试页面。

## 七、当前前端里需要注意的点

1. **评测集没有编辑入口**：源码里只有新建评测集，没有编辑评测集的弹窗或按钮。
2. **创建运行时不会强制过滤 ready 评测集**：下拉会展示评测集状态，提示选择 ready 评测集；是否允许非 ready 运行由后端决定。
3. **Profiles 只做 JSON 格式检查**：字段是否合法、策略是否可运行由后端判断。
4. **Gate Thresholds 也只做 JSON 对象检查**：具体门禁逻辑由后端报告返回。
5. **运行中会自动轮询**：有 `pending` 或 `running` 状态时，前端每 4 秒刷新一次。
6. **报告路径和 profiles 可能出现 Contract gap**：如果后端没返回对应字段，前端会明确提示。
