# 06-质量监控使用说明

## 页面用途

质量监控页用于快速查看「最近一次成功评测」的质量摘要。

它不会展示所有评测运行，也不会直接分析每条失败样本。源码页面说明里明确写了：更完整的运行管理和失败样本分析，需要继续去 **Evaluation 模块**完成。

页面主要回答这几个问题：

- 最近一次成功评测是哪一次？
- 候选策略相比基线策略，核心质量指标是变好了还是变差了？
- Gate 是否通过？哪些检查项通过或失败？
- 哪些策略贡献了质量变化？

## 适合谁用

- 想快速判断最近一次评测是否健康的运营、产品、研发。
- 想看检索策略是否带来提升的算法/后端同学。
- 想先看摘要，再决定是否进入完整报告排查的人。

## 进入路径

在 Admin 左侧菜单进入：**质量监控**。

对应前端路由是：`/quality-monitor`。

页面会调用：

- `GET /admin/kb/eval/runs`：只查 `status=succeeded` 的评测运行，页码 `page=1`，每页 `page_size=1`。
- `GET /admin/kb/eval/runs/{runId}/report`：读取该运行的报告。

也就是说，页面展示的是接口返回的第一条「成功评测运行」报告。

## 页面区域

### 1. 页面标题区

标题：**质量监控**。

说明文字：展示最近一次成功评测的核心质量摘要。

右侧按钮：**刷新**。

点击刷新后，页面会重新加载最近一次成功评测和对应报告。

### 2. 错误提示区

如果加载失败，会显示红色错误提示。

默认失败文案是：`加载质量监控摘要失败`。

如果接口错误里带了 `message`，页面会优先显示接口返回的 message。

### 3. 空状态区

如果没有成功的评测报告，页面会显示：

> 还没有成功的评测报告可供展示

常见原因：

- 还没有跑过评测。
- 评测还在运行中。
- 最近评测失败了，没有 `succeeded` 状态的运行。

### 4. 最近一次成功报告

这张卡片展示当前摘要来自哪一份报告。

字段包括：

| 字段 | 含义 |
|---|---|
| Run ID | 评测运行 ID，用来定位某一次评测。 |
| Generated At | 报告生成时间。前端会格式化为 `YYYY-MM-DD HH:mm:ss`。 |
| Baseline | 基线策略名称，也就是被对比的旧方案。 |
| Candidate | 候选策略名称，也就是要验证的新方案。 |
| Gate | 门禁结果，`passed` 表示通过，`failed` 表示失败。 |

右侧按钮：**查看完整报告**。

点击后会跳转到：`/evaluation/reports/{run_id}`。

## 质量指标说明

页面中间会展示 8 个指标卡片。

### 1. Recall@K Delta

含义：召回率变化值。

- 大于 0：候选策略比基线更能召回正确内容，绿色显示。
- 小于 0：候选策略召回变差，红色显示。
- 等于 0：无明显变化。

### 2. MRR Delta

含义：MRR 排名质量变化值。

MRR 更关注「正确答案是不是排在前面」。

- 大于 0：排序更好。
- 小于 0：排序变差。

### 3. nDCG Delta

含义：nDCG 排序质量变化值。

nDCG 用来衡量整体排序是否合理。

- 大于 0：整体排序质量提升。
- 小于 0：整体排序质量下降。

### 4. Citation Delta

含义：引用准确率变化值。

它来自 `citation_accuracy_delta`。

- 大于 0：引用准确性提升。
- 小于 0：引用准确性下降。

### 5. P95 Latency Delta

含义：P95 延迟变化，单位是毫秒。

P95 表示 95% 请求的耗时不超过这个值。

注意：延迟和质量指标相反，延迟越低越好。源码里对这个指标用了反向颜色逻辑：

- 延迟 Delta 小于 0：变快，绿色。
- 延迟 Delta 大于 0：变慢，红色。

### 6. P95 Latency Ratio

含义：P95 延迟变化比例。

同样是越低越好，前端也用了反向颜色逻辑：

- 比例下降：更好。
- 比例上升：更差。

### 7. Dataset Size

含义：本次评测使用的数据集样本数量。

它来自报告里的 `dataset_size`。

### 8. Gate Checks

含义：Gate 检查项数量。

它来自 `latestReport.gate.checks.length`。

## Gate 摘要

页面只展示前 4 条 Gate 检查项。

每条检查项包含：

| 字段 | 含义 |
|---|---|
| name | 检查项名称。 |
| passed | 是否通过。通过显示 `passed`，失败显示 `failed`。 |
| actual | 实际值。 |
| expected | 期望值或阈值。 |
| message | 检查说明。 |

如果报告没有 Gate 细项，会显示：

> 当前报告没有 gate 细项

## 贡献摘要

页面只展示前 3 条贡献分析数据。

每条贡献项包含：

| 字段 | 含义 |
|---|---|
| strategy | 当前策略名称。 |
| compared_to | 对比对象。 |
| recall_delta | Recall 变化。 |
| mrr_delta | MRR 变化。 |
| ndcg_delta | nDCG 变化。 |
| citation_accuracy_delta | 引用准确率变化。 |
| p95_latency_delta_ms | P95 延迟变化，单位毫秒。 |

如果没有贡献分析数据，会显示：

> 当前报告没有贡献分析数据

## 趋势、异常、失败原因怎么看

### 趋势

本页面没有折线图，也没有按时间连续展示趋势。

它展示的是「最近一次成功评测」中候选策略相对基线策略的 Delta，也就是一次对比结果。可以把这些 Delta 当作本次变化趋势：

- Recall/MRR/nDCG/Citation 的 Delta 为正：质量指标变好。
- Recall/MRR/nDCG/Citation 的 Delta 为负：质量指标变差。
- P95 Latency Delta 为正：延迟变慢。
- P95 Latency Delta 为负：延迟变快。

### 异常

页面会通过以下方式提示异常：

- Gate 显示 `failed`：说明报告没有通过门禁。
- 某个 Gate 检查项显示 `failed`：说明该检查项不达标。
- 质量指标为负且显示红色：说明候选策略在该项上退化。
- P95 延迟为正且显示红色：说明候选策略变慢。
- 加载失败红色 Alert：说明接口请求失败。

### 失败原因

质量监控页本身不展示逐条失败样本，也不直接展示 `failure_reason` 列表。

源码里的失败原因类型包括：

| 失败原因 | 简单含义 |
|---|---|
| recall_miss | 没召回到应该召回的内容。 |
| citation_miss | 引用没有命中预期内容。 |
| mrr_drop | MRR 排名指标下降。 |
| ndcg_drop | nDCG 排序指标下降。 |
| latency_regression | 延迟退化，变慢了。 |
| gate_failed | Gate 门禁失败。 |
| trace_missing | 缺少调试链路或追踪信息。 |

如果要看具体失败样本，需要点击 **查看完整报告**，或进入 Evaluation 模块继续排查。

## 按钮/操作

### 刷新

重新请求最近一次成功评测和报告。

### 查看完整报告

跳转到完整评测报告页面：`/evaluation/reports/{run_id}`。

## 可展开/弹窗/详情页

质量监控页源码里没有展开区域，也没有弹窗。

唯一详情入口是：**查看完整报告**。

## 常见流程

### 流程 1：快速判断最近评测是否通过

1. 打开 **质量监控**。
2. 看「最近一次成功报告」里的 Gate。
3. 如果 Gate 是 `passed`，说明门禁通过。
4. 如果 Gate 是 `failed`，继续看 Gate 摘要里的 failed 项。
5. 需要细查时，点击 **查看完整报告**。

### 流程 2：判断新策略是否值得继续推进

1. 看 Recall@K Delta、MRR Delta、nDCG Delta、Citation Delta。
2. 正数越多，说明质量越可能提升。
3. 再看 P95 Latency Delta。
4. 如果质量提升但延迟明显变慢，需要谨慎推进。
5. 最后看 Gate 是否通过。

### 流程 3：没有报告时怎么办

1. 页面显示「还没有成功的评测报告可供展示」。
2. 去 Evaluation 模块检查是否有评测运行。
3. 如果没有，先创建并运行评测。
4. 如果评测失败，先修复失败原因。
5. 等有 `succeeded` 评测后，再回到质量监控页刷新。

## 注意事项

- 页面只取最近一条 `status=succeeded` 的评测运行。
- 页面不是完整报告页，只展示摘要。
- Gate 摘要最多展示前 4 条检查项。
- 贡献摘要最多展示前 3 条贡献数据。
- 延迟指标越低越好，颜色判断和质量指标相反。
- 如果时间无法被 dayjs 正常解析，页面会直接显示原始时间字符串。

## 术语速查

| 术语 | 解释 |
|---|---|
| Baseline | 基线策略，通常是当前稳定方案。 |
| Candidate | 候选策略，通常是准备验证的新方案。 |
| Delta | 变化值，候选策略减去基线策略。 |
| Recall@K | 前 K 个结果里召回正确内容的能力。 |
| MRR | 正确结果排得越靠前，分数越高。 |
| nDCG | 衡量整体排序质量的指标。 |
| Citation Accuracy | 引用准确率。 |
| P95 Latency | 95% 请求的耗时上限，越低越好。 |
| Gate | 质量门禁，用规则判断能不能通过。 |
| Gate Check | Gate 里的具体检查项。 |
| Dataset Size | 本次评测样本数量。 |
| failure_reason | 失败原因，用于说明某条样本为什么失败。 |
