# 项目简历上传功能教学

## 1. 功能概述
本项目实现了“简历上传 + 智能解析”的端到端能力。用户上传 PDF 简历后，系统会自动保存文件，并调用基于 Eino 编排的 Agent 进行解析，提取关键信息（技能、项目经验等）并存入数据库，为后续的模拟面试提供上下文。

## 2. 核心流程
1. **上传请求**：客户端发送 `POST /api/resume/upload`，携带 PDF 文件。
2. **前置校验**：检查用户是否已配置默认模型（Agent 运行依赖）。
3. **文件处理**：校验文件类型（PDF）与大小（10MB），保存至本地 `uploads/resumes` 目录。
4. **智能解析**：
   - 启动 `ResumeParserAgent`。
   - Agent 调用 `pdf_to_text` 工具读取文件内容。
   - Agent 调用 LLM 提取结构化信息（JSON）。
5. **持久化**：将原始文件名、解析后的 JSON 内容、文件元数据存入 MySQL `resumes` 表。

## 3. 代码实现详解

### 3.1 IDL 定义 (接口契约)
在 `backend/idl/interviews/interviews.thrift` 中定义了上传接口。
- **路径**：`backend/idl/interviews/interviews.thrift`
```thrift
// 上传简历
UploadResumeResponse UploadResume(1: UploadResumeRequest request) (
    api.post="/api/resume/upload",
    api.category="resumes",
    api.gen_path="interviews"
)
```
> **注意**：修改 IDL 后需运行 `hz update -idl idl/api.thrift` 更新生成代码。

### 3.2 Handler 层 (入口与校验)
负责处理 HTTP 请求、文件接收与基础校验。
- **路径**：`backend/api/handler/interview/interviews_service.go`

**关键逻辑**：
1. **用户身份获取**：`middleware.GetUserID(c)`。
2. **文件保存**：`handleResumeUpload` 函数实现了文件大小（10MB）、类型（.pdf）检查，并使用 `os.MkdirAll` 确保目录存在。
3. **调用解析服务**：保存成功后，立即调用 `service.ParseResumeAndSave` 进行异步或同步解析。

```go
// handleResumeUpload 片段
if filepath.Ext(fileHeader.Filename) != ".pdf" {
    return "", fmt.Errorf("只支持 PDF 格式的简历文件")
}
projectRoot := filepath.Join(os.Getenv("PWD"), "uploads", "resumes")
```

### 3.3 Agent 服务层 (编排与解析)
这是本功能的核心，连接了业务逻辑与 AI 能力。
- **路径**：`backend/chatApp/agent/service/resume_service.go`

**核心函数 `ParseResumeAndSave`**：
1. **超时控制**：`context.WithTimeout(ctx, 120*time.Second)`，防止大文件解析卡死。
2. **Agent 构建**：调用 `resume.NewResumeParserAgent(userId)` 创建针对该用户的 Agent 实例。
3. **Prompt 设计**：构造包含文件路径的 Prompt，指令明确要求“先调用 pdf_to_text，再提取 JSON”。
4. **执行 Runner**：使用 `adk.NewRunner` 运行 Agent。

```go
// 构建 Query
query := fmt.Sprintf(`【重要】请立即解析以下简历文件...
简历文件路径：%s
【必须执行的步骤】：
1. 使用 pdf_to_text 工具解析...
2. 提取关键信息...`, resumeFilePath)
```

### 3.4 持久化层 (数据入库)
解析结果以 JSON 字符串形式存储，保留原始文件引用。
- **Model 定义**：`backend/internal/model/resume.go`
- **DAO 操作**：`backend/internal/service/interviews/impl/resume_manager_impl.go`

```go
resumeRecord := &model.Resume{
    UserID:    userId,
    Content:   string(contentJSON), // 解析后的结构化数据
    FileName:  fileName,            // 原始文件名
    FileType:  "pdf",
    IsDefault: 1,                   // 默认设为当前简历
}
```

## 4. 关键注意事项

1. **默认模型依赖**：
   - 上传前必须检查用户是否配置了 Default Model（OpenAI/DeepSeek 等）。
   - 前端/Handler 应拦截未配置的情况，避免 Agent 启动失败。
   
2. **文件路径问题**：
   - 代码中使用 `os.Getenv("PWD")` 获取根路径，确保运行目录正确（通常在项目根目录运行）。
   - Windows/Linux 路径分隔符由 `filepath.Join` 自动处理。

3. **Tool 必须先行**：
   - Agent 的 Prompt 必须强制引导 LLM 先使用 `pdf_to_text` 工具，否则 LLM 会因无法读取本地文件而产生幻觉。

## 5. 验证与测试

**预期结果**：
- HTTP 200 OK
- 数据库 `resumes` 表新增一条记录。
- `uploads/resumes` 目录下出现该文件。
