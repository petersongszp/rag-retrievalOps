### 2. 优化空间分析 (Why & How)

**优化点一：强化思维链 (CoT) 与 Reasoning 能力**
*   **现状**：当前 Prompt 是一次性给出的指令，模型容易在长文本解析中丢失细节，导致“幻觉”或遗漏。
*   **优化方案**：
    *   引入 **DeepSeek-R1** (或类似推理模型) 作为底层模型。
    *   在 System Prompt 中显式要求模型输出 `<thinking>` 过程，先进行原始文本的分块与语义理解，再生成最终 JSON。
    *   **价值**：显著提升复杂简历（如双栏排版、跨页项目）的解析准确率。

**优化点二：增强 JSON 输出的鲁棒性**
*   **现状**：完全依赖 LLM 的指令遵循能力生成 JSON，可能出现格式错误（如末尾多余逗号、Markdown 代码块包裹）。
*   **优化方案**：
    *   引入 **Eino OutputParser** 组件，对 LLM 的输出进行自动清洗和反序列化校验。
    *   定义明确的 Go Struct Schema，利用 Eino 的类型系统约束 LLM 输出。
    *   **价值**：消除“解析失败”的运行时错误，提高系统稳定性。

**优化点三：前端上传体验闭环**
*   **现状**：`/resume/page.tsx` 主要是“押题”入口，上传功能依赖跳转到个人中心，路径割裂。
*   **优化方案**：
    *   在简历解析页面直接集成 **拖拽上传组件**。
    *   增加 **解析进度实时反馈**（如：正在 OCR 识别 -> 正在提取技能 -> 正在生成画像）。
    *   **价值**：提供流畅的“上传即解析”体验，减少用户跳出。
