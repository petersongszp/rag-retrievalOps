# 第5章 方法论：企业级智能体构建工作流

在前面的章节中，我们已经掌握了 RAG 知识库的构建和 Tool 工具的使用，这些都是智能体（Agent）的“器官”。而要创造一个真正有智慧、能解决复杂问题的“生命体”，我们需要一套系统化的方法论来指导智能体的构建。本章我们将从“手工作坊”走向“工业化生产”，深入探讨企业级智能体的全生命周期管理、核心设计模式以及状态记忆管理。我们将结合 Eino 框架的特性，揭示如何通过规范化的工程实践，构建出稳定、可控且强大的面试智能体。

## 5.1 智能体生命周期管理

构建一个 Agent 绝不仅仅是写一段 Prompt 那么简单。在企业级开发中，Agent 的生命周期包含设计、开发和评估三个关键阶段，每个阶段都有其严格的标准和规范，且各阶段形成闭环，支撑 Agent 持续迭代优化。

### 5.1.1 设计阶段：Role（角色）、Goal（目标）、Constraint（约束）的定义

在编写任何代码之前，我们首先要为 Agent 制定“人设”。一个优秀的 Agent 定义必须包含三个核心要素：**Role（你是谁）**、**Goal（你要做什么）** 和 **Constraint（你不能做什么）**。这构成了 Prompt Engineering 的基石，也是企业级 Agent 与普通 Prompt 对话的核心区别——前者具备明确的身份边界、任务目标和行为准则。

#### 核心要素设计最佳实践
- **Role 设计**：不仅要定义专业背景，还需明确沟通风格、知识边界和行业经验。例如“拥有 8 年 Redis 内核研发经验、严谨且有耐心的技术面试官，聚焦 Redis 6.x 及以上版本的技术考察”，而非简单的“Redis 面试官”。
- **Goal 设计**：采用分层目标体系，核心目标明确核心价值，分层目标拆解执行路径。例如核心目标是“评估 Redis 专业能力”，分层目标可拆分为“初级：考察基础语法；进阶：挖掘项目落地经验；高阶：评估架构设计能力”。
- **Constraint 设计**：按维度分类约束（合规约束、功能约束、体验约束），避免模糊表述，确保 Agent 行为可预期。

*   **Role**：确立了 Agent 的专业背景、沟通风格和知识边界，确保 Agent 的输出符合场景人设。
*   **Goal**：通过分层设计明确任务边界和执行路径，防止 Agent 偏离核心目标，同时支撑动态调整的业务需求。
*   **Constraint**：多维度的约束像“护栏”一样，既保障合规性，又控制功能范围和用户体验，是企业级 Agent 稳定性的核心保障。

### 5.1.2 开发阶段：Prompt Engineering 与 Eino Graph 编排模式

设计完成后，我们需要将这些定义转化为可执行的代码。Eino 框架提供了 **Chain（线性链）** 和 **Graph（图）** 两种核心编排能力：
- **Chain**：线性执行流程，适用于简单的“Prompt→模型→输出”场景，执行路径固定；
- **Graph**：支持分支、循环、条件判断的复杂编排，适用于需要工具调用、多轮思考、动态决策的企业级场景。

#### 1. 基础 Agent 构建（Chain 模式）
在 [redis_agent.go](backend/internal/agents/interview/specialized/redis_agent.go) 中，我们通过 `adk.NewChatModelAgent` 将设计好的 Prompt 注入到 Agent 中，实现基础的线性执行流程：

```go
func NewRedisSpecializedAgent(userId uint, needResumeTool bool) (adk.Agent, error) {
    ctx := context.Background()
    // 1. 初始化LLM模型
    model, err := adk.NewOpenAIModel(ctx, &adk.OpenAIModelConfig{
        ModelName: "gpt-4o",
        ApiKey:    config.GetOpenAIKey(),
        Temperature: 0.7, // 控制问题的多样性
        MaxTokens: 500,   // 限制输出长度
    })
    if err != nil {
        return nil, fmt.Errorf("init model failed: %w", err)
    }

    // 2. 配置工具（如简历解析工具）
    var toolsConfig adk.ToolsConfig
    if needResumeTool {
        resumeTool, err := NewResumeAnalysisTool(userId)
        if err != nil {
            return nil, fmt.Errorf("init resume tool failed: %w", err)
        }
        toolsConfig = adk.ToolsConfig{
            ToolsNodeConfig: compose.ToolsNodeConfig{
                Tools: []componenttool.BaseTool{resumeTool},
                EnableToolCall: true,
                ToolCallMode:   "auto", // 自动判断是否调用工具
            },
        }
    }

    // 3. 构建基础Agent（Chain模式）
    baseAgent, err := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{
        Name:          "RedisSpecializedAgent",
        Instruction:   RedisSpecializedAgentInstruction, // 注入Prompt
        Model:         model,                            // 注入LLM
        ToolsConfig:   toolsConfig,                      // 注入工具
        MaxIterations: 15,                               // 设置最大思考轮数
        // 配置短期记忆滑动窗口
        ContextWindowSize: 10, // 只保留最近10轮对话
    })
    if err != nil {
        return nil, fmt.Errorf("init base agent failed: %w", err)
    }

    return baseAgent, nil
}
```

#### 2. 复杂场景编排（Graph 模式）
对于需要“工具调用→结果处理→二次思考”的复杂场景，我们使用 Eino Graph 实现分支逻辑。例如主面试官需要先调用简历工具解析候选人背景，再根据背景生成问题：

```go
// orchestrator.go - 主面试官Graph编排示例
func NewMainInterviewerAgent(userId uint) (adk.Agent, error) {
    ctx := context.Background()
    // 1. 初始化节点：简历解析节点
    resumeNode := adk.NewToolNode("ResumeAnalysisNode", NewResumeAnalysisTool(userId))
    // 2. 初始化节点：Redis面试官节点（复用基础Agent）
    redisAgentNode, err := adk.NewAgentNode("RedisAgentNode", NewRedisSpecializedAgent(userId, false))
    if err != nil {
        return nil, err
    }
    // 3. 初始化节点：Java面试官节点
    javaAgentNode, err := adk.NewAgentNode("JavaAgentNode", NewJavaSpecializedAgent(userId, false))
    if err != nil {
        return nil, err
    }

    // 4. 构建Graph：条件分支（根据简历技术栈选择对应面试官）
    graph := adk.NewGraph("MainInterviewerGraph")
    // 设置起始节点
    graph.SetStartNode(resumeNode)
    // 添加分支逻辑：简历解析后，根据技术栈选择节点
    graph.AddConditionalEdge(
        resumeNode,
        func(ctx context.Context, input any) (string, error) {
            // 解析简历工具的输出，判断核心技术栈
            resumeResult, ok := input.(*ResumeAnalysisResult)
            if !ok {
                return "default", nil
            }
            if strings.Contains(resumeResult.CoreSkills, "Redis") {
                return "redis", nil
            } else if strings.Contains(resumeResult.CoreSkills, "Java") {
                return "java", nil
            }
            return "default", nil
        },
        map[string]adk.Node{
            "redis":  redisAgentNode,
            "java":   javaAgentNode,
            "default": adk.NewLLMAgentNode("DefaultAgentNode", "请生成通用后端技术问题，聚焦基础能力考察"),
        },
    )
    // 设置结束节点（统一输出）
    graph.SetEndNode(adk.NewOutputNode("OutputNode"))

    // 5. 构建Graph Agent
    graphAgent, err := adk.NewGraphAgent(ctx, &adk.GraphAgentConfig{
        Name: "MainInterviewerAgent",
        Graph: graph,
        MaxIterations: 20,
    })
    if err != nil {
        return nil, fmt.Errorf("init graph agent failed: %w", err)
    }

    return graphAgent, nil
}
```

#### 3. 企业级优化：Prompt 版本管理
在企业级场景中，Prompt 需要频繁迭代，直接硬编码会导致迭代效率低且难以回滚。我们可将 Prompt 存储到配置中心（如 Nacos），实现 Prompt 与代码解耦：

```go
// prompt_manager.go - Prompt版本管理
type PromptManager struct {
    nacosClient *nacos.Client
}

// GetPrompt 根据Agent类型和版本获取Prompt
func (pm *PromptManager) GetPrompt(agentType string, version string) (string, error) {
    key := fmt.Sprintf("agent:prompt:%s:%s", agentType, version)
    prompt, err := pm.nacosClient.GetConfig(ctx, &nacos.ConfigParam{
        DataId: key,
        Group:  "interview-agent",
    })
    if err != nil {
        return "", fmt.Errorf("get prompt from nacos failed: %w", err)
    }
    return prompt, nil
}

// 在Agent构建中使用版本化Prompt
func NewRedisSpecializedAgentV2(userId uint, promptVersion string) (adk.Agent, error) {
    // 从配置中心获取指定版本的Prompt
    promptManager := NewPromptManager(nacosClient)
    prompt, err := promptManager.GetPrompt("redis-specialized", promptVersion)
    if err != nil {
        return nil, err
    }
    // 后续逻辑同基础Agent构建，注入动态获取的Prompt
    // ...
}
```

这种“配置化+编排化”的开发模式，使得我们可以快速迭代 Prompt 而无需修改底层逻辑代码，同时支持复杂场景的动态决策，实现了业务逻辑与工程实现的解耦，符合企业级开发的“高内聚、低耦合”原则。

### 5.1.3 评估阶段：如何量化 Agent 的表现

Agent 上线后，量化其表现是持续优化的核心。在 Agent 工程中，我们建立“指标体系+自动化评估+闭环优化”的评估流程，核心指标及落地方式如下：

| 评估维度 | 核心指标 | 计算方式 | 自动化评估工具 | 落地方式 |
|----------|----------|----------|----------------|----------|
| 准确性 | 知识点准确率 | 正确知识点数 / 总知识点数 | Ragas | 1. 构建面试知识点题库；2. 对比Agent问题/回答与题库的匹配度 |
| 幻觉率 | 事实幻觉率 | 捏造知识点数 / 总知识点数 | TruLens + Fact Checking API | 1. 检测Agent输出中的未验证知识点；2. 与权威文档对比验证 |
| 响应性 | 平均时延 | 总响应时间 / 对话次数 | Eino Trace + Prometheus | 1. 埋点记录Agent每轮思考/工具调用时间；2. 监控大盘可视化 |
| 体验性 | 问题适配度 | 问题与候选人背景的匹配度 | 自定义评分模型 | 1. 解析简历关键词；2. 评估Agent问题与关键词的重合度 |

#### 自动化评估集成示例（Ragas）
```go
// evaluation/ragas_evaluator.go
func EvaluateRedisAgent(conv []*adk.Message) (float64, float64, error) {
    // 1. 构造Ragas评估数据集
    dataset := ragas.NewDatasetFromMessages(conv, func(msg *adk.Message) ragas.Message {
        if msg.Role == "user" {
            return ragas.UserMessage(msg.Content)
        }
        return ragas.AssistantMessage(msg.Content)
    })
    // 2. 配置评估指标
    metrics := []ragas.Metric{
        ragas.Accuracy,
        ragas.Faithfulness, // 幻觉率反向指标
    }
    // 3. 执行评估
    result, err := ragas.Evaluate(dataset, metrics)
    if err != nil {
        return 0, 0, fmt.Errorf("ragas evaluate failed: %w", err)
    }
    // 4. 解析结果（准确率、幻觉率）
    accuracy := result.Scores[ragas.Accuracy]
    hallucinationRate := 1 - result.Scores[ragas.Faithfulness]
    // 5. 上报评估结果到监控系统
    reportToPrometheus("redis_agent_accuracy", accuracy)
    reportToPrometheus("redis_agent_hallucination_rate", hallucinationRate)
    return accuracy, hallucinationRate, nil
}

// 在Agent回调中触发评估
func AgentCallback(ctx context.Context, event *adk.AgentEvent) {
    if event.Type == adk.EventTypeConversationEnd {
        // 异步执行评估，不阻塞Agent响应
        go func() {
            _, _, err := EvaluateRedisAgent(event.Conversation)
            if err != nil {
                log.Error("evaluate agent failed", err)
            }
        }()
    }
}
```

#### 评估闭环：基于结果优化 Agent
评估结果需驱动 Agent 迭代，例如：
- 若准确率低于阈值：优化 RAG 知识库，补充缺失的知识点；
- 若幻觉率高于阈值：强化 Prompt 中的 Constraint，增加 Fact Checking 工具调用；
- 若时延过高：优化工具调用逻辑，减少不必要的思考轮数；
- 若问题适配度低：优化简历解析工具，增强关键词提取能力。

## 5.2 核心模式设计 (Design Patterns)

在解决复杂问题时，单一的“问答模式”往往力不从心。我们需要引入更高级的设计模式，让 Agent 学会思考、规划和协作，以下是企业级面试智能体中最核心的三类模式。

### 5.2.1 ReAct 模式：让 Agent 学会“思考-行动-观察-反思”

ReAct (Reasoning + Acting) 是目前最主流的 Agent 模式，核心是让 Agent 遵循“思考→行动→观察→反思”的循环，而非直接输出答案。在面试场景中，主面试官需要根据候选人回答，判断是否需要调用专项面试官工具，再根据返回结果调整后续提问，正是 ReAct 模式的典型应用。

#### 1. ReAct 模式的 Prompt 设计
要让 Agent 具备 ReAct 能力，需在 Prompt 中明确思考、行动、观察、反思的指令：

```go
// constants.go - 主面试官ReAct Prompt
const MainInterviewerInstruction = `
// Role
你是资深技术面试主考官，负责统筹全流程面试，可调用专项面试官工具解决专业问题。

// Goal
通过协调各专项面试官，全面评估候选人的技术能力，确保面试流程的完整性和专业性。

// ReAct 规则
1. 思考（Thought）：分析候选人的回答，判断是否需要调用专项工具，明确下一步目标；
2. 行动（Action）：若需要调用工具，指定工具名称和参数；若无需调用，直接生成结论；
3. 观察（Observation）：记录工具返回的结果或候选人回答的关键信息；
4. 反思（Reflection）：检查行动结果是否符合预期，若不符合，调整下一步策略。

// Constraint
- 每次思考必须明确记录“是否需要调用工具”及原因；
- 工具调用参数必须符合格式要求：{"tool": "xxx", "params": {...}}；
- 反思环节必须评估上一步行动的有效性。
`
```

#### 2. ReAct 模式的代码实现
在 [orchestrator.go](backend/internal/agents/multiagent/orchestrator.go) 中，我们为 ReAct 模式配置工具调用逻辑，并实现思考-行动-观察的循环：

```go
func NewMainInterviewerReActAgent(userId uint) (adk.Agent, error) {
    ctx := context.Background()
    // 1. 初始化专项面试官工具
    coTool, err := NewCoInterviewerTool() // Redis/Java等专项面试官工具
    if err != nil {
        return nil, err
    }
    projectTool, err := NewProjectInterviewerTool()
    if err != nil {
        return nil, err
    }

    // 2. 配置ReAct模式的Agent
    reactAgent, err := adk.NewReActAgent(ctx, &adk.ReActAgentConfig{
        Name:        "MainInterviewerReActAgent",
        Instruction: MainInterviewerInstruction,
        Model:       adk.NewOpenAIModel(ctx, &adk.OpenAIModelConfig{ModelName: "gpt-4o"}),
        Tools: []componenttool.BaseTool{coTool, projectTool},
        // ReAct循环配置
        MaxThoughtIterations: 10, // 最大思考轮数
        // 自定义思考解析器：提取Agent的思考、行动、反思内容
        ThoughtParser: func(content string) (*adk.ReActThought, error) {
            // 解析格式示例：
            // Thought: 需要调用Redis专项面试官，候选人回答涉及集群原理但表述模糊
            // Action: {"tool": "co_interviewer", "params": {"type": "redis", "question": "请解释Redis集群的槽位分配机制"}}
            // Observation: 工具返回问题：xxx
            // Reflection: 工具返回的问题符合预期，可继续追问
            lines := strings.Split(content, "\n")
            thought := &adk.ReActThought{}
            for _, line := range lines {
                if strings.HasPrefix(line, "Thought:") {
                    thought.Thought = strings.TrimPrefix(line, "Thought:")
                } else if strings.HasPrefix(line, "Action:") {
                    actionStr := strings.TrimPrefix(line, "Action:")
                    if err := json.Unmarshal([]byte(actionStr), &thought.Action); err != nil {
                        return nil, err
                    }
                } else if strings.HasPrefix(line, "Reflection:") {
                    thought.Reflection = strings.TrimPrefix(line, "Reflection:")
                }
            }
            return thought, nil
        },
    })
    if err != nil {
        return nil, fmt.Errorf("init ReAct agent failed: %w", err)
    }

    return reactAgent, nil
}
```

#### 3. ReAct 模式执行流程示例
当主面试官遇到候选人回答 Redis 集群问题模糊时，执行流程如下：
1. **Thought**：候选人提到Redis集群但未清晰解释槽位分配机制，需要调用Redis专项面试官工具，生成针对性追问；
2. **Action**：调用 `co_interviewer` 工具，参数为 `{"type": "redis", "focus": "集群槽位分配"}`；
3. **Observation**：获取到专项面试官生成的问题：“请详细解释Redis集群的槽位分配机制，包括槽位数量、分配策略及重分片流程”；
4. **Reflection**：工具返回的问题精准匹配候选人的知识盲区，符合预期；
5. **Final Answer**：将该问题反馈给候选人，继续面试流程。

### 5.2.2 Router 模式：多意图识别与任务分发

当系统支持多种能力（如Redis面试、Java面试、群面）时，需要一个“路由中心”根据用户意图将任务分发给不同的 Agent，这就是 Router 模式。Router 模式分为**静态路由**和**动态路由**，前者适用于意图明确的场景，后者适用于自然语言输入的模糊意图场景。

#### 1. 静态路由（意图明确）
在 [interview_agent_service.go](backend/internal/agents/usecase/interview/interview_agent_service.go) 中，我们实现了基于类型的静态路由，适用于前端指定 Agent 类型的场景：

代码清单5-3 静态路由分发逻辑
```go
// 定义Agent类型枚举
type InterviewAgentType string

const (
    ComprehensiveSchool InterviewAgentType = "comprehensive_school" // 校招综合面试

	case GroupInterview:

```

#### 2. 动态路由（模糊意图）
对于用户自然语言输入（如“我想练练Redis集群相关的面试题”），我们需要先通过 Classifier Agent 解析意图，再动态分发任务：

代码清单5-4 动态路由实现（Classifier Agent + 路由分发）
```go
// 1. 意图分类Agent Prompt
const ClassifierAgentInstruction = `
你是面试意图分类器，负责解析用户输入的意图，输出对应的Agent类型。
支持的Agent类型：specialized_redis、specialized_java、comprehensive_school、group_interview
输出格式：{"agent_type": "xxx", "confidence": 0.xx}
约束：
- 置信度低于0.7时，agent_type返回"comprehensive_school"
- 只输出JSON格式，不添加任何额外说明
`

// 2. 动态路由服务
func (s *InterviewAgentService) GetAgentByUserInput(input string, needResumeTool bool) (adk.Agent, error) {
    // 步骤1：调用Classifier Agent解析意图
    classifierAgent, err := adk.NewChatModelAgent(s.ctx, &adk.ChatModelAgentConfig{
        Name:        "ClassifierAgent",
        Instruction: ClassifierAgentInstruction,
        Model:       adk.NewOpenAIModel(s.ctx, &adk.OpenAIModelConfig{ModelName: "gpt-4o-mini"}),
        MaxIterations: 1,
    })
    if err != nil {
        return nil, err
    }
    // 执行分类
    classifyResp, err := classifierAgent.Run(s.ctx, adk.NewUserMessage(input))
    if err != nil {
        return nil, err
    }
    // 解析分类结果
    var classifyResult struct {
        AgentType  string  `json:"agent_type"`
        Confidence float64 `json:"confidence"`
    }
    if err := json.Unmarshal([]byte(classifyResp.Content), &classifyResult); err != nil {
        return nil, fmt.Errorf("parse classify result failed: %w", err)
    }

    // 步骤2：根据分类结果分发任务
    return s.GetInterviewAgent(InterviewAgentType(classifyResult.AgentType), needResumeTool)
}
```

#### 3. 路由模式的企业级优化
- **容错机制**：分类失败或置信度低时，兜底返回通用Agent，避免服务异常；
- **路由规则可视化**：将分类规则（如关键词匹配、意图映射）配置到可视化平台，非研发人员可调整；
- **路由监控**：统计各Agent的调用占比、分类准确率，优化分类Prompt和规则。

### 5.2.3 Plan & Execute：复杂任务的拆解与执行

对于“全链路模拟面试”这类复杂任务，Agent 不能走一步看一步，而需要预先规划执行步骤（Plan），再按计划执行（Execute），并根据执行结果动态调整计划。

#### 1. 全链路面试的 Plan 定义
在 Prompt 中显式定义结构化的 Plan，确保面试流程的完整性和逻辑递进性：

```go
// constants.go - 全链路面试Plan定义
const FullLinkInterviewInstruction = `
// Role
你是全链路模拟面试考官，负责从开场到总结的完整面试流程。

// Goal
通过结构化的面试流程，全面评估候选人的技术能力、沟通能力和问题解决能力。

// Plan（面试流程计划）
阶段1：开场（1分钟）
- 自我介绍，说明面试流程和时长
- 确认候选人是否准备就绪

阶段2：基础提问（5分钟）
- 围绕候选人简历中的基础技术栈提问
- 验证基础知识点掌握程度

阶段3：深度追问（10分钟）
- 针对项目经验中的核心问题深入追问
- 挖掘候选人的实际解决问题能力

阶段4：综合评估（3分钟）
- 总结候选人的优势和不足
- 给出针对性的改进建议

阶段5：答疑（1分钟）
- 解答候选人的疑问

// Execute（执行规则）
- 每完成一个阶段，输出阶段小结，并判断是否需要调整下一阶段的时长/内容
- 若候选人回答偏离主题，及时引导回归，确保计划完成
- 若候选人某一阶段表现优异/不足，动态调整下一阶段的问题难度

// Constraint
- 严格控制各阶段时长，总面试时长不超过20分钟
- 评估结论需基于候选人的实际回答，避免主观臆断
`
```

#### 2. Plan & Execute 模式的代码实现
通过代码注入动态 Plan，并在执行过程中监控阶段进度，调整执行策略：

```go

    // 面试计划状态

        currentStage string
        stageProgress float64
        adjustReason  string
    }

// NewFullLinkInterviewAgent 构建全链路面试Agent
func NewFullLinkInterviewAgent(userId uint) (*FullLinkInterviewAgent, error) {
    ctx := context.Background()
    // 1. 构建基础Agent，注入Plan定义
    baseAgent, err := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{

        return nil, err
    }
    // 2. 初始化计划状态
    return &FullLinkInterviewAgent{

        planStatus: struct {
            currentStage string
            stageProgress float64
            adjustReason  string
        }{
            currentStage:  "stage1", // 初始阶段：开场
            stageProgress: 0.0,
            adjustReason:  "",
        },
    }, nil
}

// RunStage 执行单个阶段，并更新计划状态
func (a *FullLinkInterviewAgent) RunStage(ctx context.Context, userInput string) (string, error) {
    // 1. 注入当前阶段状态到Prompt
    stagePrompt := fmt.Sprintf(`
当前面试阶段：%s
阶段进度：%.2f%%
上一阶段调整原因：%s
用户输入：%s
请按Plan执行当前阶段，并输出：
1. 阶段响应内容
2. 阶段小结
3. 下一阶段调整建议（如有）
`, a.planStatus.currentStage, a.planStatus.stageProgress, a.planStatus.adjustReason, userInput)
    // 2. 执行当前阶段
    resp, err := a.baseAgent.Run(ctx, adk.NewUserMessage(stagePrompt))

    // 3. 解析响应，更新计划状态（示例：解析下一阶段、进度、调整原因）
    a.updatePlanStatus(resp.Content)
    return resp.Content, nil
}

    if strings.Contains(respContent, "阶段2：基础提问") {
        a.planStatus.currentStage = "stage2"
        a.planStatus.stageProgress = 20.0
    } else if strings.Contains(respContent, "阶段3：深度追问") {

        a.planStatus.stageProgress = 45.0
    }
    // ...
}
```

#### 3. Plan & Execute 模式的核心优势
- **流程可控**：结构化的 Plan 确保复杂任务不遗漏关键步骤，符合企业级场景的流程规范；
- **动态调整**：基于执行结果调整计划，避免“一刀切”的固定流程，适配不同候选人的特点；
- **可追溯**：每个阶段的执行状态可记录，便于后续复盘和优化面试流程。

## 5.3 状态与记忆管理

Agent 本身是无状态的（Stateless），但在多轮对话场景中，记忆（Memory）是维持对话连贯性、实现个性化交互的关键。企业级 Agent 需同时管理**短期记忆**（会话上下文）和**长期记忆**（知识库/用户画像），并保证状态的分布式一致性。

### 5.3.1 短期记忆（Window Memory）vs 长期记忆（Vector Store）

短期记忆和长期记忆各司其职，共同支撑 Agent 的“认知能力”，其核心差异和落地方式如下：

| 记忆类型 | 存储内容 | 存储介质 | 核心特性 | 优化策略 |
|----------|----------|----------|----------|----------|
| 短期记忆（Window Memory） | 当前会话的上下文（用户输入、Agent 输出、工具调用结果） | 内存 + Redis（持久化） | 时效性强、容量有限、需快速访问 | 滑动窗口裁剪、关键信息提取、Token 控制 |
| 长期记忆（Long-term Memory） | 企业知识库、用户历史画像、面试历史记录 | Milvus 向量库 + MySQL（元数据） | 容量大、时效性弱、需精准检索 | 混合检索（关键词+向量）、检索结果重排序、知识更新机制 |

#### 1. 短期记忆：滑动窗口实现
Eino 框架的 `ChatModelAgent` 内置了滑动窗口机制，可配置保留最近 N 轮对话，避免 Token 溢出：

```go
// redis_agent.go - 配置短期记忆滑动窗口
func NewRedisSpecializedAgent(userId uint, needResumeTool bool) (adk.Agent, error) {
    // ...
    baseAgent, err := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{
        Name:          "RedisSpecializedAgent",
        Instruction:   RedisSpecializedAgentInstruction,
        Model:         model,
        ToolsConfig:   toolsConfig,
        MaxIterations: 15,
        // 短期记忆配置：只保留最近10轮对话（用户+Agent）
        ContextWindowSize: 10,
        // 自定义上下文裁剪策略：优先保留关键信息
        ContextFilter: func(messages []*adk.Message) []*adk.Message {
            filtered := make([]*adk.Message, 0)
            for _, msg := range messages {
                // 保留工具调用结果、核心问题/回答，过滤无关寒暄
                if strings.Contains(msg.Content, "工具调用结果") || strings.Contains(msg.Content, "Redis") {
                    filtered = append(filtered, msg)
                }
            }
            // 确保不超过窗口大小
            if len(filtered) > 10 {
                filtered = filtered[len(filtered)-10:]
            }
            return filtered
        },
    })
    // ...
}
```

#### 2. 长期记忆：RAG 融合检索
长期记忆的核心是“检索-增强”，即 Agent 在生成回答前，从向量库中检索相关知识，增强回答的准确性。以下是面试 Agent 中融合长期记忆的示例：

```go
// rag_agent.go - 融合长期记忆的Agent构建
func NewRAGEnhancedRedisAgent(userId uint) (adk.Agent, error) {
    ctx := context.Background()
    // 1. 初始化Milvus向量检索工具
    ragTool, err := NewMilvusRAGTool(&MilvusConfig{
        CollectionName: "redis_knowledge_base",
        TopK:           3, // 检索Top3相关知识
        ScoreThreshold: 0.7, // 相似度阈值
    })
    if err != nil {
        return nil, err
    }

    // 2. 构建RAG Chain：检索→增强Prompt→模型生成
    ragChain := adk.NewChain("RedisRAGChain")
    // 步骤1：检索相关知识
    ragChain.AddStep(adk.NewToolStep("RAGRetrieveStep", ragTool))
    // 步骤2：增强Prompt（将检索结果注入Prompt）
    ragChain.AddStep(adk.NewPromptStep("PromptEnhanceStep", func(input map[string]any) (string, error) {
        // 提取检索结果
        ragResults, ok := input["rag_result"].([]*MilvusSearchResult)
        if !ok {
            return "", fmt.Errorf("invalid rag result")
        }
        // 构建增强Prompt
        enhancedPrompt := fmt.Sprintf(`
%s

// 参考知识（请勿泄露来源）：
%s
`, RedisSpecializedAgentInstruction, formatRAGResults(ragResults))
        return enhancedPrompt, nil
    }))
    // 步骤3：模型生成回答
    ragChain.AddStep(adk.NewModelStep("ModelGenerateStep", model))

    // 3. 构建RAG增强的Agent
    ragAgent, err := adk.NewChainAgent(ctx, &adk.ChainAgentConfig{
        Name:  "RAGEnhancedRedisAgent",
        Chain: ragChain,
    })
    if err != nil {
        return nil, err
    }
    return ragAgent, nil
}

// formatRAGResults 格式化检索结果
func formatRAGResults(results []*MilvusSearchResult) string {
    var sb strings.Builder
    for i, res := range results {
        sb.WriteString(fmt.Sprintf("%d. %s（相似度：%.2f）\n", i+1, res.Content, res.Score))
    }
    return sb.String()
}
```

### 5.3.2 使用 Redis 管理多轮对话状态 (State Management)

在分布式系统中，仅依赖内存存储状态会导致服务重启/扩容后状态丢失。我们选择 Redis 作为会话状态的持久化存储，通过“内存计算 + Redis 持久化”的混合模式，兼顾响应速度和状态可用性。

#### 1. 会话元数据管理（Redis String）
轻量级的会话元数据（如当前面试阶段、候选人ID、已提问数量）通过 Redis String 存储，支持快速读写：

```go
// state/redis_state.go
type InterviewStateManager struct {
    redisClient *redis.Client
    prefix      string // 键前缀：interview:state:
}

// SetSessionState 存储会话状态
func (m *InterviewStateManager) SetSessionState(sessionId string, state *InterviewSessionState) error {
    key := fmt.Sprintf("%s%s", m.prefix, sessionId)
    // 序列化为JSON
    stateJSON, err := json.Marshal(state)
    if err != nil {
        return err
    }
    // 设置过期时间：24小时（面试会话超时）
    return m.redisClient.Set(ctx, key, stateJSON, 24*time.Hour).Err()
}

// GetSessionState 获取会话状态
func (m *InterviewStateManager) GetSessionState(sessionId string) (*InterviewSessionState, error) {
    key := fmt.Sprintf("%s%s", m.prefix, sessionId)
    stateJSON, err := m.redisClient.Get(ctx, key).Bytes()
    if err != nil {
        if err == redis.Nil {
            // 会话不存在，返回初始状态
            return &InterviewSessionState{
                CurrentStage: "stage1",
                QuestionCount: 0,
                UserId:        0,
            }, nil
        }
        return nil, err
    }
    // 反序列化
    var state InterviewSessionState
    if err := json.Unmarshal(stateJSON, &state); err != nil {
        return nil, err
    }
    return &state, nil
}

// InterviewSessionState 面试会话状态结构
type InterviewSessionState struct {
    SessionId     string  `json:"session_id"`
    UserId        uint    `json:"user_id"`
    CurrentStage  string  `json:"current_stage"` // 当前面试阶段
    QuestionCount int     `json:"question_count"` // 已提问数量
    LastQuestion  string  `json:"last_question"`  // 上一个问题
    CreateTime    int64   `json:"create_time"`    // 会话创建时间
```

#### 2. 对话消息流转（Redis Stream）
面试的完整对话记录通过 Redis Stream 存储，支持消息持久化、有序性和多服务协同处理：

代码清单5-5 基于 Redis Stream 的状态流转
```go
// mq/redis_stream.go
type RedisStreamQueue struct {
    client *redis.Client
    group  string // 消费组名称：interview_agent_group
}

// Publish 发布消息到 Redis Stream
func (q *RedisStreamQueue) Publish(ctx context.Context, message *Message) error {
    if message == nil || message.SessionId == "" {
        return fmt.Errorf("invalid message")
    }
    // Stream Key：interview:stream:{会话ID}
    streamKey := fmt.Sprintf("interview:stream:%s", message.SessionId)
    // 消息体：包含角色、内容、时间戳、阶段等
    values := map[string]interface{}{
        "role":        message.Role,        // user/agent/tool
        "content":     message.Content,     // 消息内容
        "timestamp":   message.Timestamp,   // 时间戳
        "stage":       message.Stage,       // 当前面试阶段
        "message_id":  message.MessageId,   // 唯一消息ID
        "session_id":  message.SessionId,   // 会话ID
    }
    // 使用 XADD 持久化存储消息，自动生成消息ID
    result := q.client.XAdd(ctx, &redis.XAddArgs{
        Stream: streamKey,
        Values: values,
    })
    if result.Err() != nil {
        return fmt.Errorf("xadd failed: %w", result.Err())
    }
    // 设置Stream过期时间：7天（保留面试记录）
    q.client.Expire(ctx, streamKey, 7*24*time.Hour)
    return nil
}

// Consume 消费指定会话的消息（支持重放历史对话）
func (q *RedisStreamQueue) Consume(ctx context.Context, sessionId string, startId string) ([]*Message, error) {
    streamKey := fmt.Sprintf("interview:stream:%s", sessionId)
    // XREAD 读取消息，从指定ID开始（$表示最新，0表示最早）
    streams := map[string]string{streamKey: startId}
    result, err := q.client.XRead(ctx, &redis.XReadArgs{
        Streams: streams,
        Count:   100, // 单次读取100条
        Block:   0,   // 阻塞等待（0表示无限等待）
    }).Result()
    if err != nil {
        if err == redis.Nil {
            return nil, nil // 无新消息
        }
        return nil, fmt.Errorf("xread failed: %w", err)
    }
    // 解析消息
    messages := make([]*Message, 0, len(result[0].Messages))
    for _, msg := range result[0].Messages {
        messages = append(messages, &Message{
            MessageId: msg.ID,
            SessionId: sessionId,
            Role:      msg.Values["role"].(string),
            Content:   msg.Values["content"].(string),
            Timestamp: int64(msg.Values["timestamp"].(float64)),
            Stage:     msg.Values["stage"].(string),
        })
    }
    return messages, nil
}

// 消费组配置：支持多服务协同处理
func (q *RedisStreamQueue) InitConsumerGroup(ctx context.Context, sessionId string) error {
    streamKey := fmt.Sprintf("interview:stream:%s", sessionId)
    // XGROUP CREATE 创建消费组（不存在时）
    err := q.client.XGroupCreateMkStream(ctx, streamKey, q.group, "0").Err()
    if err != nil && err.Error() != "BUSYGROUP Consumer Group name already exists" {
        return fmt.Errorf("xgroup create failed: %w", err)
    }
    return nil
}
```

#### 3. 企业级状态管理优化
- **过期策略**：按会话类型设置不同的过期时间（临时会话24小时，正式面试7天），避免Redis数据膨胀；
- **分布式锁**：使用 Redis Redlock 保证会话状态的并发修改安全（如同时更新面试阶段）；
- **状态备份**：每日将 Redis 中的关键状态备份到 MySQL，支持长期追溯和数据分析；
- **性能优化**：对高频访问的会话状态添加本地缓存（如LRU缓存），减少Redis访问次数。

## 5.4 企业级智能体工程化最佳实践

基于以上生命周期、设计模式和状态管理的实践，我们总结出企业级智能体构建的核心工程化原则：

### 1. 分层解耦
- **Prompt 层**：与代码解耦，通过配置中心管理，支持版本化迭代；
- **编排层**：通过 Chain/Graph 实现业务逻辑编排，与底层模型/工具解耦；
- **存储层**：短期记忆与长期记忆分离，状态存储与业务逻辑解耦。

### 2. 可观测性
- **日志埋点**：记录 Agent 的每一步思考、工具调用、状态变更；
- **指标监控**：实时监控准确率、幻觉率、时延等核心指标；
- **链路追踪**：通过 OpenTelemetry 追踪 Agent 完整执行链路，定位性能瓶颈。

### 3. 容错与降级
- **工具降级**：工具调用失败时，使用本地缓存或默认逻辑兜底；
- **模型降级**：大模型调用失败时，切换到轻量级模型（如gpt-4o-mini）；
- **会话容错**：状态读取失败时，恢复到最近的有效状态，避免会话中断。

### 4. 安全与合规
- **Prompt 安全**：过滤恶意输入，防止 Prompt 注入攻击；
- **数据合规**：用户对话数据加密存储，符合隐私保护法规；
- **权限控制**：不同 Agent 分配不同的工具调用权限，避免越权操作。

通过这套系统化的方法论和工程化实践，我们能够将智能体从“实验室原型”转化为“企业级应用”，实现稳定、可控、可扩展的智能体构建与运维。
