### 2. 优化空间分析 (Why & How)

**优化点一：从隐式路由迈向显式 Router 组件**
*   **现状**：多 Agent 的调度依赖主面试官的 LLM 决策，这在复杂场景下不稳定（如 LLM 忘记调用工具）。
*   **优化方案**：
    *   引入 **Eino Router 节点**：在 Graph 中显式定义一个 `RouterNode`，使用轻量级分类模型（或正则/关键词）解析用户意图。
    *   **价值**：降低对主模型推理能力的依赖，提高路由准确率和系统响应速度（Router 通常比 ChatModel 快）。

**优化点二：全局状态管理 (Context) 的分布式升级**
*   **现状**：`SessionManager` 是单机内存实现。如果服务部署多副本（K8s Replica > 1），用户请求落到不同 Pod 会导致会话丢失。
*   **优化方案**：
    *   引入 **Redis 集中式 Session 存储**。
    *   在 `AgentService` 中增加 Session 的序列化/反序列化逻辑，每次交互前从 Redis 拉取上下文，交互后回写。
    *   **价值**：支持服务的 **无状态化 (Stateless)** 水平扩展，这是“企业级”系统的核心指标。

**优化点三：人工介入 (Human-in-the-loop) 的补全**
*   **现状**：面试流程是全自动的，HR 无法实时干预。
*   **优化方案**：
    *   设计 **Admin API**：允许 HR 发送系统指令（如“结束面试”、“增加难度”）。
    *   在 Graph 中预留 **Human Node** 或 **Interrupt 机制**，在关键节点（如发放 Offer 前）暂停流程，等待人工确认。
    *   **价值**：增强系统的可控性，满足企业实际招聘中“人机协同”的需求。
