# 出版社技术图书写作规范 (Publisher Guidelines)

本文档汇总了出版社编辑团队对《企业级高并发AI Agent开发》一书的深度审稿意见。**这是本书的“写作宪法”，所有内容产出必须 100% 遵循本规范。**

## 1. 核心思维 (Core Mindset)

### 1.1 读者视角 (Reader-Centric)
*   **假设无先验知识**：假设读者是刚入行的工程师，不具备背景知识。
*   **知识闭环**：介绍一个概念时，必须讲清楚它的**定义、来源、用途**，不能突然冒出一个新词（如 ChatModel）而不解释。
*   **严禁 PPT 风格**：
    *   ❌ *Bad*: "Eino 的特点：1. 组件化 2. 图编排"（简单的罗列）
    *   ✅ *Good*: "Eino 的核心设计哲学在于组件化与图编排。通过将业务逻辑拆解为独立的组件..."（完整的段落式表述）

### 1.2 理论厚度 (Theoretical Depth)
*   **宏观介绍模板**：介绍新技术（如 Eino/Hertz）时，必须采用以下范式：
    *   **Who**: 由谁开发？（如：字节跳动基础架构团队）
    *   **What**: 是什么？（如：企业级大模型应用开发框架）
    *   **Features**: 有什么特点？（如：强类型、图编排、高扩展性）
    *   **Value**: 解决了什么问题？（如：解决了 Python 在高并发下的性能瓶颈及工程治理难题）
    *   **Where**: 得到了什么应用？（如：已在字节跳动内部亿级流量业务中落地）

## 2. 篇章结构规范 (Structure)

### 2.1 章首语 (Chapter Intro) —— **强制要求**
每一章或每一节（Section）的开头，**严禁直接罗列知识点**。必须包含一段“承上启下”的过渡文字（开篇语）：
1.  **背景/综述**：简单回顾上一节内容或介绍当前背景。
2.  **痛点/需求**：引出为什么要讲这一节。
3.  **预告**：明确本节将要介绍的核心内容。

> *示例*：“推荐系统是一个典型的大数据、高度实时的复杂系统...因此，我们要将推荐系统拆分成若干模块...要拆分成哪些模块，模块间如何配合，这就是本节要介绍的内容。”

### 2.2 本章小结 (Chapter Summary)
*   **拒绝空话**：不要说“本章介绍了 AI 的基础，很重要”。
*   **实质总结**：必须具体回顾本章介绍了哪些**具体技术**，以及它们在系统中的**具体用途**。

### 2.3 项目实战引入
*   **引入逻辑**：先说**目的**（要做什么），再说**功能**（用来干什么），最后**拆解**（包含哪些模块）。
*   **关联性**：明确指出“本书后续章节的内容均围绕本示例展开”。

## 3. 排版与格式 (Formatting)

### 3.1 列表与层级
*   **项目符号**：多个并列选项（无严格时序关系），**必须使用实心圆点（•）或方块**，**严禁使用数字（1. 2. 3.）**。数字仅用于步骤明确的操作流程。
*   **拒绝过度嵌套**：不要出现多层缩进。如果层级太深，请拆分为正文段落。

### 3.2 文字规范
*   **严禁斜体**：中文排版中**严禁使用斜体**。强调内容使用**加粗**。
*   **严禁箭头流**：正文中不要用 `A -> B -> C` 来描述流程，请用完整的文字：“数据首先经过 A，然后流转至 B，最终到达 C”。
*   **术语一致性**：同一个概念在全书中必须统一叫法。
    *   ❌ *Bad*: 混用“组件”、“原语”、“形态”。
    *   ✅ *Good*: 统一称为“组件”。

### 3.3 代码展示
*   **第1章原则**：作为理论铺垫章节，**尽量不贴大段代码**，避免劝退读者。更多使用架构图和概念图。
*   **解释前置**：在贴代码之前，必须先用文字详细解释代码的**意图、逻辑和关键点**（先声明，后使用）。
*   **拒绝注释依赖**：不要把核心原理解释写在代码注释里，要写在正文中。

## 4. 常见问题自检 (Self-Check)

*   [ ] **是否像 PPT？**（如果有很多短句列表，请改为段落）。
*   [ ] **章首语有了吗？**（每节开头是否有过渡段落）。
*   [ ] **数字列表用对了吗？**（并列关系请改用 bullet points）。
*   [ ] **斜体删了吗？**（中文不要斜体）。
*   [ ] **理论讲透了吗？**（是否按照 Who-What-Features-Value 模板介绍）。
*   [ ] **读者能看懂吗？**（是否假设了读者无背景知识，做到了闭环介绍）。
