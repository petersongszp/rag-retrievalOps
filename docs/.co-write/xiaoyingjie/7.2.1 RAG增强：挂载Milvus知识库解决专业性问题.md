# 7.2 实现路径

在前面的章节中，我们已经成功搭建了具备上下文记忆能力的多轮对话引擎，并定义了各种领域的智能体专家。然而，引擎的骨架再强健，如果缺乏“真才实学”，AI 面试官依然会在深度问题上露怯，甚至产生“一本正经胡说八道”的幻觉（Hallucination）。为了让系统真正具备企业级鉴别能力，我们必须将其与外部知识库进行连通。本部分将详细介绍如何通过工具扩展，完成面试系统能力的跳跃式升级。

## 7.2.1 RAG增强：挂载 Milvus 知识库解决专业性问题

在大语言模型落地业务的最佳实践中，RAG（检索增强生成，Retrieval-Augmented Generation）几乎是不可或缺的一环。既然我们的人工智能扮演的是“专项技术专家”，它就必须熟知当前团队的底层架构、最新的业务源码规范以及最权威的八股文答案。为了解决这个问题，我们在系统中引入了强大的向量数据库——Milvus。

### Milvus 检索工具的设计定位

在通过代码实现功能之前，我们先在架构层面理清这个外部检索器的高层定义：

*   **由谁提供（Who）**：底层依赖于业内顶级的开源分布式向量数据库 Milvus，在我们的应用工程内，它由基础的服务调用模块封装为 Eino 标准扩展工具。
*   **是什么（What）**：它是一个被大模型在推理过程中，根据自身“无知识把握”的情况而主动触发并在后台静默调用的查询 API（`get_milvus_retriever`）。
*   **设计特点（Features）**：
    *   **入出参结构化**：具备严格限定的 JSON Schema 进出规范。
    *   **弹性超时控制**：强制设定了极短的 3 秒上下文超时时间。
    *   **优雅降级**：当数据库宕机或未检索到内容时，不会向上抛出致命报错中断面试，而是返回格式化的空库声明，引导大模型按原有知识储备继续提问。
*   **核心价值（Value）**：彻底打消了 AI 面试官在评判深层技术细节时的不肯定与幻觉，赋予了其查阅“小抄”和“标准答案”的能力，使评判更加权威、精准。

### 实战：构建 Eino 标准向量检索工具

在 Eino 框架中，将一个普通的 Go 函数转化为大模型可理解并调用的 Tool，有着非常优雅的封装模式。我们不需要手写繁琐的 JSON 声明描述，而是可以直接利用 Eino 提供的 `utils.InferTool` 方法。

首先，我们定义好工具的入参和出参。大模型在调用工具时，系统会自动利用反射机制，将这两类结构体转换为对应的 API 元数据：

```go
// 源码路径: backend/internal/agents/tools/milvus_retriever_tool.go

// MilvusRetrieverInput 检索工具的输入参数
type MilvusRetrieverInput struct {
	// 查询文本，大模型必须将它的疑惑提炼为这个字段
	Query string `json:"query" description:"要检索的查询文本"`
}

// MilvusRetrieverOutput 检索工具的输出结果
type MilvusRetrieverOutput struct {
	Documents []DocumentInfo `json:"documents" description:"检索到的相关文档列表"`
	Count     int            `json:"count" description:"检索到的文档数量"`
	Error     string         `json:"error,omitempty" description:"错误信息"`
}
```

接下来是检索核心逻辑的编写。在这段代码中，请重点关注 **上下文超时控制（Timeout）** 与 **错误抹平（Graceful Degradation）** 的工程处理。我们不能因为一次辅助检索数据的失败，就让整个 WebSocket 面试连线断开。

```go
// GetMilvusRetriever 检索向量数据库中的数据
func GetMilvusRetriever(ctx context.Context, query string) (string, error) {
	if query == "" {
		return "", fmt.Errorf("query cannot be empty")
	}

	// 1. 获取全局单例的 Milvus 连接管理器
	mgr, err := milvus.GetMilvusManager()
	if err != nil {
        // 如果连接失败，不抛出系统 error，而是返回内部定义的错误 JSON
		return formatErrorOutput(fmt.Sprintf("向量数据库管理器初始化失败: %v", err), 0)
	}

	retriever := mgr.RetrieverService

	// 2. 核心架构约束：执行检索时，添加 3 秒硬性超时控制
	ctxWithTimeout, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()

	documents, err := retriever.Retrieve(ctxWithTimeout, query)
	if err != nil {
		log.Printf("检索失败或超时: %v", err)
		return formatErrorOutput(fmt.Sprintf("检索失败或超时: %v", err), 0)
	}

	// 3. 检查检索结果，若为空则直接返回安全的空切片 JSON
	if len(documents) == 0 {
		return formatOutput([]DocumentInfo{}, 0)
	}

	// ... (遍历并格式化 docInfos 的组装代码略)

	return formatOutput(docInfos, len(docInfos))
}
```

最后一步，也是利用 Eino 组件库最关键的一步。我们将业务层的 `GetMilvusRetrieverWithInput`（接收结构体的方法封装）通过 `InferTool` 注册为标准工具。在这里不仅需要指明方法体，还要极尽详实地填写工具的功能描述，因为这直接决定了大模型在何种情况下会选择触发它。

```go
// GetMilvusRetrieverTool 创建供智能体挂载的向量数据库检索工具
func GetMilvusRetrieverTool() (tool.InvokableTool, error) {
    // InferTool 可以通过反射自动分析入出参，省去手写配置的繁琐
	t, err := utils.InferTool(
		"get_milvus_retriever",
		"从向量数据库中检索出对应相关的数据。输入查询文本，返回最相关的文档列表。",
		GetMilvusRetrieverWithInput, // 接收带有结构体输入参数的包装函数
	)
	if err != nil {
		return nil, errors.NewMilvusError("创建检索工具失败", err)
	}
	return t, nil
}
```

> **思考**：在为大语言模型打造外挂工具时，“失败响应怎么设计”往往比“成功逻辑怎么写”更考验工程功底。正如上述代码所展示的，如果 Milvus 发生超时，我们绝不使用 `return "", err` 直接抛出系统异常，而是将其包装进 `formatErrorOutput` 转化为带有 Error 字段的 JSON 文本返回给大模型（大模型眼中这是一次“成功但在业务上失败”的调用）。这在保障了面试会话系统容错率的同时，也使 LLM 得以据此平滑放弃知识库支持，转为依赖自身算力强行控场。

### 本节小结

本小节讲述了如何通过工具扩展将外部专业知识注入给大模型。我们遵循底层架构的严谨要求，剖析了在构建 Milvus 检索工具时应当注意的 JSON 结构规范、3秒强制超时控制，以及防御性的“优雅降级”错误封装。利用 Eino 自带的 `InferTool` 反射特性，我们只写了极少的配置胶水代码，便完成了 RAG 系统的核心挂载。通过打通知识壁垒，专项面试官终于不再是空有其表的理论讲演者，而是手握真理的“主考官”了。
