# 9.1.1 全场景覆盖的系统定位：集面试、分析、推荐于一体的解决方案

在第 5 至第 8 章中，我们完成了单个 Agent 从创建到运行的全部技术细节：Prompt 工程、RAG 知识增强、Graph 编排、工具调用。这些技术能力就像一块块独立的积木。而从第 9 章开始，我们要做的事情是**用这些积木搭建一座完整的建筑**——一个能在真实企业环境中运转的、覆盖候选人评估全链路的智能体系统。

在动手写代码之前，有必要先退一步，从产品视角审视一个关键问题：这套系统到底要覆盖哪些场景？每个场景由哪类 Agent 承载？它们之间的关系是什么？只有想清楚了"要做什么"，后面的架构设计才不会跑偏。

## 六大功能模块：从简历到评估的全链路闭环

我们的系统并非一个"只会问问题的 AI 面试官"，而是一套覆盖候选人评估全生命周期的解决方案。它由六个功能模块组成，每个模块由一类或多类 Agent 驱动：

```
┌─────────────────────────────────────────────────────────────────┐
│                      候选人评估全链路                              │
│                                                                 │
│  ① 简历解析 ──→ ② 面试押题 ──→ ③ 专项面试 ──→ ⑤ 实时评分        │
│       │                          ④ 综合面试        │             │
│       │                          ④ 多人模拟面试     │             │
│       └─────────────────────────────────────────→ ⑥ 评估报告    │
└─────────────────────────────────────────────────────────────────┘
```

### 模块一：简历解析（ResumeParserAgent）

这是整条链路的起点。当候选人上传一份 PDF 简历后，`ResumeParserAgent` 会完成三件事：调用 `pdf_to_text` 工具将 PDF 转化为纯文本；提取基本信息、工作经历、技术栈等结构化数据；最关键的一步——**调用 RAG 知识库（Milvus）进行"行业标准对齐"**，将简历中的技术关键词与内部面试题库中的考察权重和评级标准进行匹配，生成一份增强版的候选人画像。

```go
// 简历解析 Agent 的工具配置
Tools: []componenttool.BaseTool{
    tool2.CreatePDFToTextTool(),   // PDF 转文本
    milvusTool,                    // RAG 知识库检索
},
```

这份画像有什么用？它会被传递给后续的面试 Agent，让面试官在提问时能够"看着简历"提出有针对性的问题，而不是一套通用的标准题库。

### 模块二：面试押题（PredictionAgent）

有了结构化的简历画像后，`PredictionAgent` 能够根据候选人的技术栈和目标岗位，预测可能被问到的 5 道面试题。每道题不仅包含问题本身，还提供了考察重点（`focus`）、回答思路（`thinking_path`）、参考答案（`reference_answer`）和可能的追问（`follow_up`），帮助候选人提前做有针对性的准备。

这个功能看似简单——"让 AI 出几道题"——但它的价值在于**将 AI 的能力从"面试中"扩展到了"面试前"**，让系统从一个纯粹的评估工具转变为一个兼具练习和辅导功能的学习平台。

### 模块三：专项面试（Go / Java / MySQL / Redis / MQ）

这是系统的核心战斗力。五个专项面试官 Agent 各自专注于一个技术领域，它们共享同一套代码架构（统一模型接入层、RAG 工具、简历工具），但拥有完全不同的"人格"——由各自独立的 `Instruction` 系统提示词定义。

```go
// 五个专项面试官，结构相同，人格各异
const GoSpecializedAgentInstruction = `你是一个经验丰富的 Go 专项技术面试官...`
const JavaSpecializedAgentInstruction = `你是一个经验丰富的 Java 专项技术面试官...`
const MQSpecializedAgentInstruction = `你是一个经验丰富的消息队列（MQ）专项技术面试官...`
const MySQLSpecializedAgentInstruction = `你是一个经验丰富的 MySQL 专项技术面试官...`
const RedisSpecializedAgentInstruction = `你是一个经验丰富的 Redis 专项技术面试官...`
```

这种"相同骨架、不同灵魂"的设计，让新增一个面试领域（比如 K8s 或 Kafka）变得非常轻量——只需编写一段新的 `Instruction` 并注册到工厂函数中即可，不涉及任何架构层面的改动。

### 模块四：综合面试与多人模拟面试

除了专项面试，系统还提供两种更高级的面试模式：

**综合面试**分为"校招"和"社招"两个变体（`ComprehensiveSchool` / `ComprehensiveSocial`），面试官会同时涉及多个技术领域，模拟真实面试中"综合能力评估"的场景。

**多人模拟面试**（`GroupInterview`）则更进一步，采用了多 Agent 协作的架构。一个"主面试官"（`MainInterviewer`）负责全局节奏把控，两个"副面试官"——技术面试官（`CoInterviewer`）和项目面试官（`ProjectInterviewer`）——作为 Agent 工具（`AgentAsTool`）被主面试官按需调度。当候选人的回答涉及深层技术细节时，主面试官会自动将话语权交给技术面试官；当聊到项目经历时，则切换到项目面试官。

```go
// 多 Agent 协作：副面试官被包装为主面试官的"工具"
coTool := adk.NewAgentTool(ctx, coAgent)         // 技术面试官 → 工具
projectTool := adk.NewAgentTool(ctx, projectAgent) // 项目面试官 → 工具

hostAgent, _ := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{
    Name:  "MainInterviewer",
    Tools: []componenttool.BaseTool{coTool, projectTool, resumeTool},
    MaxIterations: 30,
})
```

这种"Agent 作为工具"的嵌套组合模式，是 Eino 框架提供的一项强大能力，它让我们能够在不增加架构复杂度的前提下，实现多角色协作的面试场景。

### 模块五：实时评分（Evaluator）

在面试进行的每一轮问答中，`Evaluator` 评分器都会在后台默默工作。它接收面试官的问题和候选人的回答，从正确性、深度、完整性、实践性四个维度进行打分，输出一个 1-10 分的加权总分，并建议下一步动作（深入追问 / 继续 / 降低难度 / 切换话题）。

评分器的输出直接驱动了 9.3.2 节中介绍的 Graph 编排的分支决策——它是面试循环的"方向盘"。

### 模块六：评估报告（RecordEvaluation / AnswerRecordAgent）

面试结束后，系统不会把候选人"丢在原地"。两个评估 Agent 从不同维度生成报告：`RecordEvaluationAgent` 对整场面试进行宏观评估，输出 4-8 个维度的综合评分和改进建议；`AnswerRecordAgent` 则深入到每一道题，逐题分析候选人的优势、不足、参考答案和学习建议。

这些报告不仅面向企业面试官（辅助招聘决策），也面向候选人本人（支撑持续学习），让系统的价值延伸到了"面试后"的反思与成长阶段。

## 统一基础设施：六大模块的"公共底座"

虽然六个模块各自承担不同的业务功能，但它们共享同一套基础设施层。从前面几节介绍的代码中，你已经见过了这些共享组件：

- **统一模型接入层**（9.2.1 节）：所有 Agent 都通过 `llm.CreatOpenAiChatModel` 获取模型实例，无需关心底层供应商。
- **限流与熔断**：通过装饰器模式的 Transport 管线，所有模型调用共享同一套限流和熔断策略。
- **RAG 知识库**：简历解析 Agent 和专项面试官 Agent 都使用同一个 Milvus 向量数据库进行知识检索。
- **输出守卫**（9.3.1 节）：评分器的 JSON 清洗和数值校验逻辑，为所有涉及结构化输出的场景提供了统一的防线。

这种"公共底座 + 差异化上层"的架构，意味着在底座层面做的每一次改进（比如引入一个新的模型供应商、升级限流算法）都会自动惠及所有六个模块，大幅降低了维护和演进的成本。

## 本节小结

本节从产品视角出发，梳理了系统的六大功能模块：简历解析、面试押题、专项面试、综合与多人面试、实时评分、评估报告。这六个模块覆盖了候选人评估的"面试前-面试中-面试后"全生命周期，共同构成了一个闭环的智能评估体系。在实现层面，它们共享统一的模型接入层、限流熔断策略和 RAG 知识库等基础设施，形成了"公共底座 + 差异化Agent"的可扩展架构。
