# 7.1.1 场景：模拟 Go/Java 等技术专家进行深度追问

在之前的系统流程中，我们已经搭建了能够进行多轮对话的基础面试框架。然而，面试过程中的痛点往往在于“深度”二字——通用的语言模型容易提出宽泛、浮于表面的问题，无法像真正的资深工程师那样，针对候选人的项目细节进行抽丝剥茧式的追问。为了解决这一难题，我们需要在系统中引入具备特定领域知识的**专项技术专家智能体（Specialized Agent）**。本小节将详细拆解如何为系统赋予 Go 语言、Java 语言等特定技术栈的“专家人格”，并演示怎样结合工具检索来实现精准的深度追问。

### 技术专家智能体的核心价值

什么是专项技术专家智能体？在这个面试系统中，它是一个专门负责某一垂直技术领域（如 Go、Java、MySQL、Redis 或消息队列）的独立 AI 节点。
*   **深耕垂直领域**：通过精细化的提示词（Prompt），限定智能体的探讨范围与深度，要求其关注底层原理与最佳实践。
*   **动态知识校验**：集成专有知识库（如 Milvus 工具），赋予智能体查阅“标准答案”与“行业内幕”的能力，防止 AI 产生幻觉或被候选人误导。
*   **上下文感知**：结合候选人的简历信息，做到千人千面的个性化发问。

专项面试官的加入，彻底解决了大模型在模拟面试中“懂而不精”的工程瓶颈，使得我们的应用能够真正胜任企业级高级技术岗位的初筛任务。

### 专家智能体的核心设计与工具编排

在构建专项面试官时，我们采用的是一种“人格灌输 + 武器挂载”的组装模式。这里的“武器”，就是各种扩展工具编排。

我们以 Go 专项技术面试官的构造过程为例。在代码落地上，系统不只是简单地实例化一个模型对象，而是进行了周密的依赖注入。首先，系统获取与向量数据库交互的 `Milvus` 检索工具，让 AI 具备翻阅知识库的能力；其次，系统会根据场景判断是否需要加载“简历提取工具”，帮助 AI 了解候选人背景。随后，所有的工具被封装为统一的工具配置参数，注入给核心的 `ChatModelAgent`。

以下是我们系统的 Go 专家智能体初始化源码。阅读这段代码时，请重点关注 `tools` 切片的组装过程，以及 `adk.NewChatModelAgent` 方法是如何将定制化指令（Instruction）和外部工具绑定起来的。

```go
package specialized

import (
	"context"
	"fmt"
	"interview-agents/internal/agents/llm"
	tool2 "interview-agents/internal/agents/tools"

	"github.com/cloudwego/eino/adk"
	componenttool "github.com/cloudwego/eino/components/tool"
	"github.com/cloudwego/eino/compose"
)

// NewGoSpecializedAgent 创建 Go 专项面试官智能体
// 专注于评估候选人在 Go 语言方面的专业技能和深度
func NewGoSpecializedAgent(userId uint, needResumeTool bool) (adk.Agent, error) {
	ctx := context.Background()

    // 1. 初始化 Milvus 检索工具，赋予 AI 查阅深度知识的能力
	milvusTool, err := tool2.GetMilvusRetrieverTool()
	if err != nil {
		return nil, fmt.Errorf("failed to create Milvus retriever tool: %w", err)
	}

	var tools []componenttool.BaseTool
	tools = append(tools, milvusTool)

    // 2. 根据上下文情况，动态挂载简历信息工具
	if needResumeTool {
		tools = append(tools, tool2.GetResumeInfoTool())
	}

	toolsConfig := adk.ToolsConfig{
		ToolsNodeConfig: compose.ToolsNodeConfig{
			Tools: tools,
		},
	}

    // 3. 实例化底层的对话模型
	model, err := llm.CreatOpenAiChatModel(ctx, userId)
	if err != nil {
		return nil, fmt.Errorf("failed to create OpenAI chat model: %w", err)
	}

    // 4. 将预设提示词 (GoSpecializedAgentInstruction) 与各类外部工具进行融合装配
	baseAgent, err := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{
		Name:          "GoSpecializedAgent",
		Description:   "Go 专项面试官智能体，专注于评估候选人在 Go 语言方面的专业技能和深度",
		Instruction:   GoSpecializedAgentInstruction,
		Model:         model,
		ToolsConfig:   toolsConfig,
		MaxIterations: 15,
	})
	if err != nil {
		return nil, fmt.Errorf("failed to create Go specialized agent: %w", err)
	}
	return baseAgent, nil
}
```

值得一提的是，上述架构具有极高的复用性。不论是构建 Java 专家、数据库专家还是消息队列架构师，我们都可以复用这套装配流水线，唯一需要动态替换的，就是赋予 AI 灵魂的提示词（Instruction）。

### 提示词工程：如何让 AI 问得“刀刀见血”？

一个能够深度追问的专家级 AI，不仅仅依赖底层的 LLM 能力，更需要我们通过严谨的架构视角去设计其约束与策略（Prompt Engineering）。在我们的系统中，专家的核心提示词（例如 `GoSpecializedAgentInstruction`）被高度结构化分为几个层面设计。

在介绍这部分配置前，我们先梳理一下这套提示词背后的系统设定思路。我们严格限制了 AI 的单次产出，防止它像教科书一样一次性抛出所有问题；同时，为了保证面试体验的真实性，我们强制 AI 采取开放式讨论，拒绝机械化的算法默写测试。更关键的是，我们定义了一套 RAG（检索增强生成）工具的使用纪律。

让我们一探 `constants.go` 中对领域专家的核心提示声明：

```go
package specialized

// RAGInstruction 知识库检索相关的通用提示词，规范工具调用纪律
const RAGInstruction = `
你拥有查阅内部知识库的能力。在评判候选人的回答或准备进行深度追问时，如果你需要核对标准答案或行业深度细节，可以调用 get_milvus_retriever 工具。
调用要求：
1. query 必须精简为核心知识点（如：“Redis持久化AOF原理”、“Go map底层结构”），不要使用完整的问句。
2. 如果知识库没有返回有用信息，请结合你的原生知识继续提问，绝对不要对候选人提及“知识库没查到”之类的话。`

// GoSpecializedAgentInstruction Go 专项面试官智能体的提示词
const GoSpecializedAgentInstruction = `你是一个经验丰富的 Go 专项技术面试官。你的目标是通过深入的技术对话，全面评估候选人在 Go 语言方面的专业技能和深度。

核心职责：
- 根据候选人的背景进行有针对性的提问
- 每次调用只生成一道问题
- 通过递进式的问题深入了解候选人的 Go 专业能力

重要约束：
- 不要要求候选人编写代码或提供代码片段
- 面试应该是纯粹的技术讨论和知识考察

面试策略：
1. 第一个问题：从候选人的 Go 项目经验出发
2. 问题设计：
   - 深入挖掘 Go 的核心特性应用和理解
   - 关注并发编程、性能优化、系统设计的理论和实践
   - 难度循序渐进，根据回答灵活调整
   
提问建议：
- 提出开放式问题，深入了解候选人的思考过程和理论基础
- 如果候选人回答不完整，通过追问引导其深入思考
` + RAGInstruction + outputFormatPlainText
```

这套设计的巧妙之处在于运用了分层挂载的策略：
*   **角色约束锚点**：明确设定面试官身份，严禁 AI 进行在线笔试和代码测验（即“不要要求候选人编写代码”）。
*   **循序渐进策略**：指令中强调“难度循序渐进”和“一次只问一道问题”，这种多轮切分的交互设计，才能使模拟面试呈现出步步紧逼的“压迫感”。
*   **工具纪律（RAG Instruction）**：AI 经常会在没有检索到答案时表现出“抱歉，我没有查到相关数据”的机器人回复。通过硬性规则**“绝对不要对候选人提及知识库没查到”**，我们维护了面试官专业、严谨的人设不会崩塌。

> **思考**：真正的架构之美不在于堆砌技术组件，而在于如何通过极致的约束让系统呈现出优雅的业务结果——在 AI 研发中，提示词就是我们控制不确定性的最强锁扣。

### 本节小结

本小节我们深入讲解了如何设计与实现专项技术专家智能体。我们探讨了以 `adk.NewChatModelAgent` 为核心的组装模式，为智能体动态挂载了简历审查和知识库查阅（Milvus）的扩展工具。同时，我们剖析了让 AI 实现“纵深追问”的核心机制——通过结构化的分层提示词，定义系统策略并规范了检索工具的调用要求。这一整套系统化方法，让原本空洞的通用语言模型化身为了在 Go、Java 等特定领域具有深厚功底的技术大牛，为我们的智能面试系统注入了真正的企业级考验能力。
