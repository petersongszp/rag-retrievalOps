# 第3章 记忆之源：构建基于Milvus的RAG知识库

在构建“智能面试官”这样的垂直领域Agent时，通用的预训练模型（LLM）往往面临“知识截止”和“领域幻觉”两大挑战。面试场景要求系统不仅要懂通用的编程概念，还要精准掌握特定的中间件版本特性、最新的Go语言Proposal，甚至是企业内部的面试题库。

为了赋予Agent“专业记忆”，我们需要构建一个基于检索增强生成（Retrieval-Augmented Generation, RAG）的知识库系统。本章将带领大家深入 `internal/eino/milvus` 模块，从零构建一个生产可用的向量检索系统。

## 3.1 RAG架构设计：让Agent拥有“外挂大脑”

在开始编码之前，我们先梳理一下RAG的核心数据流。一个成熟的RAG系统不仅仅是“把文本存进数据库”，它包含了一条完整的数据处理流水线（Pipeline）。

### 3.1.1 知识库的数据流转

在本项目中，我们设计了如下的数据流转路径：

1.  **加载（Load）**：支持Markdown文档、PDF简历等多种格式的源数据读取。
2.  **切分（Split）**：将长文档按语义切分为适合模型理解的“块”（Chunks）。这是决定检索质量的关键一步。
3.  **嵌入（Embed）**：使用Embedding模型（本项目采用字节跳动Doubao-Embedding）将文本转换为高维向量。
4.  **存储（Store）**：将向量及其元数据（Metadata）持久化存储到Milvus向量数据库中。
5.  **检索（Retrieve）**：在对话过程中，将用户的问题转化为向量，在Milvus中进行相似度搜索（ANN Search），并结合标量字段进行过滤。

### 3.1.2 模块设计详解

我们在 `backend/internal/eino/milvus` 目录下采用了清晰的分层设计，确保各组件的高内聚低耦合：

```text
backend/internal/eino/milvus/
├── cmd/
│   └── milvusctl/      # 知识库管理CLI工具，用于离线导入和测试
├── splitter/
│   └── markdown.go     # 针对Markdown优化的文档切分器
├── retrieval/
│   ├── retriever.go    # 封装Eino的Retriever组件
│   └── filter.go       # 动态过滤逻辑实现
├── storage/
│   ├── embedding.go    # 向量化服务封装
│   └── indexer.go      # 索引管理
└── manager.go          # 统一入口，协调各子模块
```

这种结构使得我们可以独立测试切分算法，或者替换底层的向量数据库，而无需修改上层的业务逻辑。

## 3.2 文档处理与向量化

通用文本切分器（如按字符数切分）在处理技术文档时往往表现不佳。例如，它可能会把一段完整的代码或者一个核心概念的定义拦腰截断，导致召回的上下文缺失关键信息。为此，我们实现了专门的 Markdown 切分器。

### 3.2.1 实现Markdown文档切分器

在 `backend/internal/eino/milvus/splitter/markdown.go` 中，我们定义了一套基于优先级的切分策略。

**核心思路**：优先在“语义边界”进行切分。对于Markdown来说，标题（Header）、代码块（Code Block）、列表（List）是天然的语义边界。

```go
// SplitMarkdown 专门用于切割 Markdown 文档的方法
func (s *DocumentSplitterService) SplitMarkdown(ctx context.Context, markdownContent string) ([]*schema.Document, error) {
    // ... 前置校验 ...

    // Markdown 专用分隔符优先级配置
    markdownSeparators := []string{
        "\n\n\n",    // 1. 章节大分隔（多个空行）
        "\n## ",     // 2. 二级标题
        "\n### ",    // 3. 三级标题
        "\n```",     // 4. 代码块边界（防止代码被切断）
        "\n---",     // 5. 分割线
        "\n- ",      // 6. 列表项
        "\n\n",      // 7. 段落分隔
        "。",         // 8. 句子分隔（作为最后兜底）
    }

    markdownConfig := &recursive.Config{
        ChunkSize:   s.config.ChunkSize,   // 例如：500 token
        OverlapSize: s.config.OverlapSize, // 例如：50 token，保持上下文连贯
        Separators:  markdownSeparators,
        KeepType:    s.config.KeepType,
    }
    
    // 使用 Eino 提供的递归切分器基类
    markdownSplitter, err := recursive.NewSplitter(ctx, markdownConfig)
    // ... 执行切分 ...
}
```

> **架构师笔记**：
> 这里的 `markdownSeparators` 顺序至关重要。我们希望尽可能在高层级的语义边界切开。如果一段文本很长，没有标题，我们才退而求其次在段落间切开；如果段落还太长，最后才在句号处强行切开。特别是 `\n` + `code fence` 的处理，有效避免了代码示例失效的问题。

## 3.3 高级检索策略实现

将数据存入 Milvus 只是第一步，如何精准地把它们“捞”出来才是 RAG 的精髓。Eino 框架提供了强大的 `Retriever` 抽象，我们在此基础上进行了封装。

### 3.3.1 封装 Eino Retriever 组件

在 `backend/internal/eino/milvus/retrieval/retriever.go` 中，我们实现了 `RetrieverService`。这里的关键点在于配置的正确性，特别是向量类型的处理。

```go
// NewRetrieverService 创建新的检索器服务
func NewRetrieverService(ctx context.Context, config *milvus.RetrieverConfig) (*RetrieverService, error) {
    // ... 参数校验 ...

    retrieverConfig := &milvus.RetrieverConfig{
        Client:            config.Client,
        Collection:        config.Collection,
        VectorField:       "vector", // Milvus 中的向量字段名
        
        // 关键配置：指定向量转换器
        // 默认转换器可能使用 BinaryVector，而我们通常使用 FloatVector
        VectorConverter: FloatVectorConverter, 
        
        TopK:            config.TopK, // 召回数量，建议设为 10-20，留给 Rerank 筛选
        Embedding:       config.Embedding,
    }

    // 初始化 Eino 的标准 Milvus Retriever
    retriever, err := milvus.NewRetriever(ctx, retrieverConfig)
    if err != nil {
        return nil, fmt.Errorf("failed to create milvus retriever: %w", err)
    }

    return &RetrieverService{
        retriever: retriever,
        // ...
    }, nil
}
```

### 3.3.2 混合检索与元数据过滤

在实际面试场景中，用户可能会问：“请问 Java 中的 HashMap 原理是什么？”如果不加限制，系统可能会检索到 Go 语言的 Map 实现，造成混淆。

因此，我们在 `RetrieveWithOptions` 方法中支持了元数据过滤（Metadata Filtering）。我们在入库时会给文档打上 `language=java` 或 `category=specialized` 的标签。在检索时，通过构建 Milvus 的布尔表达式（Boolean Expression）来进行前置过滤。

```go
// 伪代码示例：构建过滤表达式
func buildFilter(opts *RetrieveOptions) string {
    var filters []string
    if opts.Language != "" {
        filters = append(filters, fmt.Sprintf("language == '%s'", opts.Language))
    }
    if opts.Category != "" {
        filters = append(filters, fmt.Sprintf("category == '%s'", opts.Category))
    }
    return strings.Join(filters, " && ")
}
```

这样，当 Agent 处于“Java 面试模式”时，所有的检索都会被自动限定在 Java 知识库范围内，极大地提升了回答的准确率。
