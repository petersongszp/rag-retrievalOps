# 8.4.1 SSE 流式多路复用：在单链接中推送多角色状态

## 概念描述

在AI智能面试平台中，为了提供流畅、实时的用户体验，前端需要能够即时接收到后端AI面试官的各种状态更新，例如：哪个面试官正在发言、面试官正在思考、面试进度更新、以及最终的面试结果等。传统的HTTP请求-响应模式难以满足这种实时性要求。

**Server-Sent Events (SSE)** 是一种基于HTTP协议的单向通信技术，允许服务器向客户端推送事件流。它相比WebSocket更轻量，不需要复杂的握手过程，且天然支持断线重连。

**流式多路复用（Stream Multiplexing）** 在SSE的语境下，指的是在单个SSE连接上，服务器可以发送不同类型的事件，每个事件携带不同的数据负载。通过这种方式，前端在一个连接上就能接收到所有必要的实时更新，而无需建立多个连接。

在多角色群组面试场景中，SSE流式多路复用尤为重要：

*   **实时角色状态更新**：前端可以实时显示当前是“主面试官”在提问，还是“技术面试官”在思考，或者“项目面试官”正在发言。
*   **统一通信通道**：所有与面试相关的实时事件（如新问题、答案评估、面试结束、心跳包等）都通过一个SSE连接推送，简化了前端的连接管理。
*   **降低服务器资源消耗**：相比为每个事件类型建立单独的连接，多路复用减少了连接数，降低了服务器的资源开销。

## 项目实现概览

本项目利用Hertz框架和Go语言的 `io.Pipe` 机制，结合前端的 `EventSource` 和自定义 `SSEStreamParser`，实现了SSE流式多路复用，以在单个链接中高效推送多角色状态。

1.  **后端 SSE 响应设置**：后端Hertz Handler负责设置HTTP响应头，使其符合SSE协议规范，并创建一个 `io.Pipe`，将 `PipeReader` 作为响应体流式返回给客户端。
2.  **异步面试引擎**：面试引擎在一个独立的Goroutine中运行，它负责驱动面试逻辑，并在关键时刻通过 `PipeWriter` 向前端推送结构化的SSE事件。
3.  **结构化消息体**：通过 `MessageSchema` 定义了包含角色、内容、动作类型、状态等信息的统一消息格式，确保多角色状态能够被清晰地编码和传输。
4.  **前端 SSE 消费**：前端使用 `EventSource` 建立与后端的SSE连接，并通过自定义的 `SSEStreamParser` 解析接收到的事件流，根据事件类型和负载更新UI，实现多角色状态的实时展示。

## 核心功能代码

### 1. 后端 SSE 响应设置与事件发送

后端负责建立SSE连接，并提供一系列函数用于发送不同类型的SSE事件，特别是 `SendStructuredMessage` 用于推送多角色状态。

**Go 语言代码片段 (`backend/internal/service/interview/engine/utils.go`)**:

```go
package core

import (
	"net/http"
)

// SetupSSEResponse 设置 SSE 响应头
func SetupSSEResponse(c interface {
	SetStatusCode(int)
	Header(string, string)
}) {
	c.SetStatusCode(http.StatusOK)
	c.Header("Content-Type", "text/event-stream; charset=utf-8")
	c.Header("Cache-Control", "no-cache")
	c.Header("Connection", "keep-alive")
	c.Header("Access-Control-Allow-Origin", "*") // 允许跨域
	c.Header("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
	c.Header("Access-Control-Allow-Headers", "Content-Type, Authorization, Cache-Control")
	c.Header("Transfer-Encoding", "chunked")
	c.Header("X-Accel-Buffering", "no") // 禁用Nginx缓冲
	c.Header("X-Content-Type-Options", "nosniff")
}
```
*   **说明**：`SetupSSEResponse` 函数设置了所有必要的HTTP头，将响应标记为 `text/event-stream`，并禁用缓存，确保客户端能够持续接收事件流。

**Go 语言代码片段 (`backend/internal/service/interview/engine/events.go`)**:

```go
package core

import (
	"encoding/json"
	"fmt"
	"io"
	"log"
	"net/http"
)

// SendSSEEvent 发送 SSE 事件
func SendSSEEvent(writer io.Writer, event map[string]interface{}) error {
	eventJSON, _ := json.Marshal(event)

	// 获取事件类型，默认为 "message"
	eventType := "message"
	if t, ok := event["type"]; ok {
		eventType = fmt.Sprintf("%v", t)
	}

	// 标准 SSE 格式：event: type\ndata: {...}\n\n
	message := fmt.Sprintf("event: %s\ndata: %s\n\n", eventType, string(eventJSON))
	n, err := fmt.Fprint(writer, message)
	if err != nil {
		log.Printf("[SSE] Failed to write event: %v (wrote %d bytes)", err, n)
		return err
	}

	// 立即 flush，确保数据发送到客户端
	if flusher, ok := writer.(http.Flusher); ok {
		flusher.Flush()
	}
	return nil
}

// SendStructuredMessage 发送结构化消息（支持 MessageSchema）
// 这是第8章要求的核心实现：8.4.1 SSE 流式多路复用
func SendStructuredMessage(writer io.Writer, schema *MessageSchema) error {
	// 将 MessageSchema 转换为 map，便于序列化为JSON
	eventData := map[string]interface{}{
		"type":        "structured_message", // 自定义事件类型
		"message_id":  schema.MessageID,
		"timestamp":   schema.Timestamp.Unix(),
		"role":        schema.Role,
		"role_name":   schema.RoleName,
		"role_avatar": schema.RoleAvatar,
		"content":     schema.Content,
		"action_type": schema.ActionType,
		"status":      schema.Status,
	}

	// 添加元数据（如果存在）
	if len(schema.Metadata) > 0 {
		eventData["metadata"] = schema.Metadata
	}

	return SendSSEEvent(writer, eventData)
}

// SendThinkingStatus 发送思考状态
func SendThinkingStatus(writer io.Writer, role RoleType) error {
	config := GetRoleConfig(role) // 获取角色配置，包含头像等信息

	eventData := map[string]interface{}{
		"type":        "thinking", // 自定义事件类型
		"role":        role,
		"role_name":   config.RoleName,
		"role_avatar": config.AvatarSeed,
		"action_type": ActionThinking,
	}

	return SendSSEEvent(writer, eventData)
}
```
*   **说明**：
    *   `SendSSEEvent` 是一个通用函数，用于将任何Go `map` 结构体转换为标准SSE格式并写入 `io.Writer`。它确保了事件类型 (`event: type`) 和数据 (`data: {...}`) 的正确格式，并立即 `Flush` 响应，实现实时推送。
    *   `SendStructuredMessage` 是实现多路复用的核心。它将后端定义的 `MessageSchema` 转换为一个包含所有角色状态信息的 `map`，并以 `structured_message` 类型通过 `SendSSEEvent` 推送。
    *   `SendThinkingStatus` 则是另一个特定事件类型的例子，用于推送某个角色的“思考中”状态，前端可以据此更新UI。

### 2. 前端 SSE 消费与解析

前端使用 `EventSource` 建立连接，并通过 `SSEStreamParser` 解析接收到的数据流，识别不同类型的事件，特别是 `structured_message` 来更新多角色状态。

**TypeScript 代码片段 (`frontend/src/types/message-schema.ts`)**:

```typescript
// SSE 事件类型
export interface SSEEvent {
    type: string;
    [key: string]: any; // 允许其他任意属性
}

// SSE 流解析器（支持多路复用）
export class SSEStreamParser {
    private buffer: string = '';

    // 解析流数据块
    parse(chunk: string): SSEEvent[] {
        this.buffer += chunk;
        const events: SSEEvent[] = [];

        // SSE 格式：事件之间用 \n\n 分隔
        const blocks = this.buffer.split('\n\n');

        // 最后一个可能是不完整的，保留在 buffer 中
        this.buffer = blocks.pop() || '';

        for (const block of blocks) {
            if (!block.trim()) continue;

            try {
                const event = this.parseBlock(block);
                if (event) {
                    events.push(event);
                }
            } catch (e) {
                console.error('Failed to parse SSE block:', block, e);
            }
        }

        return events;
    }

    // 解析单个事件块
    private parseBlock(block: string): SSEEvent | null {
        const lines = block.split('\n');
        let eventType = 'message'; // 默认事件类型
        let data = '';

        for (const line of lines) {
            if (line.startsWith('event:')) {
                eventType = line.substring(6).trim();
            } else if (line.startsWith('data:')) {
                data = line.substring(5).trim();
            }
        }

        if (!data) return null;

        try {
            const payload = JSON.parse(data);
            return { type: eventType, ...payload }; // 返回包含类型和负载的事件对象
        } catch (e) {
            console.error('Failed to parse JSON data:', data, e);
            return null;
        }
    }

    // 重置解析器
    reset() {
        this.buffer = '';
    }
}
```
*   **说明**：
    *   `SSEStreamParser` 负责处理从 `EventSource` 接收到的原始文本数据流。它会缓冲数据，并根据SSE协议的 `\n\n` 分隔符将数据块拆分成独立的事件。
    *   `parseBlock` 方法进一步解析每个事件块，提取 `event:` 类型和 `data:` 负载，并将 `data` 部分解析为JSON对象。

## 结论

通过SSE流式多路复用技术，本项目成功地在单个HTTP连接上实现了多角色状态的实时推送。后端通过结构化的 `MessageSchema` 和 `SendStructuredMessage` 函数，将丰富的角色状态信息编码为不同类型的SSE事件。前端则通过 `EventSource` 和自定义的 `SSEStreamParser` 高效地消费和解析这些事件，从而实现了：

*   **极佳的用户体验**：用户可以实时感知到面试官的动态，如同与真人面试官互动。
*   **高效的通信机制**：单个连接承载所有实时更新，减少了网络开销和服务器资源占用。
*   **灵活的UI渲染**：前端能够根据接收到的角色状态信息，动态调整界面展示，提升了交互的丰富性。

这种设计是构建高度互动、实时响应的AI智能面试平台不可或缺的关键技术。
