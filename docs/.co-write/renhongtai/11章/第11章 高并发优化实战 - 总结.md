# 第11章 高并发优化实战 — 总结

本章从 **Hertz 网关高并发配置** 与 **Eino Agent 资源调度优化** 两方面入手，在网关层、数据层、模型调用层与监控路径上落地可配置的调优手段，支撑面试系统在高并发与成本可控下的稳定运行。

---

## 11.1 Hertz 网关高并发配置

| 小节 | 要点 | 配置/代码位置 |
|------|------|----------------|
| **11.1.1** 连接池调优：KeepAlive 与 MaxIdleConns | Hertz 开启 KeepAlive、读/写/空闲超时从配置读取；数据库 `max_idle_conns` / `max_open_conns`；LLM 侧单例 Transport 的 MaxIdleConns、MaxIdleConnsPerHost、DisableKeepAlives: false | `config.yaml`：`hertz.keep_alive`、`database.max_idle_conns`；`main.go`、`database.go`、`internal/agents/llm/openAi.go` |
| **11.1.2** 协程模型优化：Netpoll 与 GOMAXPROCS | Hertz 基于 Netpoll 的 I/O 与协程模型；通过 `runtime.GOMAXPROCS` 在启动时按配置设置 P 数量，便于容器与多核环境调优 | `config.yaml`：`hertz.gomaxprocs`（0=不设置）；`main.go` 启动时调用 |
| **11.1.3** 限流策略升级：分布式限流 | 网关层按 IP 限流：内存版（token bucket）或 Redis 固定窗口；多实例部署时 `use_redis: true` 实现全局限流；超限返回 429 | `config.yaml`：`hertz.rate_limit`（rps、burst、use_redis、redis_key_prefix）；`internal/middleware/ratelimit.go`、`redis_ratelimit.go` |

## 11.2 Eino Agent 资源调度优化

| 小节 | 要点 | 配置/代码位置 |
|------|------|----------------|
| **11.2.1** Client 复用 | 按 (userId, modelName, baseURL) 缓存 `http.Client`，TTL 10 分钟，减少建连与 GC；新建时复用单例 Transport 与熔断器 | `internal/agents/llm/openAi.go`：getCachedClient、setCachedClient、CreatOpenAiChatModel |
| **11.2.2** 实例池设计：sync.Pool | 在 Eino 监控回调的 Token 格式化路径中，用 sync.Pool 复用 `bytes.Buffer`，降低热路径分配与 GC 压力 | `pkg/eino/callbacks/monitoring.go`：bufferPool、extractTokenUsage |
| **11.2.3** 推理成本控制：Token 监控与配额 | 按用户按日累计 Token（Redis）；开场前 CheckQuota，超配额拒绝；OnEnd 中自动 Record；0 表示不限制 | `config.yaml`：`eino.token_quota_per_user_per_day`；`main.go` 注入 DefaultTokenRecorder；`internal/agents/llm/tokenquota.go`；`graph_loop.go` 中 WithUserID、CheckQuota |

---

## 配置一览（config.yaml 相关片段）

```yaml
# Hertz（11.1）
hertz:
  keep_alive: true
  gomaxprocs: 0
  rate_limit:
    rps: 20
    burst: 50
    use_redis: false
    redis_key_prefix: "rl:"

database:
  max_idle_conns: 10
  max_open_conns: 100

# Eino 推理成本控制（11.2.3）
eino:
  token_quota_per_user_per_day: 0   # 大于 0 启用每用户每日 Token 配额
```

## 本章小结

- **11.1** 在网关与连接层：通过 KeepAlive、MaxIdleConns、GOMAXPROCS 和可选的 Redis 分布式限流，提升连接复用与并发可控性。
- **11.2** 在 Agent 与推理路径：通过 Client 复用、sync.Pool 和 Token 配额，降低资源浪费与推理成本风险。
