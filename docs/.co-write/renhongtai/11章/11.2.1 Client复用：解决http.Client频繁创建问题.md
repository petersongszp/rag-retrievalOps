# 11.2.1 Client 复用：解决 http.Client 频繁创建问题

## 概念描述

在 Eino Agent 调用外部 LLM API（如 OpenAI、豆包、DeepSeek）时，每次创建 ChatModel 若都新建一个 `http.Client`，会带来以下问题：

1. **连接无法复用**：每个 Client 拥有自己的 Transport 与连接池，请求结束后连接可能被关闭，下次请求再次建连，增加延迟与握手开销。
2. **资源浪费**：频繁创建和销毁 `http.Client` 与底层连接，增加 GC 压力与文件描述符占用，在高并发或多用户场景下易成为瓶颈。
3. **限流与熔断难以统一**：若每个请求一个 Client，针对同一模型/同一 BaseURL 的熔断器或限流状态难以在多次调用间共享。

通过**按 (userId, modelName, baseURL) 维度缓存 `http.Client`**，相同用户、同一模型、同一接口地址的多次调用复用同一个 Client，从而复用底层 Transport 的连接池与长连接；同时为缓存条目设置 TTL（如 10 分钟），在用户切换模型或配置变更后一段时间内自动失效，避免长期使用过期配置。这对应书中 11.2.1“Client 复用：解决 http.Client 频繁创建问题”的实践。

## 项目实现概览

本项目在以下方面实现了 11.2.1 的 Client 复用：

1. **缓存键与缓存结构**：以 `userId:modelName:baseURL` 字符串作为 cacheKey，使用全局 `map[string]*clientCacheEntry` 存储，每个条目包含 `*http.Client` 与创建时间 `createdAt`，便于 TTL 淘汰。
2. **获取与设置**：`getCachedClient(cacheKey)` 命中且未超 TTL 时直接返回已有 Client；未命中或已过期时，在 `CreatOpenAiChatModel` 中新建 `http.Client`（复用单例 `getBaseTransport()` 并包装熔断器），再调用 `setCachedClient` 写入缓存。
3. **TTL 与并发安全**：缓存 TTL 为 10 分钟；读写缓存时使用 `sync.RWMutex` 保护，过期条目在 get 时惰性删除，保证高并发下正确性与性能。

## 核心功能代码

### 1. 缓存条目与 TTL 常量

缓存条目携带 Client 与创建时间，用于 TTL 判断；TTL 常量控制同一配置下 Client 的最长复用时间。

**Go 语言代码片段 (`backend/internal/agents/llm/openAi.go`)**:

```go
// clientCacheEntry 11.2.1 Client 复用：缓存条目，带 TTL 避免配置变更后长期用旧 Client
type clientCacheEntry struct {
	client    *http.Client
	createdAt time.Time
}

const clientCacheTTL = 10 * time.Minute

var (
	clientCache   = make(map[string]*clientCacheEntry)
	clientCacheMu sync.RWMutex
)
```

*   **说明**：`clientCacheEntry` 保存复用的 `*http.Client` 与创建时间；`clientCacheTTL` 为 10 分钟，超过则视为过期。全局 `clientCache` 与 `clientCacheMu` 用于多协程下的安全访问，实现 11.2.1 的 Client 缓存与 TTL 策略。

### 2. 获取与设置缓存的 Client

通过 get/set 封装缓存的读取与写入，get 时若条目存在但已超过 TTL 则惰性删除并返回 nil，由调用方新建并 set。

**Go 语言代码片段 (`backend/internal/agents/llm/openAi.go`)**:

```go
func getCachedClient(cacheKey string) *http.Client {
	clientCacheMu.RLock()
	ent := clientCache[cacheKey]
	clientCacheMu.RUnlock()
	if ent == nil {
		return nil
	}
	if time.Since(ent.createdAt) > clientCacheTTL {
		clientCacheMu.Lock()
		delete(clientCache, cacheKey)
		clientCacheMu.Unlock()
		return nil
	}
	return ent.client
}

func setCachedClient(cacheKey string, client *http.Client) {
	clientCacheMu.Lock()
	defer clientCacheMu.Unlock()
	clientCache[cacheKey] = &clientCacheEntry{client: client, createdAt: time.Now()}
}
```

*   **说明**：`getCachedClient` 读锁下查找条目，若存在且未超 TTL 则返回其 client；若已超 TTL 则加写锁删除后返回 nil。`setCachedClient` 在写锁下写入新条目。二者配合实现 11.2.1 中“相同 (userId, model, baseURL) 复用同一 http.Client”的语义。

### 3. 创建 ChatModel 时的复用逻辑

在创建 OpenAI 兼容 ChatModel 时，先按 cacheKey 查找缓存 Client，未命中再新建并放入缓存，从而减少频繁创建。

**Go 语言代码片段 (`backend/internal/agents/llm/openAi.go`)**:

```go
	// 11.2.1 Client 复用：相同 (userId, model, baseURL) 复用同一 http.Client，减少频繁创建
	cacheKey := fmt.Sprintf("%d:%s:%s", userId, modelName, url)
	httpClient := getCachedClient(cacheKey)
	if httpClient == nil {
		cb := circuitbreaker.NewCircuitBreaker(fmt.Sprintf("openai-%s", modelName))
		httpClient = &http.Client{
			Timeout: 0, // No timeout, use context deadline
			Transport: &loggingTransport{
				Transport:      getBaseTransport(),
				CircuitBreaker: cb,
			},
		}
		setCachedClient(cacheKey, httpClient)
	}

	chatModel, err := openai.NewChatModel(ctx, &openai.ChatModelConfig{
		APIKey:     key,
		Model:      modelName,
		BaseURL:    url,
		HTTPClient: httpClient,
	})
```

*   **说明**：cacheKey 由 `userId`、`modelName`、`url` 拼成，保证同一用户、同一模型、同一 BaseURL 使用同一 Client。未命中时新建 `http.Client`，Transport 使用单例 `getBaseTransport()`（连接池与 KeepAlive 由 11.1.1 保证），并包装熔断器后写入缓存。后续同 key 的 ChatModel 创建将复用该 Client，实现 11.2.1 的 Client 复用，降低连接创建与 GC 开销。

## 结论

通过按 (userId, modelName, baseURL) 维度的 Client 缓存、10 分钟 TTL 的惰性过期以及 get/set 的并发安全封装，本项目在 LLM 调用侧实现了 http.Client 的复用，避免频繁创建带来的连接与资源浪费，与书中 11.2.1“Client 复用：解决 http.Client 频繁创建问题”的实践一致，为 Eino Agent 的高并发与稳定性提供了基础。
