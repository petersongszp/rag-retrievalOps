# 8.4.2 动态 UI：基于角色标识的实时渲染

## 概念描述

在多角色AI智能面试平台中，用户界面的动态性和实时反馈对于提升用户体验至关重要。**动态UI：基于角色标识的实时渲染** 指的是前端界面能够根据后端推送的不同AI面试官（主面试官、技术面试官、项目面试官）或候选人自身的角色标识，实时地调整和更新UI元素的展示，例如：

*   **头像与名称**：显示当前发言角色的专属头像和名称。
*   **消息样式**：根据角色类型应用不同的颜色、背景或布局样式，使对话内容更具区分度。
*   **状态指示**：实时显示面试官的“思考中”、“说话中”等状态，增强交互的真实感。
*   **操作权限**：根据当前角色或面试阶段，动态启用或禁用某些UI操作（例如，只有在特定阶段才能切换面试官）。

这种动态渲染机制使得用户能够清晰地识别当前对话的参与者，理解对话的上下文，并获得如同与真人团队面试般的沉浸式体验。

## 项目实现概览

本项目通过以下机制实现了基于角色标识的动态UI实时渲染：

1.  **统一消息结构体 (`Message Schema`)**：后端通过SSE推送的 `StructuredMessage` 包含了 `role`、`role_name`、`role_avatar`、`action_type`、`status` 等关键字段，为前端提供了丰富的角色标识信息。
2.  **角色配置映射 (`getRoleConfig`)**：前端定义了一个 `getRoleConfig` 函数，将抽象的 `RoleType` 映射到具体的UI展示属性（如颜色类名、头像种子字符串等）。
3.  **前端组件化渲染**：前端的对话组件在接收到新的 `StructuredMessage` 后，会根据消息中的 `role` 字段调用 `getRoleConfig` 获取对应的UI配置，并据此动态渲染消息的头像、名称和样式。
4.  **实时状态更新**：结合SSE推送的 `action_type` 和 `status` 字段，前端能够实时更新面试官的思考/说话状态，提供更细致的交互反馈。

## 核心功能代码

### 1. 角色类型定义与配置映射

`frontend/src/types/message-schema.ts` 文件定义了所有可能的 `RoleType`，以及一个 `RoleConfig` 接口来描述每个角色的UI展示属性。`getRoleConfig` 函数是核心，它根据 `RoleType` 返回对应的 `RoleConfig`。

**TypeScript 代码片段 (`frontend/src/types/message-schema.ts`)**:

```typescript
// 角色类型定义（与后端保持一致）
export type RoleType =
    | 'main_interviewer'
    | 'tech_interviewer'
    | 'project_interviewer'
    | 'candidate'
    | 'system';

// 动作类型
export type ActionType = 'thinking' | 'speaking' | 'waiting';

// 消息状态
export type MessageStatus = 'pending' | 'streaming' | 'complete' | 'error';

// 结构化消息体（Message Schema）
export interface StructuredMessage {
    message_id: string;
    timestamp: number;
    role: RoleType;
    role_name: string;
    role_avatar: string;
    content: string;
    action_type: ActionType;
    status: MessageStatus;
    metadata?: Record<string, any>;
}

// 角色配置接口
export interface RoleConfig {
    roleType: RoleType;
    roleName: string;
    avatarSeed: string; // 用于生成头像的种子
    colorClass: string; // 文本颜色类名
    borderClass: string; // 边框颜色类名
}

// 获取角色配置的函数
export const getRoleConfig = (roleType: RoleType): RoleConfig => {
    const configs: Record<RoleType, RoleConfig> = {
        main_interviewer: {
            roleType: 'main_interviewer',
            roleName: '主面试官',
            avatarSeed: 'interviewer-main-v2',
            colorClass: 'text-orange-500',
            borderClass: 'border-orange-200',
        },
        tech_interviewer: {
            roleType: 'tech_interviewer',
            roleName: '技术面试官',
            avatarSeed: 'interviewer-tech-v2',
            colorClass: 'text-blue-500',
            borderClass: 'border-blue-200',
        },
        project_interviewer: {
            roleType: 'project_interviewer',
            roleName: '项目面试官',
            avatarSeed: 'interviewer-project-v2',
            colorClass: 'text-emerald-500',
            borderClass: 'border-emerald-200',
        },
        candidate: {
            roleType: 'candidate',
            roleName: '候选人',
            avatarSeed: 'user-candidate-v2',
            colorClass: 'text-blue-600',
            borderClass: 'border-blue-100',
        },
        system: {
            roleType: 'system',
            roleName: '系统',
            avatarSeed: 'system-v2',
            colorClass: 'text-slate-400',
            borderClass: 'border-slate-200',
        },
    };

    return configs[roleType] || configs.system; // 默认返回系统角色配置
};
```
*   **说明**：`getRoleConfig` 函数是实现动态UI的关键。它提供了一个集中的地方来定义和管理不同角色的视觉表现。`avatarSeed` 可以用于生成独特的头像，`colorClass` 和 `borderClass` 则直接映射到CSS类，方便Tailwind CSS等框架进行样式控制。

### 2. 前端对话组件的实时渲染逻辑

在 `frontend/src/app/interview/multi/start/page.tsx` 中，当接收到SSE推送的 `structured_message` 事件时，前端会利用 `getRoleConfig` 来获取角色配置，并据此更新对话历史，最终渲染出带有角色特定样式的消息。

        eventSource.onmessage = (event) => {
            const events = parser.parse(event.data);

            for (const payload of events) {
                console.log('[SSE接收]', payload.type, payload);

                if (payload?.type === 'structured_message') {
                    const role: RoleType = payload.role || 'main_interviewer';
                    const roleConfig = getRoleConfig(role); // 根据角色类型获取配置
                    const content = payload.content || '';

                    setWaitingNextQuestion(false);
                    setQuestionIndex(idx);

                    if (payload.action_type === 'thinking') {

                        // 例如：显示某个面试官头像旁边的“思考中”动画
                        // 这里可以添加逻辑来更新一个表示“正在思考”的状态变量
                        // 例如：setThinkingRole(role);
                        continue;
                    }

                    setConversationHistory((prev) => {
                        const lastIdx = prev.length - 1;
                        // 如果上一条消息是同一个角色的流式消息，则进行合并

                            prev[lastIdx] &&
                            prev[lastIdx].type === 'question' &&
                            prev[lastIdx].role === role &&
                            payload.status === 'streaming'
                        ) {
                            // 合并流式内容
                            const updatedContent = prev[lastIdx].content + content;
                            return prev.map((item, i) =>
                                i === lastIdx ? { ...item, content: updatedContent } : item
                            );
                        } else {
                            // 添加新消息，使用 roleConfig 中的信息进行渲染
                            return [
                                ...prev,
                                {
                                    type: 'question', // 假设所有面试官消息都视为 question 类型
                                    role: role,
                                    roleName: roleConfig.roleName,
                                    roleAvatar: roleConfig.avatarSeed,
                                    content: content,
                                    timestamp: payload.timestamp * 1000, // 后端是秒，前端需要毫秒
                                    colorClass: roleConfig.colorClass,
                                    borderClass: roleConfig.borderClass,
                                },
                            ];
                        }
                    });
                } else if (payload?.type === 'thinking') {

                    // 例如：setThinkingRole(payload.role);
                }
                // ... 处理其他事件类型
            }

*   **说明**：
    *   在 `eventSource.onmessage` 回调中，当接收到 `structured_message` 类型的事件时，代码会提取 `payload.role`。
    *   `const roleConfig = getRoleConfig(role);` 这一行是关键，它根据角色类型获取了预定义的UI配置。
    *   在 `setConversationHistory` 内部，新的对话项 (`ConversationItem`) 会使用 `roleConfig.roleName`、`roleConfig.avatarSeed`、`roleConfig.colorClass`、`roleConfig.borderClass` 等属性来构建，确保每条消息都带有正确的角色视觉标识。
    *   对于 `action_type === 'thinking'` 的事件，前端可以专门处理，例如显示一个加载动画或“思考中”的文本，而不是将其作为正式对话内容。

## 结论

通过结合后端推送的结构化消息和前端基于角色标识的配置映射，本项目成功实现了动态UI的实时渲染。这种机制使得AI面试平台能够：

*   **增强用户沉浸感**：用户能够清晰地感知到不同AI面试官的存在和互动，提升了面试的真实感。
*   **提高信息可读性**：通过视觉上的区分，用户可以更容易地跟踪对话流程，理解不同角色的发言。
*   **优化用户体验**：实时状态反馈（如“思考中”）减少了用户的等待焦虑，使交互更加流畅自然。
*   **简化前端开发**：将角色UI配置集中管理，并通过函数映射，使得对话组件的渲染逻辑更加简洁和可维护。

这种动态UI渲染是构建现代化、高度互动AI应用不可或缺的一部分，它将抽象的AI Agent行为转化为用户可感知、可理解的视觉体验。
