# 8.2.1 主面试官（Host）：基于 Eino Graph 的状态机编排

## 概念描述

在多角色群组面试场景中，“主面试官（Host）”扮演着至关重要的协调和引导角色。它不仅仅是一个简单的提问者，更是整个面试流程的“大脑”和“指挥官”。其核心职责包括：

1.  **面试流程引导**：负责面试的开场、环节切换（如从自我介绍到技术提问，再到项目经验），确保面试按照预设的流程推进。
2.  **话语权调度**：在多个AI面试官（技术面试官、项目面试官）之间进行智能的话语权分配和移交，避免混乱，保证对话的流畅性和有效性。
3.  **上下文管理**：维护整个面试的对话历史和状态，确保所有参与的AI面试官都能共享最新的信息，进行有针对性的追问和评估。
4.  **决策与控制**：根据面试进展、候选人回答和预设规则，做出下一步的决策，例如是否深入追问、是否切换话题、是否结束面试等。

为了高效且灵活地实现这些复杂职责，本项目采用了 **Eino Graph 状态机编排** 的方式来构建主面试官的逻辑。Eino Graph 允许将复杂的面试流程抽象为一系列状态和状态之间的转换，每个状态可以由一个或多个AI Agent负责处理，从而实现高度模块化和可控的面试流程。

## 项目实现概览

本项目通过以下方式实现了基于 Eino Graph 的主面试官状态机编排：

1.  **主面试官Agent的创建**：主面试官本身被设计为一个Eino Agent，其Prompt指令定义了其核心职责和调度规则。
2.  **协作Agent作为工具**：技术面试官和项目面试官被封装成主面试官的“工具”，主面试官可以在需要时“调用”这些工具，从而将话语权移交给它们。
3.  **面试状态管理**：定义了统一的 `InterviewState` 结构体，作为Eino Graph编排的核心数据结构，承载整个面试过程中的所有关键信息和状态。
4.  **Graph工作流定义**：利用Eino的图编排能力，将面试流程抽象为一系列节点和边，每个节点代表一个面试环节或决策点，通过状态转换驱动面试的进行。

## 核心功能代码

### 1. 主面试官Agent的创建与工具集成

`NewInterviewHostAgent` 函数展示了如何创建主面试官Agent，并将其余的协作面试官（技术面试官、项目面试官）作为工具集成进去。这使得主面试官能够通过调用这些工具来调度其他面试官。

**Go 语言代码片段 (`backend/internal/agents/multiagent/orchestrator.go`)**:

```go
package multiagent

import (
	"context"
	"fmt"

	"github.com/cloudwego/eino/adk"
	"github.com/cloudwego/eino/compose"

	llm "interview-agents/internal/agents/llm"
	tool2 "interview-agents/internal/agents/tools"
	componenttool "interview-agents/internal/pkg/eino/component/tool"
)

// NewInterviewHostAgent 创建面试主控智能体 (主面试官)
// 负责统筹整个面试流程，调度副面试官 and 项目面试官
func NewInterviewHostAgent(ctx context.Context, userId uint, needResumeTool bool) (adk.Agent, error) {
	model, err := llm.CreatOpenAiChatModel(ctx, userId)
	if err != nil {
		return nil, err
	}

	// 1. 初始化协作 Agent
	coAgent, err := NewCoInterviewerAgent(ctx, userId) // 技术面试官
	if err != nil {
		return nil, fmt.Errorf("failed to create co-interviewer: %w", err)
	}

	projectAgent, err := NewProjectInterviewerAgent(ctx, userId) // 项目面试官
	if err != nil {
		return nil, fmt.Errorf("failed to create project-interviewer: %w", err)
	}

	// 2. 将协作 Agent 包装成工具 (AgentAsTool)
	coTool := adk.NewAgentTool(ctx, coAgent)
	projectTool := adk.NewAgentTool(ctx, projectAgent)

	// 3. 构建工具列表
	tools := []componenttool.BaseTool{
		coTool,
		projectTool,
	}

	// 如果需要，添加简历工具
	if needResumeTool {
		tools = append(tools, tool2.GetResumeInfoTool())
	}

	// 4. 创建主面试官 (Host)
	hostAgent, err := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{
		Name:        "MainInterviewer",
		Description: "主面试官，负责面试全流程的引导、节奏控制 and 最终评价。",
		Instruction: MainInterviewerInstruction, // 引用主面试官的Prompt指令
		Model:       model,
		ToolsConfig: adk.ToolsConfig{
			ToolsNodeConfig: compose.ToolsNodeConfig{
				Tools: tools,
			},
		},
		MaxIterations: 30, // 最大迭代次数，防止无限循环
	})

	if err != nil {
		return nil, fmt.Errorf("failed to create main interviewer agent: %w", err)
	}

	return hostAgent, nil
}
```
*   **说明**：此代码片段是主面试官Agent的实例化过程。它将 `CoInterviewerAgent` (技术面试官) 和 `ProjectInterviewerAgent` (项目面试官) 封装为 `adk.AgentTool`，并作为主面试官的可用工具。主面试官的 `Instruction` 字段引用了 `MainInterviewerInstruction`，这是其行为逻辑的核心定义。`MaxIterations` 参数用于防止Agent在复杂场景下陷入无限循环。

### 2. 面试状态（InterviewState）定义

`InterviewState` 结构体是Eino Graph状态机编排的核心数据结构，它承载了面试过程中所有需要共享和维护的状态信息，确保了Graph中各个节点能够访问到最新的面试上下文。

**Go 语言代码片段 (`backend/internal/service/interview/engine/graph_loop.go`)**:

```go
package core

import (
	"context"
	"fmt"
	"io"
	"log"
	"strings"
	"time"

	evaluator "interview-agents/internal/agents/evaluation"
	"interview-agents/internal/agents/evaluation/topic"
	"interview-agents/internal/agents/usecase/interview"
	"interview-agents/internal/model"
	interviewservice "interview-agents/internal/service/resume"

	"github.com/cloudwego/eino/compose"
)

// =============================================================================
// InterviewState - 面试状态（Graph 编排的核心数据结构）
// =============================================================================

// InterviewState 面试状态，在 Graph 各节点间传递
type InterviewState struct {
	// 基础信息
	Session        *InterviewSession
	SessionManager *SessionManager
	InterviewSvc   interviewservice.InterviewManager
	Writer         io.Writer

	// Agent 相关
	AgentSvc       *interview.InterviewAgentService
	AgentType      interview.InterviewAgentType
	NeedResumeTool bool

	// 评分相关
	Evaluator    *evaluator.Evaluator
	ScoreHistory *evaluator.ScoreHistory
	TopicTracker *topic.TopicTracker

	// 当前轮次数据
	QuestionIndex int
	QuestionText  string
	Answer        string
	EvalResult    *evaluator.EvaluationResult

	// 分支节点设置的下一题提示（由 deepen/continue/lower/switch 节点设置）
	NextActionHint string // 下一题的 Prompt 提示

	// 历史记录
	AllDialogues  []*InterviewDialogueData
	RecentHistory []historyItem

	// 配置
	MaxQuestions       int
	HistoryContextSize int
	AnswerTimeout      time.Duration
	HeartbeatInterval  time.Duration

	// 控制标志
	ShouldStop bool
	Error      error
}
```
*   **说明**：`InterviewState` 包含了面试会话ID、用户ID、当前问题、用户回答、评估结果、对话历史、配置参数以及控制标志等。这个结构体在Eino Graph的各个节点之间传递，确保了每个Agent在执行其任务时都能获取到完整的面试上下文，从而实现状态机编排的连贯性和准确性。

### 3. Eino Graph 工作流示例

`docs/后端架构设计.md` 中提供了一个抽象的Eino工作流示例，虽然不是主面试官Agent本身的实现，但它展示了Eino Graph如何将面试流程抽象为可编排的节点，主面试官的逻辑将是这个工作流的驱动者。

**Go 语言代码片段 (`docs/后端架构设计.md`)**:

```go
// 创建面试工作流
func CreateInterviewWorkflow() *eino.Workflow {
    workflow := eino.NewWorkflow("interview_process")
    
    // 添加节点
    resumeNode := workflow.AddNode("analyze_resume", resumeAnalyzer)
    questionNode := workflow.AddNode("generate_question", questionGenerator)
    evaluateNode := workflow.AddNode("evaluate_answer", answerEvaluator)
    reportNode := workflow.AddNode("generate_report", reportGenerator)
    
    // 定义流程
    workflow.Connect(resumeNode, questionNode)
    workflow.Loop(questionNode, evaluateNode, 5) // 循环5轮问答
    workflow.Connect(evaluateNode, reportNode)
    
    return workflow
}
```
*   **说明**：这个示例展示了Eino Graph如何通过 `AddNode` 定义工作流中的各个AI组件（如简历分析、问题生成、答案评估、报告生成），并通过 `Connect` 和 `Loop` 定义它们之间的执行顺序和逻辑。主面试官Agent的职责就是驱动这个工作流，根据面试的实际情况，在这些节点之间进行调度和决策。

## 结论

通过将主面试官设计为基于 Eino Graph 状态机编排的Agent，本项目能够有效地管理复杂的群组面试流程。Eino Graph 提供了强大的编排能力，使得主面试官能够智能地引导面试、调度其他协作Agent，并维护整个面试的上下文状态。这种设计不仅提高了面试的真实性和流畅性，也为未来功能的扩展和维护提供了坚实的基础。
