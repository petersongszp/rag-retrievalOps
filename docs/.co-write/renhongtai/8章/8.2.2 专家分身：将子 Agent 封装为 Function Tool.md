# 8.2.2 专家分身：将子 Agent 封装为 Function Tool

## 概念描述

在多角色AI智能体系统中，为了实现更精细化的职责分工和更灵活的协作模式，一种高效的策略是将特定的AI智能体（子Agent）封装成可供其他Agent调用的“Function Tool”（函数工具）。这种模式可以形象地理解为“专家分身”：每个子Agent都是某个领域的专家，当主Agent遇到需要该领域专业知识的问题时，它不再自己尝试解决，而是将问题“委托”给对应的专家分身工具。

**核心思想：**

*   **职责分离**：每个子Agent专注于其特定领域（例如技术面试官专注于技术问题，项目面试官专注于项目经验），降低了单个Agent的复杂性。
*   **能力扩展**：主Agent通过调用不同的Function Tool，可以动态地扩展其能力边界，无需在自身Prompt中包含所有领域的知识。
*   **模块化与可复用**：子Agent可以独立开发、测试和优化，并作为可复用的组件集成到不同的主Agent或工作流中。
*   **话语权动态转移**：当主Agent调用子Agent作为工具时，实际上是将当前对话的焦点和话语权暂时转移给了子Agent，由子Agent来处理特定领域的交互。

## 项目实现概览

本项目充分利用了Eino框架提供的Agent作为工具（AgentAsTool）的能力，将技术面试官和项目面试官这两个子Agent封装成Function Tool，供主面试官Agent调用。

具体实现步骤如下：

1.  **独立子Agent的创建**：首先，独立创建技术面试官Agent (`CoInterviewerAgent`) 和项目面试官Agent (`ProjectInterviewerAgent`)，它们各自拥有针对特定领域的Prompt指令和潜在的工具集（例如技术面试官可能拥有代码分析工具，项目面试官可能拥有项目管理知识库）。
2.  **子Agent封装为工具**：使用Eino框架提供的 `adk.NewAgentTool()` 方法，将这些独立的子Agent包装成可供其他Agent调用的Function Tool。
3.  **主Agent集成工具**：主面试官Agent在初始化时，将这些封装好的子Agent工具添加到自己的工具列表中。
4.  **主Agent调用工具**：在面试过程中，当主面试官Agent的LLM模型判断需要技术面试官或项目面试官介入时，它会通过Function Calling机制，调用对应的子Agent工具，从而实现话语权的动态转移和专业领域的深度追问。

## 核心功能代码

### 1. 主面试官Agent集成子Agent作为工具

`NewInterviewHostAgent` 函数清晰地展示了如何创建主面试官Agent，并将其余的协作面试官（技术面试官、项目面试官）作为工具集成进去。

**Go 语言代码片段 (`backend/internal/agents/multiagent/orchestrator.go`)**:

```go
package multiagent

import (
	"context"
	"fmt"

	"github.com/cloudwego/eino/adk"
	"github.com/cloudwego/eino/compose"

	llm "interview-agents/internal/agents/llm"
	tool2 "interview-agents/internal/agents/tools"
	componenttool "interview-agents/internal/pkg/eino/component/tool"
)

// NewInterviewHostAgent 创建面试主控智能体 (主面试官)
// 负责统筹整个面试流程，调度副面试官 and 项目面试官
func NewInterviewHostAgent(ctx context.Context, userId uint, needResumeTool bool) (adk.Agent, error) {
	model, err := llm.CreatOpenAiChatModel(ctx, userId)
	if err != nil {
		return nil, err
	}

	// 1. 初始化协作 Agent (技术面试官和项目面试官)
	coAgent, err := NewCoInterviewerAgent(ctx, userId) // 技术面试官
	if err != nil {
		return nil, fmt.Errorf("failed to create co-interviewer: %w", err)
	}

	projectAgent, err := NewProjectInterviewerAgent(ctx, userId) // 项目面试官
	if err != nil {
		return nil, fmt.Errorf("failed to create project-interviewer: %w", err)
	}

	// 2. 将协作 Agent 包装成工具 (AgentAsTool)
	coTool := adk.NewAgentTool(ctx, coAgent)
	projectTool := adk.NewAgentTool(ctx, projectAgent)

	// 3. 构建主面试官的工具列表，包含子Agent工具
	tools := []componenttool.BaseTool{
		coTool,      // 技术面试官作为工具
		projectTool, // 项目面试官作为工具
	}

	// 如果需要，添加简历工具
	if needResumeTool {
		tools = append(tools, tool2.GetResumeInfoTool())
	}

	// 4. 创建主面试官 (Host) Agent，并集成这些工具
	hostAgent, err := adk.NewChatModelAgent(ctx, &adk.ChatModelAgentConfig{
		Name:        "MainInterviewer",
		Description: "主面试官，负责面试全流程的引导、节奏控制 and 最终评价。",
		Instruction: MainInterviewerInstruction, // 引用主面试官的Prompt指令
		Model:       model,
		ToolsConfig: adk.ToolsConfig{
			ToolsNodeConfig: compose.ToolsNodeConfig{
				Tools: tools, // 将子Agent工具添加到主面试官的工具列表中
			},
		},
		MaxIterations: 30,
	})

	if err != nil {
		return nil, fmt.Errorf("failed to create main interviewer agent: %w", err)
	}

	return hostAgent, nil
}
```
*   **说明**：
    *   `NewCoInterviewerAgent` 和 `NewProjectInterviewerAgent` 分别创建了技术面试官和项目面试官的Agent实例。
    *   `adk.NewAgentTool(ctx, coAgent)` 和 `adk.NewAgentTool(ctx, projectAgent)` 是将这些Agent实例转换为Function Tool的关键步骤。这意味着主面试官的LLM模型在生成回复时，可以像调用普通函数一样，选择调用这些“专家分身”来处理特定问题。
    *   通过这种方式，主面试官的Prompt可以专注于流程控制和整体协调，而具体的专业领域问题则由对应的子Agent工具来处理，实现了高效的职责分离和协作。

## 结论

将子Agent封装为Function Tool是构建复杂多智能体系统的一种强大模式。它使得主面试官Agent能够像拥有多个“专家分身”一样，在需要时动态地调用不同领域的专业知识和能力。这种设计不仅提高了系统的模块化程度和可扩展性，也使得AI面试平台能够更灵活、更智能地模拟真实世界中多面试官协同工作的场景，为候选人提供更全面、更深入的面试体验。
