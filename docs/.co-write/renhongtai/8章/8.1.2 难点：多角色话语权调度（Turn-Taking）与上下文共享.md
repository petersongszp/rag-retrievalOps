# 8.1.2 难点：多角色话语权调度（Turn-Taking）与上下文共享

## 难点描述

在模拟“主面+技术面+项目面”的群组面试环境中，实现多角色AI面试官之间的流畅互动和高效协作面临两大核心难点：

1.  **话语权调度（Turn-Taking）**：如何智能地决定当前由哪个面试官进行提问或追问，避免多个面试官同时发言、重复提问或出现对话中断、不连贯的情况。这要求系统能够理解对话的当前焦点、各面试官的职责范围，并根据预设规则或动态判断进行话语权的平滑转移。
2.  **上下文共享**：各面试官（AI Agent）需要共享完整的面试历史、候选人简历信息以及之前的问答上下文，才能进行有深度、有针对性的追问。如果上下文信息不完整或传递不及时，将导致AI面试官“失忆”，无法形成连贯的对话，影响面试的真实性和评估效果。

## 项目实现概览

本项目通过以下策略和技术手段，有效解决了多角色话语权调度和上下文共享的难点：

1.  **Prompt Engineering 引导话语权**：通过精心设计的Prompt指令，为主面试官Agent设定明确的职责和调度规则，使其能够引导面试流程，并在适当的时机将话语权“移交”给其他面试官。
2.  **统一消息结构体实现上下文共享**：定义了结构化的消息体（`MessageSchema`），确保所有对话消息都包含角色、内容、时间戳等关键信息，并在整个面试会话中进行传递和维护，供所有Agent访问。
3.  **前端交互辅助调度**：前端提供了用户主动切换面试官的功能，作为一种辅助手段，允许用户在需要时主动引导对话方向，弥补AI调度可能存在的不足。

## 核心功能代码

### 1. 主面试官的Prompt指令与调度规则

主面试官的Prompt指令是实现话语权调度的核心。它明确了主面试官的职责，并包含了“强制调度规则”和“身份传承”机制，确保各面试官在对话中的发言顺序和内容连贯性。

**后端 Go 语言定义 (`backend/internal/agents/multiagent/constants.go`)**:

```go
package multiagent

// MainInterviewerInstruction 主面试官智能体的提示词
const MainInterviewerInstruction = `你是一位资深的技术经理（主面试官）。你正在主持一场"主面试官 + 技术面试官 + 项目面试官"的三人群组面试。

【核心职责】
1. 【表明身份】：除了直接输出技术面试官或项目面试官的回应外，你发表的所有言论必须在最开头包含"我是主面试官："字样。
2. 【身份传承】：当你通过工具调用获取到技术面试官或项目面试官的反馈时，你必须【原封不动】地直接输出他们的内容（他们已包含"我是技术面试官："或"我是项目面试官："前缀）。不要在此基础上再添加"我是主面试官："前缀。
3. 【禁止总结】：不要对技术面试官或项目面试官的话进行总结或再次包装，直接输出他们的原始回应。
4. 【引导流程】：负责面试的开场、自我介绍引导、以及在各环节间进行自然切换。

【强制调度规则 - 非常重要！】
`
```
*   **说明**：上述Prompt中的“强制调度规则”和“身份传承”是实现话语权调度的关键。主面试官作为协调者，负责在不同面试官之间进行切换，并确保对话的流畅性。当其他面试官（如技术面试官）通过工具输出内容时，主面试官会“传承”其身份并直接输出，避免了重复包装和不必要的干预。

### 2. 统一消息结构体实现上下文共享

为了确保所有Agent都能访问和理解完整的对话历史，项目定义了一个统一的`MessageSchema`结构体，用于封装所有对话消息。

**后端 Go 语言定义 (`backend/internal/service/interview/engine/message_schema.go`)**:

```go
package core

import "time"

// MessageSchema 结构化的多角色对话消息体
type MessageSchema struct {
	// 基础字段
	MessageID string    `json:"message_id"` // 消息唯一ID
	Timestamp time.Time `json:"timestamp"`  // 时间戳

	// 角色信息
	Role       RoleType `json:"role"`        // 角色类型
	RoleName   string   `json:"role_name"`   // 角色显示名称（如"主面试官"）
	RoleAvatar string   `json:"role_avatar"` // 角色头像标识

	// 内容信息
	Content    string     `json:"content"`     // 消息内容
	ActionType ActionType `json:"action_type"` // 动作类型（思考/说话）

	// 状态信息
	Status MessageStatus `json:"status"` // 消息状态

	// 元数据
	Metadata map[string]interface{} `json:"metadata,omitempty"` // 扩展元数据
}

// RoleType 角色类型
type RoleType string

const (
	RoleMainInterviewer    RoleType = "main_interviewer"    // 主面试官
	RoleTechInterviewer    RoleType = "tech_interviewer"    // 技术面试官
	RoleProjectInterviewer RoleType = "project_interviewer" // 项目面试官
	RoleCandidate          RoleType = "candidate"           // 候选人
	RoleSystem             RoleType = "system"              // 系统消息
)
```
*   **说明**：`MessageSchema` 结构体包含了 `Role`、`RoleName`、`Content` 等字段，使得每条消息都携带了完整的上下文信息。面试引擎在处理对话时，会将这些结构化的消息作为历史记录传递给各个Agent，确保它们能够基于完整的对话上下文进行决策和生成回复。前端也使用类似的 `StructuredMessage` (`frontend/src/types/message-schema.ts`) 来展示和管理对话历史。

### 3. 前端用户主动切换面试官

前端提供了一个“快捷切换面试官”的功能，允许用户在对话过程中主动选择与哪个面试官进行交流，这在一定程度上弥补了AI自动调度可能存在的不足，增强了用户体验。

**前端 TypeScript 代码片段 (`frontend/src/app/interview/multi/start/page.tsx`)**:

```typescript
    // 快捷切换面试官
    const switchInterviewer = async (interviewerType: 'tech' | 'project' | 'main') => {
        if (!sessionId || !answer.trim() || submitting) return;

        const interviewerMap = {
            tech: '技术面试官',
            project: '项目面试官',
            main: '主面试官'
        };

        const switchRequest = `我想和${interviewerMap[interviewerType]}聊聊这个问题：${answer}`;

        setSubmitting(true);
        const currentAnswer = switchRequest;
        setConversationHistory((prev) => [
            ...prev,
            { type: 'answer', content: currentAnswer, timestamp: Date.now() },
        ]);
        setAnswer('');
        setWaitingNextQuestion(true);

        try {
            const token = localStorage.getItem('token');
            const res = await fetch(`${INTERVIEW_API.SUBMIT_ANSWER}`, {
                method: 'POST',
                headers: {
                    'Content-Type': 'application/json',
                    Authorization: `Bearer ${token}`,
                },
                body: JSON.stringify({ session_id: sessionId, answer: currentAnswer }),
            });

            if (!res.ok) throw new Error('提交失败');
        } catch (error) {
            message.error('切换面试官失败');
            setWaitingNextQuestion(false);
        } finally {
            setSubmitting(false);
        }
    };
```
*   **说明**：当用户点击切换面试官按钮时，前端会构造一个特殊的请求，明确指出用户希望与哪个面试官对话，并将此请求发送给后端。后端Agent会根据这个请求调整话语权，从而实现用户驱动的调度。
