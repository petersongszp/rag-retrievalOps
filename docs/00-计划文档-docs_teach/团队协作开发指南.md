## 开发流程

### 🚀 完整流程图

```
1. 认领任务
   ↓
2. 阅读教程文档
   ↓
3. 创建功能分支
   ↓
4. 本地开发 & 测试
   ↓
5. 提交 Pull Request
   ↓
6. 代码评审
   ├─ ✅ 通过 → 合并到 main
   └─ ❌ 有意见 → 修改 → 重新提交
```

### 1️⃣ 认领任务

**步骤**:
1. 查看 [迭代优化-教学版.md](./迭代优化-教学版.md)
2. 选择感兴趣的任务（建议按顺序：TASK-001 → TASK-004）
3. 在群里/任务看板上认领
4. 确认没有其他人在做同一个任务

**建议**:
- 新手从 TASK-001（Semantic Cache）开始
- 可以 1-2 人组队做一个任务
- 有困难及时问，不要卡住！

### 2️⃣ 阅读教程

每个任务都有详细的教程文档：
- TASK-001: [Semantic Cache](./TASK-001-semantic-cache.md)
- TASK-002: [Cross-Encoder](./TASK-002-cross-encoder-rerank.md)
- TASK-003: [OpenTelemetry](./TASK-003-opentelemetry-tracing.md)
- TASK-004: [RRF Fusion](./TASK-004-rrf-fusion.md)

**教程包含**:
- ✅ 需求说明
- ✅ 技术原理
- ✅ 完整代码示例
- ✅ 验证步骤
- ✅ 提交指南

### 3️⃣ 创建分支

```bash
# 确保在 main 分支
git checkout main

# 拉取最新代码
git pull origin main

# 创建功能分支（命名规范：feature/TASK-XXX-简短描述）
git checkout -b feature/TASK-001-semantic-cache
```

### 4️⃣ 本地开发

**按照教程实现功能**，记得：
- 写单元测试！
- 本地手动测试！
- 确保现有测试都通过！

```bash
# 运行测试
cd backend
go test ./... -v

# 运行 linter
golangci-lint run
```

### 5️⃣ 提交 PR

```bash
# 查看修改
git status
git diff

# 添加文件
git add <修改的文件>

# 提交（Commit 规范见下文）
git commit -m "feat: TASK-001 实现语义缓存

- 实现基于余弦相似度的语义缓存
- 集成 Redis 存储
- 添加 Prometheus 监控"

# 推送到远程
git push origin feature/TASK-001-semantic-cache
```

然后在 GitHub/GitLab 网页上创建 Pull Request。

**PR 模板**（必须填）:
```markdown
## 任务说明
- 任务 ID：TASK-001
- 功能：语义缓存
- 实现人：[你的名字]

## 实现方案
[简单说明你的实现]

## 验证结果
- [x] 单元测试通过
- [x] 本地手动测试通过
- [x] 评估指标：[如果有数据]

## 相关文档
- 教程：./docs/TASK-001-semantic-cache.md

## 截图（可选）
[截图]
```

### 6️⃣ 代码评审

**导师评审后会有两种情况**:

#### ✅ 批准（Approved）
- 导师会合并到 main 分支
- 你的任务完成！🎉
- 可以开始下一个任务

#### 💬 有修改意见（Changes Requested）
- 仔细阅读评审意见
- 修改代码
- 重新提交 commit
- 在 PR 评论里说"已修改，请再看一下"
- 等待再次评审

**注意**:
- 不要直接 push 到 main 分支！
- 不要在没有评审的情况下合并！

## 代码规范

### 📝 Commit 信息规范

格式：`<type>(<scope>): <subject>`

**Type 类型**:
- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档修改
- `style`: 代码格式（不影响功能）
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具相关

**例子**:
```
feat: TASK-001 实现语义缓存
fix: 修复 Redis 连接泄漏问题
docs: 更新 README
test: 添加 RRF 融合单元测试
```

### 🎨 Go 代码规范

1. **遵循 Go 官方规范**
   - 使用 `gofmt` 格式化
   - 使用 `golint`/`golangci-lint` 检查

2. **命名规范**
   - 包名：小写，简短
   - 导出函数：首字母大写
   - 接口名：通常以 -er 结尾

3. **注释规范**
   - 每个导出函数都要有注释
   - 注释以函数名开头
   ```go
   // NewSemanticCache 创建语义缓存
   func NewSemanticCache(...) *SemanticCache { ... }
   ```

4. **错误处理**
   - 不要忽略错误！
   - 如果忽略，必须注释说明原因
   ```go
   // 忽略这个错误，因为...
   _ = someFunc()
   ```

### ✅ 测试规范

- 每个新功能都要有单元测试
- 测试文件命名：`*_test.go`
- 测试函数命名：`TestXxx(t *testing.T)`
- 测试覆盖率：尽量 > 70%

## Git 工作流

### 🌿 分支策略

我们使用 **Git Flow** 简化版：

```
main (主分支，稳定)
  ↑
  └─ feature/* (功能分支，从 main 分出，合并回 main)
```

### 📖 常用 Git 命令

```bash
# 创建新分支
git checkout -b feature/TASK-001

# 查看状态
git status

# 查看修改
git diff

# 添加文件
git add .

# 提交
git commit -m "feat: ..."

# 推送到远程
git push origin feature/TASK-001

# 拉取最新 main
git checkout main
git pull origin main

# 合并 main 到你的分支（如果有冲突）
git checkout feature/TASK-001
git merge main
# 解决冲突后
git add .
git commit -m "merge main"

# 删除已经合并的分支
git branch -d feature/TASK-001
```

## 代码评审

### 👀 评审标准

导师评审时会检查：

| 检查项 | 说明 |
|--------|------|
| 功能正确性 | 功能是否符合需求 |
| 代码质量 | 代码是否清晰、易读 |
| 测试覆盖 | 是否有单元测试 |
| 不破坏现有功能 | 现有测试是否都通过 |
| 文档注释 | 是否有必要的注释 |

### 💬 评审意见示例

**正面反馈**:
```
👍 很棒！代码很清晰，测试也很完整！
```

**改进建议**:
```
💡 建议：这里可以抽一个函数出来，提高可读性
```

**需要修改**:
```
❌ 这里有个 bug，需要修复一下
```

### 🤝 如何回应评审

1. **认真阅读每一条意见**
2. **有疑问及时问**，不要不好意思
3. **修改后回复说明**：
   ```
   已修改！
   - 修复了 xxx 问题
   - 添加了 xxx 测试
   ```

## 常见问题

### Q1: 我遇到 bug 了，怎么办？

**A**:
1. 先自己调试（打 log、用 debugger）
2. 看错误信息，Google/Stack Overflow
3. 还是不行？问导师！

### Q2: 我可以参考其他项目的代码吗？

**A**: 可以！但要：
- 理解原理，不要直接 copy
- 注明来源
- 遵守原项目的开源协议

### Q3: 任务太难了，我做不完怎么办？

**A**:
- 很正常！
- 及时和导师沟通
- 可以先做一部分，或者降低难度
- 重要的是学习过程，不是完成度

### Q4: 我可以做教程里没有的功能吗？

**A**: 当然！欢迎创新！
- 先和导师讨论
- 确认方向
- 做完可以补充教程

### Q5: 团队协作有什么沟通工具？

**A**:
- 群聊：日常沟通
- 任务看板：任务管理
- PR 评论：代码讨论

## 🎯 学习建议

### 1. 先理解，再写代码

不要上来就复制粘贴！
- 先看教程理解原理
- 自己尝试写
- 写不出来再看示例

### 2. 多问问题

- 不要害怕问"傻问题"
- 最好的问题是："我理解的是 xxx，对吗？"

### 3. 复盘总结

完成一个任务后：
- 总结学到了什么
- 记录踩过的坑
- 分享给团队

### 4. 帮助别人

- 学会了就去教别人
- 教是最好的学！
