# 08-成本运营使用说明

本文说明 Admin 前端里的 **成本运营** 菜单。当前源码里包含两个页面：

- **成本看板**：查看问答/检索相关成本、趋势和高成本请求。
- **Vector DB**：查看向量库 Collection、健康状态和最近操作记录。

> 依据源码：`cost-ops-cost-page.tsx`、`vector-db-page.tsx`、`types/kb.ts`、`config/api.ts`。

---

## 一、成本看板

### 1. 页面用途

成本看板用于看一段时间内系统大概花了多少钱，并找出哪些请求比较贵。

页面标题为 **成本看板**，说明文字为：

> 查看请求级成本归因、时间趋势和高成本查询。

当前页面会根据顶部选中的知识库显示数据：

- 如果选了某个知识库：只看该知识库的数据。
- 如果没有选知识库：显示“全部知识库”。

### 2. 适合谁用

适合这些人使用：

- 运营人员：想知道最近成本有没有升高。
- 管理员：想找出特别贵的请求。
- 技术同学：想排查某些策略、模型或上下文过长导致的成本问题。

### 3. 进入路径

左侧菜单：

**成本运营 → 成本看板**

页面地址：

`/cost-ops/cost`

### 4. 页面区域

成本看板目前分为 4 个区域：

1. 顶部标题和说明
2. 时间范围与刷新按钮
3. 成本统计卡片
4. 成本趋势和高成本 Query 表格

---

## 二、成本看板：字段和参数含义

### 1. 当前知识库

顶部说明里会显示：

`当前知识库：xxx`

含义：

- `xxx` 是当前选中的知识库名称。
- 如果没有选中知识库，会显示 `全部知识库`。
- 源码中请求接口时，如果有选中的知识库，会附带 `kb_id` 参数。

### 2. 时间范围

页面右上角有时间范围切换按钮：

| 选项 | 含义 |
|---|---|
| `1h` | 最近 1 小时 |
| `24h` | 最近 24 小时，页面默认值 |
| `7d` | 最近 7 天 |

切换时间范围后，页面会自动重新加载数据。

### 3. 统计卡片

页面有 4 张统计卡片：

| 卡片名 | 字段来源 | 小白解释 |
|---|---|---|
| 总成本 | `total_estimated_cost` | 当前时间范围内的预估总花费 |
| 每千次问答成本 | `cost_per_1k_queries` | 平均每 1000 次问答大概要花多少钱 |
| 平均上下文 Tokens | `avg_context_tokens` | 每次请求平均带给模型的上下文长度，越大通常越贵 |
| 高成本 Query | `high_cost_query_count` | 被系统识别为高成本的请求数量 |

补充说明：

- 金额类数字当前显示 4 位小数。
- 如果接口没有返回值，页面会显示 `0`。
- `currency` 字段在类型里存在，但当前页面没有单独展示币种。

### 4. 成本趋势

区域标题：**成本趋势**

页面会按时间桶展示成本数据：

| 字段 | 含义 |
|---|---|
| `bucket` | 时间点/时间桶，页面会转成本地时间显示 |
| `total_estimated_cost` | 该时间桶内的预估总成本 |

如果当前时间窗没有数据，会显示：

`当前时间窗内没有成本数据`

源码类型里还定义了这些趋势字段，但当前页面没有展示出来：

| 字段 | 含义 |
|---|---|
| `cost_per_1k_queries` | 每千次问答成本 |
| `embedding_cost` | 向量化成本 |
| `llm_cost` | 大模型调用成本 |
| `rerank_cost` | 重排成本 |
| `vector_storage_cost` | 向量存储成本 |
| `index_rebuild_cost` | 索引重建成本 |
| `avg_context_tokens` | 平均上下文 Tokens |
| `avg_candidate_count` | 平均候选数量 |

> 注意：这些字段在类型中存在，但 `cost-ops-cost-page.tsx` 当前只把 `bucket` 和 `total_estimated_cost` 展示到页面上。

### 5. 高成本 Query Top 10

区域标题：**高成本 Query Top 10**

当前固定请求第 1 页、每页 10 条，所以页面展示 Top 10。

表格字段：

| 列名 | 字段 | 含义 |
|---|---|---|
| Request ID | `request_id` | 请求编号，用来定位一次具体请求 |
| 策略版本 | `strategy_version` | 这次请求使用的策略版本；没有则显示 `-` |
| 模型 | `model_name` | 使用的模型名称；没有则显示 `-` |
| 成本 | `estimated_cost` | 这次请求的预估成本，显示 4 位小数 |
| 上下文 Tokens | `context_tokens` | 这次请求传入模型的上下文 Token 数 |

类型里还定义了这些高成本请求字段，但当前表格没有展示：

| 字段 | 含义 |
|---|---|
| `kb_id` | 知识库 ID |
| `query_type` | 问题类型 |
| `experiment_id` | 实验 ID |
| `currency` | 币种 |
| `candidate_count` | 候选数量 |
| `final_count` | 最终返回数量 |
| `created_at` | 创建时间 |
| `contract_gaps` | 前后端契约差异提示 |

### 6. 策略维度说明

源码里有和成本维度相关的接口与类型：

- `COST_BY_KB`
- `COST_BY_STRATEGY`
- `COST_BY_MODEL`
- `CostDimensionBreakdown`

但是当前 **成本看板页面没有展示按知识库、按策略、按模型聚合的维度表或图表**。

当前页面能看到的策略相关信息只有：

- 高成本 Query 表格里的 `策略版本 strategy_version`。

所以，如果你想按策略对比成本，目前这个前端页面只能先看单条高成本请求属于哪个策略版本，不能直接看“策略 A 总成本多少、策略 B 总成本多少”的汇总。

## 三、成本看板：按钮和操作

### 1. 时间范围切换

操作：点击 `1h`、`24h`、`7d`。

效果：

- 自动重新请求成本汇总、成本趋势、高成本 Query。
- 当前选中的知识库也会一起作为筛选条件传给后端。

### 2. 刷新

按钮：**刷新**

效果：

- 重新加载当前时间范围、当前知识库下的数据。
- 加载中按钮会显示 loading 状态。

### 3. 错误提示

如果接口失败，页面会显示红色错误提示。

常见文案来自源码：

- `加载成本看板失败`
- 或具体接口返回的错误信息。

## 四、成本看板：常见流程

### 流程 1：查看最近 24 小时成本

1. 进入 **成本运营 → 成本看板**。
2. 确认时间范围是 `24h`。
3. 查看 4 张统计卡片：总成本、每千次问答成本、平均上下文 Tokens、高成本 Query。
4. 查看 **成本趋势** 是否有明显升高。
5. 查看 **高成本 Query Top 10**，找出成本最高的请求。

### 流程 2：排查某个知识库成本

1. 在 Admin 顶部或全局知识库选择器中选择目标知识库。
2. 进入 **成本运营 → 成本看板**。
3. 页面说明里确认“当前知识库”是否正确。
4. 切换 `1h`、`24h`、`7d` 对比不同时间范围。
5. 查看高成本请求是否集中在某个策略版本或模型上。

### 流程 3：判断是否上下文太长导致成本高

1. 查看统计卡片里的 **平均上下文 Tokens**。
2. 查看高成本 Query 表里的 **上下文 Tokens**。
3. 如果 Token 数很高，通常说明请求带给模型的文本比较长，成本可能变高。
4. 结合 `Request ID` 去其他日志页面继续排查。

## 五、Vector DB 页面

### 1. 页面用途

Vector DB 页面用于查看向量数据库里的 Collection 列表、健康状态和最近操作记录。

页面标题为 **Vector DB**，说明文字为：

> 查看 Collection 列表、健康状态和最近操作记录。

### 2. 适合谁用

适合这些人使用：

- 技术运维：确认向量库 Collection 是否健康。
- 管理员：查看当前 Active Collection 是哪个。
- 后端/算法同学：排查索引版本、Collection 状态、最近操作记录。

### 3. 进入路径

左侧菜单：

**成本运营 → Vector DB**

页面地址：

`/cost-ops/vector-db`

---

## 六、Vector DB：页面区域

Vector DB 页面目前分为 4 个区域：

1. 顶部标题和刷新按钮
2. 错误提示
3. Collections 表格
4. Recent Operations 表格
5. 健康详情弹窗

### 1. Collections 表格

区域标题：**Collections**

如果没有记录，会显示：

`当前没有 Collection 记录`

表格字段：

| 列名 | 字段 | 含义 |
|---|---|---|
| Collection | `collection_name` | Collection 名称，可以理解为向量库里的一个数据集合 |
| Index Version | `index_version` | 索引版本，页面用代码样式显示 |
| Active | `active` | 是否当前正在使用；`active` 表示正在使用，`inactive` 表示未使用 |
| Health | `health_status` | 健康状态，具体值由后端返回 |
| Status | `status` | Collection 状态，具体值由后端返回 |
| 操作 | - | 当前只有“健康详情”按钮 |

源码中 `VectorCollection` 还定义了这些字段，但当前表格没有展示：

| 字段 | 含义 |
|---|---|
| `index_status` | 索引状态 |
| `schema_version` | Schema 版本 |
| `rollback_collection` | 可回滚 Collection |
| `contract_gaps` | 前后端契约差异提示 |

### 2. Active 状态

`Active` 列有两种显示：

| 显示 | 含义 |
|---|---|
| `active` | 当前启用中的 Collection |
| `inactive` | 当前未启用 |

### 3. Health 状态

`Health` 列展示 `health_status`。

源码没有限定具体枚举值，所以页面会把后端返回的值原样显示成标签。

常见理解方式：

- 健康：可以正常查询。
- 不健康：可能存在 Collection 不存在、维度不匹配、加载失败、冒烟查询失败等问题。

> 注意：上面是根据健康详情类型字段的含义解释；具体状态文字以接口返回为准。

### 4. Status 状态

`Status` 列展示 `status`。

源码没有限定具体枚举值，页面会原样显示后端返回值。

### 5. Index Version

`Index Version` 是索引版本。

用途：

- 区分不同批次、不同配置构建出来的向量索引。
- 排查问题时，可以知道当前请求或 Collection 用的是哪个索引版本。

### 6. 集合统计和容量说明

当前 `vector-db-page.tsx` 的 Collections 表格只展示：

- Collection 名称
- Index Version
- Active
- Health
- Status
- 健康详情按钮

源码中没有展示这些常见的容量/统计信息：

- 向量条数
- 文档数
- 分片数
- 存储容量
- 内存占用
- 磁盘占用
- Collection 大小

所以当前页面只能看 Collection 是否存在、是否 active、健康状态和最近操作，不能直接看容量使用量或向量数量。

### 7. 索引参数说明

`types/kb.ts` 中另有 `IndexRegistryRecord` 类型，包含以下索引生命周期字段：

| 字段 | 含义 |
|---|---|
| `index_version` | 索引版本 |
| `collection_name` | Collection 名称 |
| `collection_role` | Collection 角色，如 active/candidate/standby/rollback/deprecated |
| `embedding_model` | 向量模型 |
| `embedding_dimension` | 向量维度 |
| `metric_type` | 向量距离计算方式 |
| `index_type` | 索引类型 |
| `index_params` | 索引参数 |
| `build_status` | 构建状态 |

但是这些字段属于索引生命周期相关类型，**当前 Vector DB 页面没有展示这些完整索引参数**。

当前 Vector DB 页面直接展示的索引相关字段只有：

- `Index Version`
- `Health`
- `Status`
- 健康详情弹窗中的后端返回 JSON

## 七、Vector DB：Recent Operations

区域标题：**Recent Operations**

当前页面固定请求第 1 页、每页 20 条最近操作记录。

表格字段：

| 列名 | 字段 | 含义 |
|---|---|---|
| Operation | `operation` | 操作类型，例如构建、切换、回滚等，具体值由后端返回 |
| Collection | `collection_name` | 被操作的 Collection |
| Index Version | `index_version` | 操作关联的索引版本 |
| Reason | `operation_reason` | 操作原因；没有则显示 `-` |

源码中 `VectorOperation` 还定义了 `created_at`，但当前表格没有展示操作时间。

## 八、Vector DB：按钮、弹窗和操作

### 1. 刷新

按钮：**刷新**

效果：

- 重新加载 Collection 列表。
- 重新加载最近 20 条操作记录。

### 2. 健康详情

按钮位置：Collections 表格的“操作”列。

点击后：

1. 页面会打开弹窗。
2. 弹窗标题是当前 Collection 名称。
3. 前端会调用健康详情接口。
4. 如果有数据，会以 JSON 格式展示。
5. 如果没有数据，会显示：`暂无健康详情`。

健康详情接口使用的是：

`GET_VECTOR_COLLECTION_HEALTH(item.index_version)`

也就是说，源码里实际传入的是 `index_version`。

### 3. 当前没有的操作

`config/api.ts` 中定义了这些接口：

- `REBUILD_VECTOR_COLLECTION`
- `SWITCH_VECTOR_COLLECTION`
- `ROLLBACK_VECTOR_COLLECTION`

但当前 `vector-db-page.tsx` 页面没有对应按钮，所以前端页面上不能直接执行重建、切换、回滚。

## 九、Vector DB：常见流程

### 流程 1：查看当前使用中的 Collection

1. 进入 **成本运营 → Vector DB**。
2. 查看 **Collections** 表格。
3. 找到 `Active` 为 `active` 的行。
4. 记录它的 `Collection` 和 `Index Version`。

### 流程 2：检查 Collection 健康状态

1. 进入 **成本运营 → Vector DB**。
2. 查看 **Health** 列。
3. 如果状态看起来异常，点击该行的 **健康详情**。
4. 在弹窗中查看 JSON 详情。
5. 如果弹窗显示 `暂无健康详情`，说明前端没有拿到健康详情数据。

### 流程 3：查看最近是否有人操作过 Collection

1. 进入 **成本运营 → Vector DB**。
2. 查看 **Recent Operations** 表格。
3. 关注 `Operation`、`Collection`、`Index Version`、`Reason`。
4. 如果某次操作后出现问题，可以根据这些字段继续排查。

## 十、注意事项

1. 成本看板当前只有 `1h`、`24h`、`7d` 三个时间范围。
2. 成本看板会受到当前选中知识库影响；Vector DB 页面当前不按知识库筛选。
3. 成本看板当前没有分页，高成本 Query 固定显示 Top 10。
4. Vector DB 最近操作固定显示前 20 条，页面没有分页按钮。
5. Vector DB 当前没有容量统计展示，例如向量数量、存储大小等。
6. Vector DB 当前没有直接重建、切换、回滚按钮，虽然 API 配置里有对应接口。
7. 如果页面空白或显示 Empty，可能是接口没有返回数据，不一定代表系统没有相关能力。
8. 如果出现红色错误提示，优先检查接口是否正常、是否有权限、后端是否返回错误。

## 十一、术语速查

| 术语 | 简单解释 |
|---|---|
| 成本 | 系统调用模型、向量检索、重排、存储等产生的预估花费 |
| Query | 一次用户问题或一次检索请求 |
| 高成本 Query | 花费较高的请求，通常需要重点排查 |
| Token | 模型处理文本的基本单位，文本越长 Token 越多，成本通常越高 |
| 上下文 Tokens | 传给模型作为参考材料的文本长度 |
| 策略版本 | 系统处理请求时使用的一套策略版本 |
| 模型 | 处理请求时使用的大模型或相关模型 |
| Vector DB | 向量数据库，用来存储和检索文档向量 |
| Collection | 向量数据库里的数据集合 |
| Index Version | 索引版本，用来区分不同构建批次或配置 |
| Active | 当前正在使用 |
| Health | 健康状态，用来判断 Collection 是否能正常工作 |
| Operation | 操作记录，例如构建、切换、回滚等 |
| Contract Gaps | 前后端数据契约差异提示，表示接口字段可能没有完全对齐 |
