# litellm 目录作用速览

## 一句话结论

`litellm/` 是一个**可选的 LLM 网关子项目**：基于 [BerriAI/litellm](https://github.com/BerriAI/litellm)，把不同模型供应商统一成 OpenAI 兼容接口，给主系统提供一个稳定的单一入口（默认 `http://localhost:4000/v1`）。

## 这个目录解决什么问题

- 把多家模型 API（如 DashScope/Qwen）统一成一个调用协议。
- 让业务侧只配置一次 `BaseURL + ModelName`，减少供应商切换成本。
- 提供统一的可观测与成本记录能力（配套 Postgres + Prometheus）。
- 通过管理 UI 可视化管理模型配置和查看调用统计。

## 目录内文件职责

- `config.yaml`：LiteLLM 路由配置。示例里把 `qwen3-max` 通过 `openai/` 前缀映射到 DashScope 兼容接口（`openai/` 前缀告诉 LiteLLM 使用 OpenAI 兼容协议调用该模型）。同时配置了 token 级别的成本定价（含 cache 读写成本），LiteLLM 会据此自动统计每次调用的费用。
- `docker-compose.yml`：一键启动 `litellm + postgres + prometheus` 三个服务。引用了 `.env` 文件用于加载环境变量。
- `prometheus.yml`：Prometheus 抓取 LiteLLM 指标配置（15 秒间隔）。
- `test.py`：基于 OpenAI SDK 的完整测试脚本，发起流式对话并支持深度思考（reasoning）功能验证，分别展示模型的思考过程和最终回复。

## 路由机制说明

`config.yaml` 中的路由规则：

- `model_name: qwen3-max` —— 这是外部调用时使用的名称。
- `model: openai/qwen3-max` —— `openai/` 前缀是 LiteLLM 的约定，表示以 OpenAI 兼容协议调用后面的模型。
- `api_base` —— 实际的模型供应商 API 地址。
- 添加新模型时，需同时配置 `model_name`（对外暴露名）和 `litellm_params.model`（实际调用名+协议前缀）。

## 与本仓库主项目的关系

- 它是**独立可选组件**，主仓库根目录的 `docker-compose.yml` 默认不包含它。
- 主后端本身走 OpenAI 兼容协议；若要接 LiteLLM，只需把模型 `base_url` 指向 LiteLLM 地址即可。

## 快速接入（5 步）

### 1. 补齐 API Key

在 `litellm/config.yaml` 中补齐真实 `api_key`（当前为空）：

```yaml
api_key: sk-your-dashscope-api-key
```

### 2. 创建 .env 文件

`docker-compose.yml` 引用了 `.env` 文件，需在 `litellm/` 目录下创建：

```bash
# 最简配置，内容可以为空
touch .env
```

如需通过环境变量传入 API Key（而非写在 config.yaml 中），可在 `.env` 中添加：

```
DASHSCOPE_API_KEY=sk-your-dashscope-api-key
```

### 3. 启动服务

在 `litellm/` 目录执行：

```bash
docker compose up -d
```

### 4. 健康检查

确认服务启动成功：

```bash
curl http://localhost:4000/health/liveliness
```

### 5. 验证模型调用

运行测试脚本（需先安装 openai 包）：

```bash
pip install openai
python test.py
```

## 管理 UI

启动后可通过浏览器访问 LiteLLM 管理后台：

- 地址：`http://localhost:4000/ui`
- 功能：可视化管理模型配置、查看调用日志与成本统计（因 `store_model_in_db: true` 已启用）。

## 主系统如何使用这个网关

- 将业务模型配置改为：
  - `base_url`: `http://localhost:4000/v1`（本机开发）
  - `model_key`: `qwen3-max`（与 `litellm/config.yaml` 中 `model_name` 对齐）
- 如果后端也在 Docker 内运行，需确保网络可达（同网络或使用可访问的宿主机地址）。

## 安全注意事项

- PostgreSQL 默认密码 `dbpassword9090` 硬编码在 `docker-compose.yml` 中，生产环境请务必修改。
- PostgreSQL 端口 `5432` 直接暴露到宿主机，生产环境建议移除端口映射或限制访问。
- Prometheus 端口 `9090` 同样暴露，生产环境应限制访问。
- `config.yaml` 中 `store_prompts_in_spend_logs: true` 会在日志中记录完整的 prompt 内容，请注意数据隐私合规。

## 何时建议开启 litellm

- 你需要频繁切换模型供应商。
- 你希望统一做模型调用观测、成本统计、限流和治理。
- 你不希望业务代码感知各家厂商差异。

## 何时可以不启用

- 仅接入单一模型供应商，且暂时不需要统一网关能力时，可直接由后端直连模型 API。
