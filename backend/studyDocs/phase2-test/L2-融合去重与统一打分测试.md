# L2 - 融合、去重与统一打分 测试报告

## 测试目标
验证检索结果包含 `score`、`citation`、`source` 字段，检查 `source.route` 标识主贡献路由，验证空结果分类（`empty_reason` 字段）。

## 测试环境
- 测试时间：2026-05-26 01:30 CST
- API 地址：http://localhost:8899/api/admin/kb/retrieve
- 测试数据：知识库 id=1（Go/React 教程）

## 测试用例

### 用例1: 返回结果包含 score、citation、source 字段
- **测试方法**：POST retrieve 并检查返回 items 的字段结构
- **预期结果**：每个 item 包含 content、score、citation（含 kb_id/document_id/chunk_id/file_name/chunk_index）、source（含 route/collection/retriever_version）
- **实际结果**：
```json
{
  "content": "# Go 语言简介...",
  "score": 0.7,
  "citation": {
    "kb_id": 1,
    "document_id": 1,
    "chunk_id": "kb_1_doc_1_chunk_0_...",
    "file_name": "go_introduction.md",
    "chunk_index": 0,
    "snippet_offset": -1
  },
  "source": {
    "route": "dense",
    "collection": "documents",
    "retriever_version": "phase2-hybrid-v1"
  }
}
```
- **测试结论**：✅ 通过

### 用例2: source.route 字段标识主贡献路由
- **测试方法**：检查返回结果中 `source.route` 的值
- **预期结果**：route 为 "dense" 或 "sparse" 或 "hybrid"
- **实际结果**：
  - 当前测试中所有结果的 `source.route` 均为 `"dense"`
  - 代码中 `annotateRetrieveDocs` 函数设置默认 route 为 "hybrid"（useHybrid=true 时）或 "dense"
  - 实际 route 由 metadata 中的 `route` 字段决定
- **测试结论**：✅ 通过

### 用例3: 空结果分类 - Empty-After-Retrieve

  - `result_status: "no_result"` ✅
