# 12.3.1 Agent 单元测试策略

本文档描述本书项目中 Agent 及相关组件的单元测试策略，便于读者落地「评估与测试」实践。

## 一、测试分层

| 层级 | 范围 | 依赖 | 示例 |
|------|------|------|------|
| **单元测试** | 单函数/单组件，无外部服务 | 仅 Go 标准库或 Mock | `BuildEvaluationPrompt`、`parseEvaluationResponse`、工具函数 |
| **组件测试** | 单个 Agent 或 Eino 组件 | Mock LLM / Mock 向量库 | Evaluator + Mock Model、Callbacks 行为 |
| **集成测试** | 多组件协作或真实 API | 可选 DB/Redis/真实 API | `evaluator_test.go`（需配置）、Ragas/TruLens 脚本 |

单元测试应尽量**不依赖**：数据库、Redis、外部 HTTP、真实 LLM。需要时用环境变量或 `t.Skip()` 跳过集成用例。

## 二、推荐策略

1. **Prompt 与解析逻辑必测**  
   - 所有「请求 → Prompt 字符串」的构建函数（如 `BuildEvaluationPrompt`）做表驱动测试，断言输出包含关键字段。  
   - 所有「LLM 输出 → 结构化结果」的解析函数（如 `parseEvaluationResponse`）用若干组合法/非法 JSON 做单测，避免线上解析崩溃。

2. **工具（Tool）单测**  
   - 每个 Tool 的 `Invoke` 在给定合法输入下，校验返回结构或关键字段；非法输入校验错误返回。  
   - 涉及外部服务的 Tool 可用接口抽象 + Mock 或 `--short` 下跳过。

3. **Callbacks / 可观测性**  
   - 已有 `pkg/eino/callbacks/monitoring_test.go`：覆盖 OnStart/OnEnd/OnError 与 TraceID 注入。  
   - 新增 Callback 时同步写单测，保证不阻塞主流程、不依赖真实网络。

4. **评估器（Evaluator）**  
   - 纯逻辑：Prompt 构建、JSON 解析、分数 clamp、NextAction 判断等用单测覆盖。  
   - 需要 LLM 的 `Evaluate`：放在集成测试，通过 `config` 或环境变量控制是否执行，CI 可设为 `-short` 跳过。

5. **表驱动与可读性**  
   - 多组输入用 `[]struct{ name, input, want }` 表驱动。  
   - 测试名清晰表达场景，如 `TestBuildEvaluationPrompt_ContainsDomainAndQuestion`。

## 三、本项目中的落点

- **`internal/agents/evaluation/`**：`prompt_test.go`（Prompt 构建）、`single_answer_evaluator_test.go`（解析与边界）。  
- **`pkg/eino/callbacks/`**：`monitoring_test.go`（已存在）。  
- **`internal/agents/tools/`**：`pdf_test.go` 等工具单测。  
- **`internal/alert/`**：`feishu_test.go`（已存在）。  
- **集成 / 评估集**：见 12.3.2，使用 Ragas/TruLens 与 `scripts/evaluation/` 下的数据集。

## 四、运行方式

```bash
# 仅单元测试（建议 CI 默认）
go test ./internal/agents/evaluation/... ./pkg/eino/callbacks/... -short -count=1

# 含集成测试（需配置 config 与 .env）
go test ./internal/agents/evaluation/... -count=1
```

上述策略对应书中 **12.3.1 Agent的单元测试策略**，与 **12.3.2 自动化评估集构建** 配合使用。
