# 11-报告周报使用说明

## 1. 这个页面是做什么的？

“周报”页面用于查看和生成自动化治理周报。

根据页面说明，它主要帮助你跟踪：

- 风险摘要
- 质量趋势
- 下一步动作

简单理解：这是一个“每周治理情况汇总”页面，方便管理员快速看看最近一段时间系统有没有风险、质量情况如何、后面要做什么。

---

## 2. 适合谁使用？

适合这些人使用：

- 管理员
- 负责知识库治理的人
- 负责质量监控、审计、告警、成本运营的人
- 想快速查看近期系统治理结果的人

如果你只是普通用户，一般不需要看这个页面。

---

## 3. 从哪里进入？

在 Admin 后台左侧菜单中进入：

```text
报告 → 周报
```

页面路由是：

```text
/reports/weekly
```

面包屑显示为：

```text
概览 / 报告 / 周报
```

---

## 4. 页面整体区域说明

页面主要分为 3 个部分：

1. 顶部标题区
2. 周报列表区
3. 周报详情抽屉

---

## 5. 顶部标题区

页面标题是：

```text
周报
```

标题下方说明文字是：

```text
查看自动化治理周报，跟踪风险摘要、质量趋势和下一步动作。
```

右侧有两个按钮：

| 按钮 | 作用 |
|---|---|
| 生成周报 | 调用接口生成一份新的周报 |
| 刷新 | 重新加载周报列表 |

---

## 6. 周报列表区

列表卡片标题是：

```text
Weekly Reports
```

页面打开后，会自动请求周报列表。

当前前端固定请求：

```text
page = 1
page_size = 20
```

也就是说，当前页面最多只加载第一页的 20 条记录。

### 6.1 没有周报时

如果接口返回的周报列表为空，页面会显示：

```text
当前没有周报记录
```

### 6.2 有周报时

如果有周报记录，会显示一个表格。

表格字段如下：

| 列名 | 含义 | 显示来源 |
|---|---|---|
| Report ID | 周报 ID | `id` |
| Generated | 周报生成时间 | `generated_at`，前端会转换成本地时间显示 |
| Window | 周报统计时间窗口 | `window_start` 到 `window_end`，前端会转换成本地日期显示 |
| Risks | 风险数量 | `report.risks` 的数量 |
| 操作 | 可执行操作 | 当前只有“详情”按钮 |

---

## 7. 字段 / 参数含义

### 7.1 周报记录字段

每条周报记录大致包含：

| 字段 | 中文解释 |
|---|---|
| `id` | 周报唯一 ID |
| `generated_at` | 这份周报生成的时间 |
| `window_start` | 周报统计范围的开始时间 |
| `window_end` | 周报统计范围的结束时间 |
| `report` | 周报正文内容 |

### 7.2 report 字段

`report` 是周报的具体内容，类型是 `WeeklyReport`。

源码中定义的字段包括：

| 字段 | 中文解释 | 当前页面是否展示 |
|---|---|---|
| `generated_at` | 周报生成时间 | 列表使用外层 `generated_at`，详情里不单独展示这个字段 |
| `window_start` | 统计开始时间 | 列表使用外层 `window_start` |
| `window_end` | 统计结束时间 | 列表使用外层 `window_end` |
| `quality_summary` | 质量摘要 | 详情中展示为 JSON 文本 |
| `release_summary` | 发布摘要 | 当前页面不展示 |
| `experiment_summary` | 实验摘要 | 当前页面不展示 |
| `index_registry` | 索引注册信息 | 当前页面不展示 |
| `index_operations` | 索引操作记录 | 当前页面不展示 |
| `audit_events` | 审计事件 | 当前页面不展示 |
| `risks` | 风险列表 | 列表显示数量，详情显示具体内容 |
| `next_actions` | 后续动作列表 | 详情显示具体内容 |
| `contract_gaps` | 契约缺口 / 接口能力缺口 | 当前页面不展示 |

## 8. 按钮和操作说明

### 8.1 生成周报

点击“生成周报”后，前端会调用：

```text
POST /admin/kb/reports/weekly
```

请求体是空对象：

```json
{}
```

生成成功后，页面会提示：

```text
已生成周报
```

然后自动重新加载列表。

如果生成失败，会弹出错误提示。错误内容优先显示接口返回的错误信息；如果没有明确错误，则显示：

```text
生成周报失败
```

### 8.2 刷新

点击“刷新”后，前端会重新请求周报列表：

```text
GET /admin/kb/reports/weekly?page=1&page_size=20
```

刷新过程中按钮会显示加载状态。

如果加载失败，页面会显示红色错误提示。错误内容优先显示接口返回的错误信息；如果没有明确错误，则显示：

```text
加载周报失败
```

### 8.3 详情

点击某一行的“详情”按钮，会从右侧打开一个抽屉面板。

注意：当前源码里点击“详情”不会额外请求详情接口，而是直接使用列表里已有的这条数据。

---

## 9. 周报详情抽屉说明

点击“详情”后，会打开右侧抽屉。

抽屉标题是：

```text
周报详情
```

抽屉宽度为 560。

里面当前展示 3 块内容：

### 9.1 风险

显示字段：

```text
report.risks
```

如果有多个风险，会用：

```text
 / 
```

连接显示。

如果没有风险，显示：

```text
-
```

### 9.2 后续动作

显示字段：

```text
report.next_actions
```

如果有多个动作，会用：

```text
 / 
```

连接显示。

如果没有后续动作，显示：

```text
-
```

### 9.3 质量摘要

显示字段：

```text
report.quality_summary
```

前端会把它转换成格式化 JSON 显示。

也就是说，这里不是图表，而是一段结构化文本。

## 10. 当前已定义但页面没有使用的能力

源码中 API 配置还定义了：

```text
GET /admin/kb/reports/weekly/{reportId}
GET /admin/kb/reports/weekly/{reportId}/export
```

分别看起来像是：

- 获取某一份周报详情
- 导出某一份周报

但在当前 `weekly-reports-page.tsx` 页面里：

- 没有调用“获取详情”接口
- 没有导出按钮
- 没有下载或导出操作
- 没有分页控件
- 没有筛选条件
- 没有搜索框

所以使用时不要误以为页面已经支持这些功能。

## 11. 常见使用流程

### 流程一：查看已有周报

1. 进入 Admin 后台。
2. 点击左侧菜单：`报告 → 周报`。
3. 等待页面自动加载周报列表。
4. 查看表格中的生成时间、统计窗口、风险数量。
5. 点击某条记录右侧的“详情”。
6. 在右侧抽屉中查看风险、后续动作和质量摘要。

### 流程二：生成新的周报

1. 进入 `报告 → 周报` 页面。
2. 点击右上角“生成周报”。
3. 等待提示“已生成周报”。
4. 页面会自动刷新列表。
5. 找到新生成的周报，点击“详情”查看内容。

### 流程三：刷新列表

1. 停留在周报页面。
2. 点击右上角“刷新”。
3. 等待按钮加载完成。
4. 查看列表是否出现最新记录。

## 12. 注意事项

1. 当前页面只加载第一页数据，固定 `page_size = 20`，没有分页按钮。
2. “详情”使用的是列表返回的数据，不会重新请求单独详情接口。
3. 当前页面没有导出入口，虽然 API 配置里有导出接口。
4. 质量摘要当前以 JSON 形式展示，小白用户可能需要开发或运维人员帮助解读。
5. 如果列表为空，不一定代表系统没有能力生成周报，也可能只是当前还没有生成过周报。
6. 点击“生成周报”后是否真的能生成成功，取决于后端接口是否正常可用。
7. 页面中部分字段是英文列名，例如 `Report ID`、`Generated`、`Window`、`Risks`。
8. 周报功能可能和特性开关 `RAG_ENABLE_WEEKLY_REPORT` 有关，因为类型定义中包含这个开关名称；但当前页面源码没有直接判断这个开关。

## 13. 常见问题

### Q1：为什么我看不到任何周报？

可能原因：

- 还没有生成过周报。
- 接口返回了空列表。
- 后端接口加载失败。

如果页面有红色错误提示，优先看错误内容。

### Q2：为什么点击“详情”没有看到完整周报？

当前详情只展示：

- 风险
- 后续动作
- 质量摘要

虽然 `WeeklyReport` 类型里还有发布摘要、实验摘要、索引信息、审计事件等字段，但当前页面没有展示这些内容。

### Q3：能不能导出周报？

从 API 配置看，存在导出接口：

```text
/admin/kb/reports/weekly/{reportId}/export
```

但当前页面没有导出按钮，所以不能在这个页面直接导出。

### Q4：为什么质量摘要是一堆代码一样的内容？

因为当前页面直接把 `quality_summary` 转成 JSON 文本显示，没有做成图表或中文解释。

## 14. 术语速查

| 术语 | 简单解释 |
|---|---|
| 周报 | 按一段时间汇总出来的治理报告 |
| Report ID | 周报的唯一编号 |
| Generated | 周报生成时间 |
| Window | 周报统计的时间范围 |
| Risks | 风险，表示这段时间内发现的问题或隐患 |
| 后续动作 | 建议接下来要处理的事情 |
| 质量摘要 | 关于系统质量的数据汇总 |
| JSON | 一种结构化数据格式，看起来像代码，常用于接口返回数据 |
| 抽屉 | 从页面右侧滑出的详情面板 |
| API | 前端向后端请求数据的接口 |
| page_size | 每页加载多少条数据 |
| contract_gaps | 契约或接口能力缺口，通常表示前后端约定中还没完全补齐的部分 |
