# 12-向量运维使用说明

## 1. 页面用途

“向量库运维”用于查看和操作 index / collection 的生命周期信息。

它主要做这些事：

1. 查看当前 active collection。
2. 查看 index registry 列表。
3. 查看最近的 index operation 记录。
4. 对某个 index 做健康检查。
5. 将某个 index 切换为 active。
6. 执行 active 回滚。

源码依据：`vector-ops-page.tsx`、`kb.ts`、`api.ts`。

## 2. 适合谁用

这个页面偏运维和研发，适合：

- 负责知识库向量库的研发同学。
- 需要排查 collection 是否健康的运维人员。
- 需要切换 active index 的管理员。
- 需要查看切换、回滚记录的人。

普通运营人员一般只需要查看，不建议随意点击 Activate 或回滚。

## 3. 进入路径

源码中存在路由：

```text
/vector-ops
```

但当前左侧菜单 `admin-shell.tsx` 里没有把 `/vector-ops` 放进菜单项。

也就是说：

- 这个页面代码存在。
- 可以通过直接访问 `/vector-ops` 进入。
- 当前左侧菜单不显示“向量库运维”。

注意：左侧菜单里另有 **成本运营 > Vector DB**，它对应的是 `/cost-ops/vector-db` 和另一个页面组件，不是本文档描述的 `VectorOpsPage`。

## 4. 页面区域说明

向量库运维页面分为：

1. 顶部标题和操作按钮。
2. 错误提示区。
3. 三个概览卡片。
4. Index Registry 表格。
5. Recent Operations 表格。
6. Health Check 弹窗。

页面加载时会同时请求：

```text
GET /admin/kb/index-lifecycle/registry
GET /admin/kb/index-lifecycle/operations
```

## 5. 顶部操作区

标题：**向量库运维**

说明文字：

> 查看 collection/index registry、health、切换记录和回滚轨迹。

右侧有两个按钮：

| 按钮 | 作用 | 调用接口 |
|---|---|---|
| 回滚 Active | 回滚到 rollback collection。 | `POST /admin/kb/index-lifecycle/rollback` |
| 刷新 | 重新加载 registry 和 operations。 | `GET registry` + `GET operations` |

### 5.1 回滚 Active

点击 **回滚 Active** 后，页面会提交：

```json
{
  "operation_reason": "admin rollback"
}
```

成功后提示：

> 已回滚到 rollback collection

然后重新加载页面数据。

如果失败，会提示：

> 回滚 active 失败

或后端返回的错误信息。

## 6. 概览卡片

顶部下方有 3 张卡片。

### 6.1 Active Collection

显示当前 `collection_role === active` 的记录。

字段包括：

| 字段 | 含义 |
|---|---|
| Version | 当前 active index 的版本。 |
| Collection | 当前 active collection 名称。 |
| Metric | metric 类型。 |

如果没有 active 记录，会显示 `-`。

### 6.2 Registry Count

显示当前 registry 记录数量。

来源：`registry.length`

### 6.3 Operation Count

显示当前 operation 记录数量。

来源：`operations.length`

## 7. Index Registry 表格

这个表格展示 index registry 记录。

如果没有数据，页面显示：

> 当前还没有 index registry 记录

表格行主键是 `index_version`。

### 7.1 表格字段

| 列名 | 字段 | 含义 |
|---|---|---|
| Index Version | `index_version` | index 版本，页面用代码样式展示。 |
| Collection | `collection_name` | collection 名称。 |
| Role | `collection_role` | collection 角色。 |
| Build | `build_status` | 构建状态。 |
| Metric | `metric_type` | metric 类型。 |
| Action | - | 操作按钮。 |

### 7.2 Role 颜色含义

源码里根据角色显示不同颜色：

| Role | 页面颜色含义 |
|---|---|
| `active` | success，当前生效。 |
| `candidate` | processing，候选。 |
| `rollback` | warning，回滚目标。 |
| `deprecated` | default，已废弃。 |
| 其他值 | blue。 |

类型定义中还包含 `standby`，页面没有单独配色，会走默认 blue。

### 7.3 Build 状态颜色含义

源码里根据构建状态显示不同颜色：

| Build | 页面颜色含义 |
|---|---|
| `ready` | success。 |
| `switched` | success。 |
| `building` | processing。 |
| `failed` | error。 |
| `rolled_back` | warning。 |
| 其他值 | default。 |

类型定义中还包含 `pending`，页面没有单独配色，会走 default。

### 7.4 Action 操作

每行有两个按钮：

| 按钮 | 作用 |
|---|---|
| Health | 打开健康检查弹窗，查看该 index 的健康状态。 |
| Activate | 将该 index 切换为 active。当前行如果已经是 active，则按钮禁用。 |

#### Health

点击后调用：

```text
GET /admin/kb/index-lifecycle/health/{indexVersion}
```

成功后打开 Health Check 弹窗。

失败会提示：

> 加载健康检查失败

或后端返回的错误信息。

#### Activate

点击后调用：

```text
POST /admin/kb/index-lifecycle/switch/{indexVersion}
```

请求体为：

```json
{
  "operation_reason": "admin activate"
}
```

成功后提示：

```text
已切换 active：{index_version}
```

然后重新加载 registry 和 operations。

失败会提示：

> 切换 active 失败

或后端返回的错误信息。

## 8. Recent Operations 表格

这个表格展示最近的 index operation 记录。

如果没有数据，页面显示：

> 当前还没有 index operation 记录

表格行主键是 `id`。

### 8.1 表格字段

| 列名 | 字段 | 含义 |
|---|---|---|
| Operation | `operation` | 操作类型。 |
| Index Version | `index_version` | index 版本。 |
| Collection | `collection_name` | collection 名称。 |
| From | `from_role` | 操作前角色。没有则显示 `-`。 |
| To | `to_role` | 操作后角色。没有则显示 `-`。 |
| Reason | `operation_reason` | 操作原因。 |

源码类型里还定义了这些字段，但当前表格不展示：

- `operator_id`
- `health_status`
- `rollback_target`
- `created_at`

## 9. Health Check 弹窗

点击某一行的 **Health** 后，会出现弹窗。

弹窗标题：

```text
Health Check: {index_version}
```

如果正在加载，会显示：

> 加载健康检查中...

如果没有健康检查结果，会显示：

> 当前没有健康检查结果

### 9.1 健康检查字段

| 字段 | 含义 |
|---|---|
| Collection Exists | collection 是否存在。是显示 Yes，否显示 No。 |
| Dimension Match | 向量维度是否匹配。显示 true/false。 |
| Metric Match | metric 类型是否匹配。显示 true/false。 |
| Load Healthy | collection 加载是否健康。显示 true/false。 |
| Query Smoke | 冒烟查询是否健康。显示 true/false。 |
| Message | 健康检查消息，没有则显示 `-`。 |

### 9.2 关闭弹窗

点击取消或关闭弹窗时，页面会清空当前选中的 index 和健康检查结果。

## 11. 常见流程

### 11.1 查看当前 active collection

1. 直接访问 `/vector-ops`。
2. 查看顶部 **Active Collection** 卡片。
3. 重点看 Version、Collection、Metric。

### 11.2 查看某个 index 是否健康

1. 进入 `/vector-ops`。
2. 在 **Index Registry** 表格找到目标 `Index Version`。
3. 点击该行的 **Health**。
4. 在弹窗中查看：
   - Collection Exists
   - Dimension Match
   - Metric Match
   - Load Healthy
   - Query Smoke
   - Message

### 11.3 切换 active index

1. 进入 `/vector-ops`。
2. 在 **Index Registry** 表格找到目标 index。
3. 建议先点击 **Health** 看健康状态。
4. 如果确认要切换，点击 **Activate**。
5. 成功后页面会提示已切换，并自动刷新。
6. 再查看 Active Collection 是否变成新版本。

### 11.4 回滚 active collection

1. 进入 `/vector-ops`。
2. 点击顶部 **回滚 Active**。
3. 成功后页面提示已回滚，并自动刷新。
4. 查看 Active Collection 和 Recent Operations，确认回滚结果。

## 12. 注意事项

- 当前页面不在左侧菜单中，需直接访问 `/vector-ops`。
- `Activate` 和 `回滚 Active` 都是会改变线上 active collection 的操作，使用前要确认目标版本。
- 源码里点击 `Activate` 前没有二次确认弹窗。
- 源码里点击 `回滚 Active` 前也没有二次确认弹窗。
- 建议切换前先用 **Health** 检查目标 index。
- `operation_reason` 目前由前端固定传：`admin activate` 或 `admin rollback`。
- Recent Operations 当前不显示操作时间；虽然类型里有 `created_at`，但表格没有展示。
- Health Check 弹窗只展示健康报告的一部分字段。

## 13. 术语速查

| 术语 | 简单解释 |
|---|---|
| 向量库 | 存放文本向量的数据库或集合。 |
| Collection | 向量库中的集合。 |
| Index | 用于加速向量搜索的索引。 |
| Index Version | index 版本号。 |
| Registry | 登记表，记录有哪些 index / collection。 |
| Active | 当前正在使用的版本。 |
| Candidate | 候选版本，可能准备切换成 active。 |
| Rollback | 回滚目标或回滚动作。 |
| Deprecated | 已废弃版本。 |
| Metric | 向量相似度计算方式。 |
| Dimension | 向量维度。 |
| Health Check | 健康检查。 |
| Smoke Query | 冒烟查询，用一个简单查询检查是否能正常搜索。 |
| Activate | 激活，把某个 index 切换为 active。 |
| Operation | 操作记录，例如切换或回滚。 |
