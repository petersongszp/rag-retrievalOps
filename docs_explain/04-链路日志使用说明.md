# 04-链路日志使用说明

## 1. 页面用途

“链路日志”用于查看知识库相关流程的日志。当前源码里包含两个子页面：

1. **检索日志**：查看每次检索请求的结构化日志，支持按 `request_id`、知识库、状态、时间范围等筛选。
2. **入库日志**：查看文档入库任务的状态、失败原因和人工操作记录。

源码依据：`retrieval-logs-page.tsx`、`ingest-logs-page.tsx`、`kb.ts`、`api.ts`。

## 2. 适合谁用

适合这些人使用：

- 运营人员：想知道某次检索有没有成功、是否无结果、是否报错。
- 知识库管理员：想查看文档入库任务是否完成或失败。
- 研发/算法同学：想根据 `request_id` 下钻单次检索链路。
- 排障人员：想定位入库失败原因、错误类型和操作轨迹。

## 3. 进入路径

左侧菜单：**链路日志**

子菜单：

- **检索日志**：`/trace-logs/retrieval`
- **入库日志**：`/trace-logs/ingest`

也可以从检索实验室跳转：

- 点击 **查看 Trace** 会进入 `/trace-logs/retrieval?request_id=xxx`

## 4. 检索日志

### 4.1 页面用途

检索日志用于查看每次检索请求的记录。

页面说明文字：

> 查看结构化检索日志，按 request_id、知识库、状态和时间范围筛选，并下钻单次 trace 详情。

检索日志列表接口：

```text
GET /admin/kb/retrieve/audit
```

单条详情接口：

```text
GET /admin/kb/retrieve/audit/{request_id}
```

调试详情入口接口：

```text
GET /admin/kb/retrieve/audit/{request_id}/debug
```

### 4.2 检索日志页面区域

检索日志页面分为：

1. 顶部标题和刷新按钮。
2. 筛选表单。
3. 错误提示区。
4. 日志表格。
5. 右侧详情抽屉。

### 4.3 检索日志筛选字段

| 字段 | 含义 |
|---|---|
| 知识库 | 按知识库筛选。默认会带上当前选中的知识库。可以清空，查看全部知识库。 |
| 状态 | 按检索结果状态筛选。 |
| Request ID | 精确查找某一次检索请求。 |
| Query 关键词 | 按查询内容进行模糊搜索。 |
| 时间范围 | 按创建时间范围筛选，支持选择起止时间。 |

状态选项来自源码：

| 状态 | 页面中文 | 简单解释 |
|---|---|---|
| `success` | 成功 | 检索成功。 |
| `no_result` | 无结果 | 检索完成但没有结果。 |
| `filtered_out` | 被过滤 | 结果被过滤掉。 |
| `error` | 错误 | 检索报错。 |
| `timeout` | 超时 | 检索超时。 |

### 4.4 检索日志按钮/操作

| 按钮/操作 | 作用 |
|---|---|
| 刷新 | 按当前筛选条件和页码重新加载列表。 |
| 查询日志 | 提交筛选条件，从第 1 页重新查询。 |
| 重置 | 清空筛选条件，并恢复为当前选中知识库。 |
| 点击表格行 | 打开右侧“Trace 详情”抽屉。 |
| 调试视图 | 跳转到 `/retrieval-lab/debug?request_id=xxx`。 |

页面分页大小固定为 20 条。

### 4.5 检索日志表格字段

| 列名 | 字段 | 含义 |
|---|---|---|
| Query | `query` | 原始查询内容。 |
| Request ID | `request_id` | 请求唯一编号。 |
| KB | `kb_ids` | 涉及的知识库 ID。 |
| Top K | `top_k` | 请求的 Top K。 |
| Final | `final_count` | 最终结果数量。 |
| Duration | `duration_ms` | 总耗时，单位 ms。 |
| Status | `result_status` | 请求结果状态。 |
| Created | `created_at` | 创建时间。 |
| 操作 | - | 可进入调试视图。 |

如果部分字段为空，页面会显示 `Contract gap`。

### 4.6 检索日志详情抽屉

点击一条检索日志后，右侧会打开 **Trace 详情** 抽屉。

如果这条请求没有 P3 调试字段，页面会显示警告：

> 该请求暂无 P3 调试字段

并说明当前仍可查看基础 trace 详情。

详情分为 4 个区域。

#### 4.6.1 请求信息

| 字段 | 含义 |
|---|---|
| Request ID | 请求唯一编号。 |
| KB IDs | 知识库 ID。 |
| Query | 原始查询。 |
| Final Query | 最终查询。 |
| Expr | 表达式或过滤表达式。 |
| Top K | 请求 Top K。 |
| Candidate Top K | 候选 Top K。 |
| Final Top K | 最终 Top K。 |

#### 4.6.2 阶段耗时

| 字段 | 含义 |
|---|---|
| Embedding | 向量化耗时，单位 ms。 |
| Search | 搜索耗时，单位 ms。 |
| Postprocess | 后处理耗时，单位 ms。 |
| Rerank | 重排耗时，单位 ms。 |
| Duration | 总耗时，单位 ms。 |

#### 4.6.3 结果与路由

| 字段 | 含义 |
|---|---|
| Routes | 命中的检索路线。 |
| Collection | 使用的 collection。 |
| Retriever | 检索器版本。 |
| Result Status | 结果状态。 |
| Final Count | 最终结果数量。 |
| Truncated Count | 被截断的数量。 |
| Dense Hits | dense 检索命中数。 |
| Sparse Hits | sparse 检索命中数。 |
| Dense Contribution | dense 贡献。 |
| Sparse Contribution | sparse 贡献。 |

#### 4.6.4 错误与补充信息

这一块包含 P3 摘要和错误信息。

P3 摘要字段：

| 字段 | 含义 |
|---|---|
| parent_child_enabled | 是否启用 parent-child。 |
| topk_policy_version | TopK 策略版本。源码里如果没返回，会显示“当前日志未返回 topk_policy_version”。 |
| evidence_gate_result | 证据门控结果。 |
| citation_support_score | 引用支持分。 |
| refusal_reason | 拒答原因。 |

错误和发布字段：

| 字段 | 含义 |
|---|---|
| Error Code | 错误码。 |
| Error Message | 错误信息。 |
| Strategy | 策略。 |
| Release Stage | 发布阶段。 |
| Release Reason | 发布原因。 |
| Empty Reason | 空结果原因。 |
| Created At | 创建时间。 |

### 4.7 检索日志常见流程

#### 流程一：根据 request_id 查一次请求

1. 进入 **链路日志 > 检索日志**。
2. 在 `Request ID` 输入框粘贴请求 ID。
3. 点击 **查询日志**。
4. 在表格里找到对应记录。
5. 点击该行查看详情，或点击 **调试视图** 查看更细的阶段数据。

#### 流程二：查看某个知识库最近的错误

1. 进入 **检索日志**。
2. 选择知识库。
3. 状态选择 `错误` 或 `超时`。
4. 选择时间范围。
5. 点击 **查询日志**。
6. 查看 `Error Code`、`Error Message`、阶段耗时和路由信息。

## 5. 入库日志

### 5.1 页面用途

入库日志用于查看文档入库任务的状态机和操作审计记录。

页面说明文字：

> 查看入库任务状态机和操作审计记录，定位失败原因与人工操作轨迹。

入库日志列表接口：

```text
GET /admin/kb/logs/ingest
```

入库详情接口：

```text
GET /admin/kb/logs/ingest/{jobId}
```

### 5.2 入库日志页面区域

入库日志页面分为：

1. 顶部标题和刷新按钮。
2. 筛选表单。
3. 错误提示区。
4. 入库任务表格。
5. 右侧入库详情抽屉。

### 5.3 入库日志筛选字段

| 字段 | 含义 |
|---|---|
| 知识库 | 按知识库筛选。默认使用当前选中的知识库。 |
| 状态 | 按入库任务状态筛选。 |
| 错误类型 | 按 `error_code` 筛选。 |
| 时间范围 | 按创建时间范围筛选。 |

入库状态选项来自源码：

| 状态 | 简单解释 |
|---|---|
| `pending` | 等待处理。 |
| `processing` | 正在处理。 |
| `completed` | 已完成。 |
| `failed` | 失败。 |
| `retrying` | 重试中。 |
| `dead` | 已进入死信/不可继续状态。 |
| `canceled` | 已取消。 |

错误类型选项来自源码：

| 错误类型 | 简单解释 |
|---|---|
| `embedding_failed` | 向量化失败。 |
| `milvus_error` | Milvus / 向量库错误。 |
| `canceled_by_operator` | 被操作人取消。 |

### 5.4 入库日志按钮/操作

| 按钮/操作 | 作用 |
|---|---|
| 刷新 | 按当前筛选条件和页码重新加载。 |
| 查询日志 | 提交筛选条件，从第 1 页开始查询。 |
| 重置 | 清空筛选条件，并恢复为当前选中知识库。 |
| 点击表格行 | 打开右侧“入库详情”抽屉。 |

页面分页大小固定为 20 条。

### 5.5 入库日志表格字段

| 列名 | 字段 | 含义 |
|---|---|---|
| Job ID | `id` | 入库任务 ID。 |
| KB | `kb_id` | 知识库 ID。 |
| Document | `document_id` | 文档 ID。 |
| Status | `status` | 当前任务状态。 |
| Error Code | `last_error_code` | 最近一次错误码，没有则显示 `-`。 |
| Operation | `operation` | 最近操作，没有则显示 `-`。 |
| Reason | `operation_reason` | 操作原因，没有则显示 `-`。 |
| Created | `created_at` | 创建时间。 |

### 5.6 入库详情抽屉

点击入库任务行后，右侧打开 **入库详情** 抽屉。

详情包括两个区域：

1. 任务信息
2. 操作审计记录

#### 5.6.1 任务信息

| 字段 | 含义 |
|---|---|
| Job ID | 入库任务 ID。 |
| KB ID | 知识库 ID。 |
| Document ID | 文档 ID。 |
| Status | 当前状态。 |
| Retry Count | 重试次数。 |
| Error Code | 最近错误码。 |
| Error Detail | 最近错误详情。 |
| Operation | 操作。 |
| Operation Reason | 操作原因。 |
| Operated At | 操作时间。 |

#### 5.6.2 操作审计记录

如果没有操作记录，页面显示：

> 该任务暂无操作审计记录

如果有记录，会显示表格：

| 列名 | 字段 | 含义 |
|---|---|---|
| 时间 | `created_at` | 操作记录创建时间。 |
| 操作人 | `operator_id` | 操作人 ID。 |
| 操作 | `operation` | 做了什么操作。 |
| 状态流转 | `from_status -> to_status` | 从哪个状态变成哪个状态。 |
| 原因 | `operation_reason` | 操作原因，没有则显示 `-`。 |

### 5.7 入库日志常见流程

#### 流程一：查看失败的入库任务

1. 进入 **链路日志 > 入库日志**。
2. 选择知识库。
3. 状态选择 `failed` 或 `dead`。
4. 如已知道错误类型，可以选择 `embedding_failed` 或 `milvus_error`。
5. 点击 **查询日志**。
6. 点击某条任务行，查看错误详情和操作审计记录。

#### 流程二：查看某个时间段的入库情况

1. 进入 **入库日志**。
2. 选择知识库。
3. 选择时间范围。
4. 点击 **查询日志**。
5. 根据状态列查看哪些完成、哪些失败、哪些还在处理中。

## 6. 注意事项

- 检索日志按 `request_id` 串联，排查检索问题时优先复制 `request_id`。
- 检索日志的“调试视图”会跳到检索实验室的调试页，不是在当前抽屉里展开。
- 入库日志按 `Job ID` 串联，排查入库问题时优先查看任务详情。
- 页面里出现 `Contract gap`，说明接口字段为空或缺失。
- 检索日志和入库日志的筛选都会使用后端接口查询，前端不是只在当前页过滤。
- 两个日志页面分页大小都是 20 条。
- 重置按钮会恢复到当前选中的知识库，而不是一定查询全部。

## 7. 术语速查

| 术语 | 简单解释 |
|---|---|
| 链路日志 | 一次操作从开始到结束留下的记录。 |
| 检索日志 | 每次知识库检索请求的记录。 |
| 入库日志 | 文档进入知识库、切分、向量化等任务记录。 |
| request_id | 一次检索请求的唯一编号。 |
| Job ID | 一个入库任务的唯一编号。 |
| KB | Knowledge Base，知识库。 |
| Top K | 最多返回前 K 条结果。 |
| Candidate Top K | 候选阶段取的 Top K。 |
| Final Top K | 最终阶段使用的 Top K。 |
| Duration | 总耗时。 |
| Embedding | 把文本转换成向量。 |
| Search | 搜索阶段。 |
| Postprocess | 搜索后的处理阶段。 |
| Rerank | 重排，把候选结果重新排序。 |
| Dense Hits | dense 向量检索命中数量。 |
| Sparse Hits | sparse 稀疏检索命中数量。 |
| Evidence Gate | 证据门控，判断证据是否足够。 |
| Citation | 引用，说明答案依据来自哪里。 |
| Error Code | 错误码。 |
| Operation Log | 操作记录。 |
| 状态流转 | 一个任务从旧状态变成新状态。 |
