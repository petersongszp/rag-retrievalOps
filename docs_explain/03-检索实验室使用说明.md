# 03-检索实验室使用说明

## 1. 页面用途

“检索实验室”用于手动发起一次知识库检索测试，查看这次检索返回了哪些内容，并检查后端是否返回了关键字段。

它主要做三件事：

1. 输入问题，运行检索测试。
2. 查看本次检索的 `request_id`、结果内容、分数、引用信息、来源信息。
3. 把一次检索结果保存为评测样本草稿，后续可在评测集中继续完善。

源码依据：`retrieval-lab-page.tsx`、`retrieval-debug-page.tsx`、`kb.ts`、`api.ts`。

## 2. 适合谁用

适合这些人使用：

- 想验证“某个问题能不能从知识库里搜到答案”的运营或产品人员。
- 想检查检索结果是否正确的知识库管理员。
- 想定位检索链路问题的研发或算法同学。
- 想把真实检索问题沉淀成评测样本的人。

## 3. 进入路径

左侧菜单：**检索实验室**

页面路由：

- 检索实验室：`/retrieval-lab`
- 检索调试视图：`/retrieval-lab/debug`
- 带 request_id 的调试视图：`/retrieval-lab/debug?request_id=xxx`

页面上的按钮也会跳转到：

- 原始检索日志：`/trace-logs/retrieval?request_id=xxx`

## 4. 页面区域说明

### 4.1 顶部说明区

页面标题是 **检索实验室**。

说明文字：运行检索测试、检查 `request_id` 与契约字段，并把一次检索沉淀为评测样本草稿。

这里告诉你这个页面不是正式问答页面，而是调试和验证用的页面。

### 4.2 检索表单区

表单里有 3 个字段：

| 字段 | 是否必填 | 含义 |
|---|---:|---|
| 知识库 | 是 | 选择要在哪个知识库里搜索。选项来自当前系统里的知识库列表。 |
| 查询 | 是 | 输入你要测试的问题或关键词。 |
| Top K | 否 | 想让后端最多返回多少条结果。页面提供 `3`、`5`、`10`，默认是 `5`。 |

点击 **运行检索测试** 后，页面会调用：

```text
POST /admin/kb/retrieve
```

请求内容包含：

- `kb_id`
- `query`
- `top_k`

### 4.3 空状态区

如果还没有运行检索测试，页面会显示提示：

- 已选择知识库时：提示你可以对当前知识库运行测试。
- 未选择知识库时：提示先选择知识库并运行检索测试。

### 4.4 结果顶部区

运行成功后，页面会先显示 **Request ID**。

`request_id` 是本次检索请求的唯一编号，后面查日志、看调试详情都要靠它。

这里有几个按钮：

| 按钮 | 作用 |
|---|---|
| 复制 request_id | 把当前 `request_id` 复制到剪贴板。如果后端没返回，会提示“后端未返回 request_id”。 |
| 查看 Trace | 跳转到检索日志页面，并带上当前 `request_id`。 |
| 查看调试视图 | 跳转到检索调试视图，并带上当前 `request_id`。 |
| 保存为评测样本 | 打开弹窗，把这次检索保存成评测样本草稿。 |

## 5. 检索结果字段说明

每条结果会单独显示成一张卡片。

### 5.1 结果卡片内容

每条结果包含：

| 字段 | 含义 |
|---|---|
| 结果序号 | 例如“结果 1”“结果 2”。 |
| Score | 检索分数，代表这条结果和查询的相关程度。源码只负责展示分数，不定义分数越大越好还是越小越好。 |
| content | 检索返回的正文片段。 |
| 文件 | `citation.file_name`，结果来自哪个文件。 |
| Chunk Index | `citation.chunk_index`，文件切分后的片段序号。 |
| Chunk ID | `citation.chunk_id`，片段唯一标识。 |
| Route | `source.route`，命中的检索路线。 |
| Collection | `source.collection`，使用的向量集合。 |
| Retriever | `source.retriever_version`，检索器版本。 |

如果某些字段后端没返回，页面会显示 **Contract gap**。

### 5.2 Contract gap 是什么

`Contract gap` 可以理解成“前端期望后端返回这个字段，但实际没拿到”。

页面会检查这些字段：

- `score`
- `citation`
- `citation.file_name`
- `citation.chunk_index`
- `citation.chunk_id`
- `source`
- `source.route`
- `source.collection`
- `source.retriever_version`

其中 `score` 和 `citation` 在源码里被标为“阻塞验收”。

### 5.3 契约缺口记录

如果有缺失字段，页面底部会出现一个可展开区域：**契约缺口记录**。

展开后会看到表格：

| 列名 | 含义 |
|---|---|
| 缺失字段 | 哪个字段没返回。 |
| 所属接口 | 对应接口，例如 `POST /admin/kb/retrieve -> items[].score`。 |
| 影响页面 | 固定显示“检索实验室”。 |
| 阻塞验收 | 是/否。 |

## 6. 保存为评测样本弹窗

点击 **保存为评测样本** 后，会打开弹窗。

页面会先加载评测集列表，接口是：

```text
GET /admin/kb/eval/datasets?page=1&page_size=100
```

保存样本时调用：

```text
POST /admin/kb/eval/datasets/{dataset_id}/items
```

### 6.1 弹窗字段

| 字段 | 是否必填 | 含义 |
|---|---:|---|
| 评测集 | 是 | 选择要保存到哪个评测集。没有评测集时，页面会提示先去创建评测集。 |
| Case Key | 是 | 样本唯一标识。页面会自动生成类似 `retrieval-lab-20260526183000` 的值。 |
| Top K | 是 | 本样本记录的 top_k。 |
| Query | 是 | 查询内容，默认使用刚才检索的查询。 |
| Query Type | 否 | 查询类型，例如页面占位提示里的 `factual / multi-hop`。 |
| Collection | 否 | Collection，默认取当前检索结果里第一条有 `source.collection` 的值。 |
| Tags | 否 | 标签，支持用逗号或换行分隔。 |
| Relevant IDs 草稿 | 否 | 相关 chunk_id 草稿。注意它只是草稿，不等于最终标准答案。 |
| Notes | 否 | 备注。 |

### 6.2 弹窗按钮

| 按钮 | 作用 |
|---|---|
| 复制当前结果 chunk_id 到 relevant_ids 草稿 | 把当前检索结果里的 `citation.chunk_id` 去重后写入 `Relevant IDs 草稿`。 |
| 确认 | 保存评测样本。 |
| 取消 | 关闭弹窗并清空弹窗表单。 |

保存成功后，页面提示：

> 样本已保存，请前往评测集页面补齐标准答案并执行校验。

这说明当前保存的是草稿，不是已经验收过的标准答案。

## 7. 检索调试视图说明

调试视图用于按阶段查看一次检索请求。

进入方式：

- 在检索实验室结果区点击 **查看调试视图**。
- 直接打开 `/retrieval-lab/debug?request_id=xxx`。
- 从检索日志或评测报告跳转进入。

调试视图调用接口：

```text
GET /admin/kb/retrieve/audit/{request_id}/debug
```

### 7.1 调试视图顶部操作

页面顶部有：

| 按钮/入口 | 作用 |
|---|---|
| 返回检索实验室 | 回到 `/retrieval-lab`。 |
| 打开原始 Trace Logs | 打开 `/trace-logs/retrieval`，如果有 `request_id` 会带上它。 |
| Request ID 输入框 | 输入要查询的 `request_id`。 |
| 查询 | 根据输入的 `request_id` 查询调试详情。 |
| 刷新 | 重新加载当前 `request_id` 的调试数据。 |

如果没输入 `request_id`，页面会提示请输入。

### 7.2 请求顶栏

调试数据加载成功后，会看到“请求顶栏”。

字段包括：

| 字段 | 含义 |
|---|---|
| request_id | 本次请求 ID。 |
| original_query | 原始查询。 |
| rewritten_query | 改写后的查询。 |
| kb_ids | 涉及的知识库 ID。 |
| created_at | 创建时间。 |
| debug_available | 是否有可用调试数据。 |
| degradation | 是否发生降级，以及降级原因、错误码、fallback 策略。 |

这里也有 **复制 request_id** 按钮。

### 7.3 集中契约缺口

如果后端返回 `contract_gaps`，页面会以警告形式展示。

这表示调试数据中也有字段缺失或契约不完整的情况。

## 8. 调试视图可展开区域

调试视图下面是一个可展开的折叠面板。默认展开：

- Query Rewrite
- Route Hits
- TopK Decision
- Evidence Gate
- Citation Consistency

另外还可以展开：

- Fusion / Dedupe / Rerank / Filter
- Parent-Child
- Final Results

### 8.1 Query Rewrite

用于看查询是否被改写。

展示字段：

| 字段 | 含义 |
|---|---|
| original query | 用户原始问题。 |
| rewritten query | 改写后的问题。 |
| route final queries | 每条 route 最终使用的 query。 |
| rewrite_strategy | 改写策略。 |
| rewrite_gain_bucket | 改写收益分桶。 |
| term_hits | 命中的词。 |

如果没有 `route final queries`，页面显示 `Contract gap`。

### 8.2 Route Hits

用于看不同检索路线分别命中了什么。

每个 route 会单独显示一张卡片：

| 字段 | 含义 |
|---|---|
| contribution | 该 route 的贡献。 |
| latency_ms | 该 route 耗时。 |
| error | 该 route 错误信息。 |

下面还有一个表格展示 top hits：

| 列名 | 含义 |
|---|---|
| Chunk | `chunk_id`。 |
| File | 文件名。 |
| Route | route 名称。 |
| Score | 分数，页面会格式化为 4 位小数。 |

如果没有 route hits，页面会显示空状态，并可能显示相关 contract gaps。

### 8.3 Fusion / Dedupe / Rerank / Filter

这个区域把多个后处理阶段放在一起看。

#### Fusion

| 字段 | 含义 |
|---|---|
| before | 融合前结果数量。 |
| after | 融合后结果数量。 |

#### Dedupe

| 字段 | 含义 |
|---|---|
| before_count | 去重前数量。 |
| after_count | 去重后数量。 |
| removed | 被去掉的数量。 |

#### Rerank

| 字段 | 含义 |
|---|---|
| rerank_model | 使用的 rerank 模型。 |
| fallback | 是否发生 fallback。 |
| reason | fallback 或 rerank 说明原因。 |

#### Filter

| 字段 | 含义 |
|---|---|
| before_count | 过滤前数量。 |
| after_count | 过滤后数量。 |
| truncate_reason | 截断原因。 |

### 8.4 Parent-Child

用于看父子片段补全相关信息。

展示字段：

| 字段 | 含义 |
|---|---|
| parent_child_enabled | 是否启用 parent-child。 |
| parent_fill_strategy | 父片段填充策略。 |
| parent_fill_tokens | 父片段填充 token 数。 |
| fallback_reason | fallback 原因。 |

下面有两个表格：

- **Child Hits**：子片段命中。
- **Parent Contexts**：父片段上下文。

表格列和 Route Hits 类似：Chunk、File、Route、Score。

如果没有 parent-child 数据，页面显示空状态。

### 8.5 TopK Decision

用于看最终 TopK 是怎么决定的。

展示字段：

| 字段 | 含义 |
|---|---|
| candidate_topk | 候选 TopK。 |
| final_topk | 最终 TopK。 |
| score_distribution | 分数分布。 |
| rerank_gap | rerank 差距。 |
| evidence_density | 证据密度。 |
| token_budget | token 预算。 |
| topk_decision_reason | TopK 决策原因。 |

### 8.6 Evidence Gate

用于看证据门控是否通过。

展示字段：

| 字段 | 含义 |
|---|---|
| evidence_gate_result | 证据门控结果。 |
| refusal_reason | 拒答原因。 |
| thresholds.min_rerank_score | 最小 rerank 分数阈值。 |
| thresholds.min_density | 最小密度阈值。 |
| thresholds.min_citation_coverage | 最小引用覆盖阈值。 |
| evidence_gate_error | 证据门控错误。 |
| refusal_template_version | 拒答模板版本。 |

### 8.7 Citation Consistency

用于看引用一致性检查。

展示字段：

| 字段 | 含义 |
|---|---|
| citation_supported | 引用是否支持答案。 |
| citation_support_score | 引用支持分。 |
| unsupported_claims | 不被引用支持的说法。 |
| citation_check_version | 引用检查版本。 |

页面还会提示：

> 当前后端尚未返回 citation snippets 与 child/parent 对照专用结构

这是源码里的固定提示。

### 8.8 Final Results

用于看最终返回给用户的结果。

每条结果展示：

- Result 序号
- content 正文
- route
- file
- chunk
- kb

如果有 `request_id`，每条结果旁边会有 **跳转原始详情** 按钮，进入原始检索日志。

## 9. 常见流程

### 9.1 测试一个知识库能不能搜到内容

1. 进入 **检索实验室**。
2. 选择知识库。
3. 在“查询”里输入问题。
4. 选择 Top K，比如 `5`。
5. 点击 **运行检索测试**。
6. 查看结果卡片里的内容、文件、chunk、score。

### 9.2 发现结果不对，查看详细链路

1. 先运行检索测试。
2. 复制或记下 `request_id`。
3. 点击 **查看调试视图**。
4. 重点查看：
   - Query Rewrite：问题是否被错误改写。
   - Route Hits：是不是某条 route 没命中。
   - Fusion / Dedupe / Rerank / Filter：是否被去重、重排、过滤影响。
   - Evidence Gate：是否因为证据不足被拒。
   - Final Results：最终输出是否合理。

### 9.3 保存一条评测样本草稿

1. 运行检索测试。
2. 点击 **保存为评测样本**。
3. 选择评测集。
4. 检查 Case Key、Query、Top K。
5. 如有需要，点击 **复制当前结果 chunk_id 到 relevant_ids 草稿**。
6. 填写 Tags 或 Notes。
7. 点击确认保存。
8. 后续去评测集页面补齐标准答案并校验。

## 10. 注意事项

- `request_id` 很重要，查日志和调试都靠它。
- `Relevant IDs 草稿` 只是草稿，不代表最终正确答案。
- 页面出现 `Contract gap` 时，通常说明后端接口没有返回前端期望的字段。
- 如果调试视图没有数据，可能是当前 `request_id` 没有调试信息，或后端接口没有返回。
- `Score`、`Route`、`Collection`、`Retriever` 都来自后端返回，前端只展示，不做业务解释。
- 保存评测样本前必须已有评测集；没有评测集时页面会提示去创建。

## 11. 术语速查

| 术语 | 简单解释 |
|---|---|
| 检索 | 从知识库里找和问题相关的内容。 |
| request_id | 一次请求的唯一编号。 |
| Top K | 最多取前 K 条结果。 |
| Chunk | 文档被切分后的一个小片段。 |
| Chunk ID | 片段唯一标识。 |
| Citation | 引用信息，说明结果来自哪个文件、哪个片段。 |
| Route | 检索路线，例如不同检索方式或策略分支。 |
| Collection | 向量库里的集合。 |
| Retriever | 检索器或检索器版本。 |
| Contract gap | 前端期望有字段，但后端没返回。 |
| Query Rewrite | 查询改写，把原问题改成更适合检索的形式。 |
| Fusion | 多路结果融合。 |
| Dedupe | 去重。 |
| Rerank | 对候选结果重新排序。 |
| Filter | 过滤不需要的结果。 |
| Fallback | 主流程不可用时使用备用策略。 |
| Evidence Gate | 证据门控，用来判断证据是否足够。 |
| Citation Consistency | 引用一致性检查，判断答案是否被引用支持。 |
