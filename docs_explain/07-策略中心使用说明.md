# 07-策略中心使用说明

## 页面用途

策略中心用于管理和观察 Phase 3 高级检索策略。

页面源码里的说明是：查看 Phase 3 高级检索策略的状态、影响、版本和最小操作日志，并在需要时安全地做灰度或回滚。

简单说，它可以用来做这些事：

- 查看每个策略开关（Feature Flag）当前是什么状态。
- 查看策略是否启用、灰度比例是多少、风险等级是什么。
- 查看某个策略在 1h、24h、7d 范围内的 Impact 指标。
- 查看 Gate 摘要，判断策略是否通过质量门禁。
- 查看版本列表和操作日志。
- 修改策略状态、灰度比例。
- 回滚当前策略，或全量回滚到 Phase2 Baseline。

## 适合谁用

- 负责检索策略发布的研发同学。
- 需要观察策略质量和风险的算法同学。
- 需要判断是否继续灰度、放量或回滚的负责人。
- 需要查看策略操作记录的管理员。

## 进入路径

在 Admin 左侧菜单进入：**策略中心**。

对应前端路由是：`/strategy-center`。

页面会使用这些接口：

| 操作 | 接口 |
|---|---|
| 获取策略列表 | `GET /admin/kb/strategy/flags` |
| 修改策略 | `PATCH /admin/kb/strategy/flags/{flagKey}` |
| 获取版本列表 | `GET /admin/kb/strategy/versions` |
| 回滚策略 | `POST /admin/kb/strategy/rollback` |
| 获取 Impact | `GET /admin/kb/strategy/impact` |
| 获取 Gate 摘要 | `GET /admin/kb/strategy/gates` |
| 获取操作日志 | `GET /admin/kb/strategy/operations` |

## 页面区域

### 1. 标题区

标题：**策略中心**。

说明文字：查看 Phase 3 高级检索策略的状态、影响、版本和最小操作日志，并在需要时安全地做灰度或回滚。

右侧按钮：

- **查看评测运行**：跳转到 `/evaluation/runs`。
- **刷新**：重新加载策略列表和概览操作日志。

### 2. 顶部统计卡片

页面顶部有 4 张统计卡片：

| 卡片 | 含义 |
|---|---|
| 启用策略数 | `enabled` 为 true 的策略数量。 |
| Canary 策略数 | `status` 等于 `canary` 的策略数量。 |
| Error 策略数 | `status` 等于 `error` 的策略数量。 |
| 最近回滚次数 | 最近 50 条操作日志里，`operation` 等于 `rollback` 的数量。 |

### 3. Feature Flags 列表

左侧卡片标题是 **Feature Flags**。

它展示所有策略开关。表格字段包括：

| 字段 | 含义 |
|---|---|
| 策略 | 显示 `label`，如果没有 label 就显示 `flag_key`。下面会显示具体 `flag_key`。 |
| 状态 | 显示 `status`，用不同颜色 Tag 标记。 |
| 灰度 | 显示 `rollout_percentage`，也就是灰度百分比。没有值时显示 `gap`。 |
| 风险 | 显示 `risk_level`，没有值时显示 `unknown`。 |

这个表格是单选表格。点击某一行，就会选中该策略，并在右侧展示详情。

如果没有策略，会显示：

> 当前没有可展示的策略开关。

如果策略加载失败，会显示错误提示，并提供 **重试** 按钮。

### 4. 策略详情卡片

选中某个 Feature Flag 后，右侧第一张卡片展示它的详情。

字段包括：

| 字段 | 含义 |
|---|---|
| flag_key | 策略开关的唯一标识。 |
| label | 策略展示名。缺失时显示 `Contract gap`。 |
| status | 当前策略状态。 |
| enabled | 是否启用，显示 `true` 或 `false`。 |
| rollout_percentage | 灰度比例，0 到 100。 |
| strategy_version | 当前策略版本。缺失时显示 `Contract gap`。 |
| risk_level | 风险等级。`high` 会用红色 Tag。 |
| updated_at | 更新时间。 |

右上角有 4 个操作控件：

- 时间范围选择：`1h`、`24h`、`7d`。
- **修改策略**。
- **回滚当前策略**。
- **回滚到 Phase2 Baseline**。

## Feature Flags 和状态说明

Feature Flag 可以理解成「策略开关」。它控制某个检索策略是否启用、启用到什么阶段、放量多少。

源码支持的状态有 6 种：

| 状态 | 简单解释 |
|---|---|
| enabled | 已启用。通常表示策略正在生效。 |
| disabled | 已关闭。策略不生效。 |
| shadow | 影子模式。通常用于后台观察，不直接影响主流程。 |
| canary | 金丝雀/灰度模式。通常表示只对一部分流量生效。 |
| rolling_back | 正在回滚。表示策略处于回退过程中。 |
| error | 异常状态。表示策略或发布过程出现错误。 |

前端颜色规则：

| 状态 | 颜色 |
|---|---|
| enabled | success |
| shadow | processing |
| canary | orange |
| rolling_back | warning |
| error | error |
| 其他/空 | default |

## Impact 分析

Impact 分析用于看选中策略在某个时间范围内的影响。

可选时间范围：

- `1h`
- `24h`
- `7d`

切换时间范围后，页面会重新请求 Impact 数据。

### Impact 展示字段

| 字段 | 含义 |
|---|---|
| sample_size | 样本数量。 |
| parent_fill_gain | 父子内容填充带来的收益。 |
| rewrite_gain | Query Rewrite 带来的收益。 |
| evidence_refusal_rate | 证据不足时拒答的比例。 |
| refusal_false_positive_rate | 错误拒答比例，也就是不该拒答却拒答的比例。 |
| citation_support_score | 引用支持分数。 |
| p95_latency_delta_ms | P95 延迟变化，单位毫秒。 |
| avg_context_tokens_delta | 平均上下文 token 数变化。 |
| route_contribution.dense | dense 路由贡献。 |
| route_contribution.sparse | sparse 路由贡献。 |

### Impact 提示

如果 `sample_size_too_small` 为 true，页面会显示黄色提示：

> 样本量不足

如果 `contract_gaps` 有内容，页面会显示黄色提示：

> Impact 存在契约缺口

并把缺口字段用逗号拼接展示。

如果某些指标缺失，页面会显示：`Contract gap`。

## Gate 摘要

Gate 摘要用于判断当前策略是否通过质量门禁。

展示字段包括：

| 字段 | 含义 |
|---|---|
| gate_status | Gate 状态。没有值时显示 `unknown`。 |
| passed | 是否通过。true 显示绿色，false 显示红色。 |
| failed_rules | 失败规则列表。没有失败规则时显示 `none`。 |
| baseline_report_id | 基线报告 ID。 |
| candidate_report_id | 候选报告 ID。 |
| last_eval_run_id | 最近一次评测运行 ID。 |

如果 Gate 数据加载失败，会显示错误提示。

如果没有 Gate 数据，会显示：

> 当前没有 gate 数据。

## 版本列表

版本列表展示当前策略最近的版本记录。

页面请求版本接口时会带：

- `flag_key`：当前选中的策略。
- `page=1`
- `page_size=10`

表格字段包括：

| 字段 | 含义 |
|---|---|
| Version ID | 版本 ID。 |
| Created By | 创建人。 |
| Gate | 该版本的 Gate 状态。没有值时显示 `pending`。 |
| Created At | 创建时间。 |

如果没有版本记录，会显示：

> 当前没有版本记录。

## 操作日志

操作日志展示当前策略最近的操作记录。

页面请求操作日志时会带：

- `flag_key`：当前选中的策略。
- `page=1`
- `page_size=10`

表格字段包括：

| 字段 | 含义 |
|---|---|
| Operation | 操作类型。缺失时显示 `Contract gap`。 |
| From | 操作前状态。没有值时显示 `n/a`。 |
| To | 操作后状态。没有值时显示 `n/a`。 |
| Reason | 操作原因。 |
| Time | 操作时间。 |

如果没有操作日志，会显示：

> 当前没有操作日志。

## 按钮/操作

### 查看评测运行

跳转到 `/evaluation/runs`，用于查看评测运行列表。

### 刷新

重新加载策略列表和最近 50 条概览操作日志。

注意：选中策略的 Impact、Gate、版本、操作日志，会在选中策略或时间范围变化时自动加载。

### 修改策略

打开「修改策略」弹窗。

提交后会调用：`PATCH /admin/kb/strategy/flags/{flagKey}`。

提交内容包括：

| 字段 | 含义 |
|---|---|
| enabled | 是否启用，必填。 |
| status | 策略状态，必填。可选 enabled/disabled/shadow/canary/rolling_back/error。 |
| rollout_percentage | 灰度比例，必填，范围 0 到 100。 |
| reason | 修改原因，必填。 |

提交成功后：

1. 页面提示：`策略已更新`。
2. 关闭弹窗。
3. 重新加载策略列表。
4. 重新加载当前策略详情相关数据。

### 回滚当前策略

打开「回滚当前策略」弹窗。

提交后会调用：`POST /admin/kb/strategy/rollback`。

请求内容：

```json
{
  "target_version": "phase2_baseline",
  "flag_keys": ["当前选中的 flag_key"],
  "reason": "用户填写的回滚原因"
}
```

也就是说，它只回滚当前选中的策略，目标版本固定为 `phase2_baseline`。

### 回滚到 Phase2 Baseline

打开「回滚到 Phase2 Baseline」弹窗。

提交后同样调用：`POST /admin/kb/strategy/rollback`。

请求内容：

```json
{
  "target_version": "phase2_baseline",
  "reason": "用户填写的回滚原因"
}
```

注意这里不会传 `flag_keys`，表示按后端逻辑做全量回滚。

弹窗提示文案说明：

> 影响范围：全部 Phase 3 flags，目标版本为 phase2_baseline。

源码里还说明：全量回滚会「按后端冻结顺序做全量回滚」。具体冻结顺序由后端决定，前端没有展开显示。

## 可展开/弹窗/详情页

### 修改策略弹窗

点击 **修改策略** 打开。

弹窗字段：

- Enabled：true/false。
- Status：enabled、disabled、shadow、canary、rolling_back、error。
- Rollout Percentage：0 到 100。
- Reason：修改原因，必填。

如果当前策略 `risk_level` 是 `high`，弹窗会显示黄色警告：

> 高风险策略
>
> 从 disabled 到 enabled 时建议先走 shadow 或 canary，避免直接全量开启。

如果页面判断当前选择属于高风险直接启用，还会显示红色提示：

> 当前选择会触发后端高风险校验
>
> 请优先选择 shadow 或 canary，再逐步扩大 rollout。

源码中的判断条件是：

- 当前策略 `risk_level` 是 `high`；
- 当前策略原本未启用；
- 弹窗里选择 enabled 为 true；
- status 不是 `shadow`；
- status 不是 `canary`。

### 回滚弹窗

点击 **回滚当前策略** 或 **回滚到 Phase2 Baseline** 打开。

弹窗只有一个必填字段：Reason。

不同按钮的影响范围不同：

| 按钮 | 影响范围 |
|---|---|
| 回滚当前策略 | 仅当前选中的策略。 |
| 回滚到 Phase2 Baseline | 全部 Phase 3 flags。 |

提交成功后，页面会记录最近一次回滚结果，并显示绿色提示：

- 最近回滚 ID。
- 如果返回了 `changed_flags`，还会显示 Changed flags 列表。

### 详情页

策略中心本身没有跳转到单独策略详情页。

右侧详情、Impact、Gate、版本列表、操作日志都在当前页面内展示。

## Phase2 Baseline 回滚说明

前端所有回滚请求的 `target_version` 都固定为：`phase2_baseline`。

有两种回滚方式：

1. **回滚当前策略**：传入当前 `flag_key`，只回滚一个策略。
2. **回滚到 Phase2 Baseline**：不传 `flag_keys`，让后端执行全部 Phase 3 flags 的回滚。

小白可以这样理解：

- 如果只有一个策略出问题，先用「回滚当前策略」。
- 如果 Phase 3 整体策略都有风险，才用「回滚到 Phase2 Baseline」。

## 常见流程

### 流程 1：查看某个策略是否健康

1. 打开 **策略中心**。
2. 在左侧 Feature Flags 里点击一个策略。
3. 看右侧 `status`、`enabled`、`rollout_percentage`、`risk_level`。
4. 看 Impact 分析，确认样本量、收益、延迟变化。
5. 看 Gate 摘要，确认 `passed` 是否为 true。
6. 看版本列表和操作日志，了解最近是否有人改过。

### 流程 2：把策略先灰度开启

1. 选择目标策略。
2. 点击 **修改策略**。
3. 设置 `enabled=true`。
4. 设置 `status=canary` 或 `shadow`。
5. 设置较小的 `rollout_percentage`。
6. 填写 Reason。
7. 点击确认。
8. 等数据回来后，看 Impact 和 Gate。

### 流程 3：高风险策略不要直接全量启用

1. 如果策略 `risk_level=high`，打开修改弹窗会看到高风险提示。
2. 不建议直接从 disabled 改成 enabled 且非 shadow/canary。
3. 推荐先选 `shadow` 或 `canary`。
4. 观察 Impact 和 Gate 后，再逐步扩大 rollout。

### 流程 4：回滚一个出问题的策略

1. 在 Feature Flags 里选中出问题的策略。
2. 点击 **回滚当前策略**。
3. 填写 Reason，例如「延迟回退」或「质量异常」。
4. 点击确认。
5. 看页面底部最近回滚提示。
6. 再查看操作日志确认回滚记录。

### 流程 5：全量回滚到 Phase2 Baseline

1. 确认不是单个策略问题，而是 Phase 3 整体需要回退。
2. 点击 **回滚到 Phase2 Baseline**。
3. 阅读弹窗里的影响范围提示。
4. 填写 Reason。
5. 点击确认。
6. 等待后端返回结果。
7. 查看 Changed flags 和操作日志。

## 注意事项

- 修改策略和回滚都要求填写 Reason。
- `rollout_percentage` 只能填 0 到 100。
- 高风险策略建议先走 `shadow` 或 `canary`。
- `Contract gap` 表示前端期望字段缺失，不一定代表策略失败，但需要关注接口数据是否完整。
- Impact 的 `sample_size_too_small` 表示样本量不足，结论要谨慎。
- 全量回滚到 Phase2 Baseline 影响全部 Phase 3 flags，操作前要确认影响范围。
- 页面不会展示版本详情内容，只展示版本列表。
- 页面不会展示完整操作审计，只展示当前策略最近 10 条操作日志，以及顶部最近 50 条日志里的回滚次数统计。
