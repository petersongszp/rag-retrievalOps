# 09-审计中心使用说明

本文说明 Admin 前端里的 **审计中心** 页面。

> 依据源码：`audit-page.tsx`、`types/kb.ts`、`config/api.ts`。

---

## 一、页面用途

审计中心用于查看系统里的关键治理事件。

页面标题为 **审计中心**，说明文字为：

> 查询关键治理事件、查看脱敏后的 before/after 摘要，并检查 contract gaps。

简单理解：

- 谁做了什么操作？
- 操作的是哪类资源？
- 操作前是什么样？
- 操作后变成什么样？
- 有没有前后端字段契约不一致的提示？

这些信息可以帮助管理员追踪重要操作和排查问题。

---

## 二、适合谁用

适合这些人使用：

- 管理员：查看系统关键操作记录。
- 运维人员：排查某次配置或资源变更。
- 技术同学：根据操作记录定位问题。
- 安全/合规人员：检查重要操作是否有记录。

---

## 三、进入路径

左侧菜单：

**审计中心**

页面地址：

`/audit`

---

## 四、页面区域

审计中心当前分为 4 个区域：

1. 顶部标题和说明
2. 刷新按钮
3. 错误提示
4. Audit Events 表格
5. 审计详情抽屉

---

## 五、筛选说明

当前 `audit-page.tsx` 源码里 **没有提供筛选表单**。

也就是说，页面上目前没有这些筛选项：

- 按操作类型筛选
- 按资源类型筛选
- 按资源 ID 筛选
- 按操作人筛选
- 按时间范围筛选
- 按结果筛选

当前前端固定请求：

- `page: 1`
- `page_size: 20`

所以页面默认只展示接口返回的前 20 条审计事件。

> 如果后端支持更多筛选参数，当前这个前端页面也还没有把它们做成可操作控件。

## 六、表格字段说明

区域标题：**Audit Events**

如果没有数据，会显示：

`当前没有审计事件`

表格字段：

| 列名 | 字段 | 含义 |
|---|---|---|
| Action | `action` | 操作类型，页面用标签显示 |
| Resource | `resource_type` | 被操作的资源类型 |
| Resource ID | `resource_id` | 被操作资源的 ID，没有则显示 `-` |
| Reason | `reason` | 操作原因，没有则显示 `-` |
| Created | `created_at` | 创建时间，页面会转成本地时间显示 |
| 操作 | - | 当前只有“详情”按钮 |

### 1. Action

`Action` 表示发生了什么操作。

源码没有限定具体枚举值，所以页面会把后端返回的 `action` 原样显示。

例如可能是创建、更新、删除、切换、回滚等类型，但具体值要以后端返回为准，不能仅凭前端确定。

### 2. Resource

`Resource` 来自 `resource_type`。

表示这次操作针对的资源类型。

例如可能是知识库、文档、策略、索引、告警等，但当前前端没有枚举定义，实际以接口返回为准。

### 3. Resource ID

`Resource ID` 来自 `resource_id`。

用于定位具体被操作的资源。

如果后端没有返回，会显示 `-`。

### 4. Reason

`Reason` 来自 `reason`。

表示操作原因。

如果没有填写或接口没有返回，会显示 `-`。

### 5. Created

`Created` 来自 `created_at`。

如果有值，会用浏览器本地时间格式显示。

如果没有值，会显示 `-`。

## 七、状态和结果说明

`types/kb.ts` 中的审计事件类型包含 `result` 字段：

| 字段 | 含义 |
|---|---|
| `result` | 操作结果，例如成功或失败，具体值以后端返回为准 |

但是当前审计中心表格没有展示 `result` 字段，详情抽屉里也没有展示该字段。

所以当前页面能直接看到的状态类信息有限，主要是：

- 操作类型 `Action`
- 资源类型 `Resource`
- 操作原因 `Reason`
- 创建时间 `Created`

如果需要看操作结果，需要后续前端增加展示，或通过接口/日志排查。

## 八、按钮和操作

### 1. 刷新

按钮：**刷新**

位置：页面右上角。

效果：

- 重新加载审计事件列表。
- 加载中按钮会显示 loading 状态。

### 2. 详情

按钮：**详情**

位置：每条审计事件的“操作”列。

点击后：

1. 前端会请求该审计事件详情。
2. 右侧打开一个抽屉，标题为 **审计详情**。
3. 抽屉里显示该事件的详细信息。

详情接口地址由源码拼接：

`LIST_AUDIT_EVENTS + '/' + item.id`

也就是：

`/admin/kb/audit/events/{id}`

---

## 九、详情抽屉说明

点击“详情”后，会打开右侧抽屉。

当前抽屉宽度：`520`。

展示字段：

| 区域 | 字段 | 含义 |
|---|---|---|
| Action | `detail.action` | 操作类型 |
| Before | `detail.before` | 操作前摘要，没有则显示 `-` |
| After | `detail.after` | 操作后摘要，没有则显示 `-` |
| Contract Gaps | `detail.contract_gaps` | 契约差异提示，没有则显示 `-` |

### 1. Before

`Before` 表示操作前的内容摘要。

源码说明里提到是“脱敏后的 before 摘要”。

页面会用灰色代码块展示。

### 2. After

`After` 表示操作后的内容摘要。

页面同样用灰色代码块展示。

### 3. Contract Gaps

`Contract Gaps` 表示前端和后端数据契约可能存在的差异。

如果有多个，会用逗号拼接显示。

如果没有，会显示 `-`。

## 十一、常见流程

### 流程 1：查看最近审计事件

1. 进入 **审计中心**。
2. 查看 **Audit Events** 表格。
3. 重点看 `Action`、`Resource`、`Resource ID`、`Reason`、`Created`。
4. 如果想看更详细内容，点击该行的 **详情**。

### 流程 2：排查一次异常变更

1. 进入 **审计中心**。
2. 根据时间大致找到相关记录。
3. 看 `Action` 判断是什么操作。
4. 看 `Resource` 和 `Resource ID` 判断操作对象。
5. 点击 **详情**。
6. 对比 `Before` 和 `After`，确认变更内容。
7. 查看 `Contract Gaps` 是否有契约差异提示。

### 流程 3：确认操作原因

1. 进入 **审计中心**。
2. 在表格中找到相关事件。
3. 查看 `Reason` 列。
4. 如果显示 `-`，说明前端没有拿到操作原因。

---

## 十二、注意事项

1. 当前页面没有筛选控件，只展示接口返回的前 20 条记录。
2. 当前页面没有分页控件，即使接口返回了 `total`、`page`、`page_size`，前端也没有展示分页。
3. `Action`、`Resource`、`Result` 等具体值没有在前端写死枚举，实际以后端返回为准。
4. 详情抽屉只展示 Action、Before、After、Contract Gaps，不展示操作人、IP、请求 ID 等字段。
5. 页面说明提到 before/after 是脱敏摘要；如果看到字段缺失或被隐藏，可能是脱敏处理导致。
6. 如果点击详情失败，页面顶部会显示错误提示。
7. 如果列表为空，页面显示“当前没有审计事件”，不代表后端一定没有历史数据，也可能是权限、接口或分页范围问题。

## 十三、术语速查

| 术语 | 简单解释 |
|---|---|
| 审计 | 记录关键操作，方便追踪谁在什么时候做了什么 |
| 审计事件 | 一条操作记录 |
| Action | 操作类型，比如创建、修改、删除、切换、回滚等，具体以后端返回为准 |
| Resource | 被操作的资源类型 |
| Resource ID | 被操作资源的编号 |
| Reason | 操作原因 |
| Created | 事件创建时间 |
| Before | 操作前的内容摘要 |
| After | 操作后的内容摘要 |
| Contract Gaps | 前后端字段契约差异提示 |
| 脱敏 | 隐藏或替换敏感信息，避免泄露 |
| Drawer/抽屉 | 从页面右侧滑出的详情面板 |
