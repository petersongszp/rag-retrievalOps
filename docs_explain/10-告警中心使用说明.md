# 10-告警中心使用说明

本文说明 Admin 前端里的 **告警中心** 页面。

> 依据源码：`alerts-page.tsx`、`types/kb.ts`、`config/api.ts`。

---

## 一、页面用途

告警中心用于集中查看治理告警，并对告警做“确认”和“解决”。

页面标题为 **告警中心**，说明文字为：

> 汇总质量、成本、容量与审计相关治理告警，并支持确认与解决。

简单理解：

- 系统发现了什么风险？
- 风险属于哪一类？
- 严重程度高不高？
- 现在是未处理、已确认，还是已解决？
- 管理员是否需要点击确认或解决？

---

## 二、适合谁用

适合这些人使用：

- 管理员：处理系统治理告警。
- 运维人员：关注容量、稳定性、成本类风险。
- 技术负责人：判断质量、审计类问题是否需要跟进。
- 运营人员：关注成本异常和高成本风险。

---

## 三、进入路径

左侧菜单：

**告警中心**

页面地址：

`/alerts`

---

## 四、页面区域

告警中心当前分为 4 个区域：

1. 顶部标题和说明
2. 刷新按钮
3. 错误提示
4. Alerts 表格

当前页面没有单独的详情弹窗或抽屉。

---

## 五、筛选说明

当前 `alerts-page.tsx` 源码里 **没有提供筛选表单**。

也就是说，页面上目前没有这些筛选项：

- 按类别筛选
- 按严重级别筛选
- 按状态筛选
- 按知识库筛选
- 按目标对象筛选
- 按时间范围筛选
- 按请求 ID 或 Trace ID 搜索

当前前端固定请求：

- `page: 1`
- `page_size: 20`

所以页面默认只展示接口返回的前 20 条告警。

> 如果后端支持更多筛选参数，当前这个前端页面也还没有做成可操作控件。

---

## 六、表格字段说明

区域标题：**Alerts**

如果没有数据，会显示：

`当前没有治理告警`

表格字段：

| 列名 | 字段 | 含义 |
|---|---|---|
| 标题 | `title` | 告警标题，告诉你大概发生了什么 |
| 类别 | `category` | 告警分类，页面用标签显示 |
| 级别 | `severity` | 严重程度，页面用不同颜色标签显示 |
| 状态 | `status` | 当前处理状态，页面用不同颜色标签显示 |
| Metric | `metric_key` | 关联的指标名，没有则显示 `-` |
| 操作 | - | 当前有“确认”和“解决”两个按钮 |

---

## 七、类别说明

`category` 的类型在源码中定义为：

| 类别 | 小白解释 |
|---|---|
| `quality` | 质量类告警，例如回答质量、检索质量相关问题 |
| `stability` | 稳定性类告警，例如接口失败、服务异常相关问题 |
| `cost` | 成本类告警，例如成本过高、费用异常 |
| `capacity` | 容量类告警，例如存储、索引、资源容量相关问题 |
| `audit` | 审计类告警，例如关键操作记录或审计覆盖相关问题 |

页面会把类别显示成普通标签，颜色没有特殊区分。

---

## 八、级别说明

`severity` 的类型在源码中定义为：

| 级别 | 小白解释 | 页面颜色 |
|---|---|---|
| `low` | 低风险 | 默认色 |
| `medium` | 中等风险 | warning 警告色 |
| `high` | 高风险 | error 错误色 |
| `critical` | 严重风险 | 当前代码没有单独配色，会走默认色 |

注意：

- 源码里 `severity` 支持 `critical`。
- 但页面颜色判断只特殊处理了 `high` 和 `medium`。
- 所以 `critical` 当前不会自动显示成红色，实际会按默认标签颜色显示。

---

## 九、状态说明

`status` 的类型在源码中定义为：

| 状态 | 小白解释 | 页面颜色 | 可用操作 |
|---|---|---|---|
| `open` | 新告警/未处理 | error 红色 | 可以点“确认”，也可以点“解决” |
| `acknowledged` | 已确认，表示有人知道了 | processing 蓝色 | 不能再点“确认”，可以点“解决” |
| `resolved` | 已解决 | success 绿色 | 不能点“确认”，不能点“解决” |

按钮禁用逻辑来自源码：

- “确认”按钮：只有 `status === 'open'` 时可以点。
- “解决”按钮：只要 `status !== 'resolved'` 就可以点。

---

## 十、Metric 字段说明

`Metric` 来自 `metric_key`。

含义：

- 告警关联的指标名。
- 例如可能是成本指标、质量指标、容量指标等。
- 具体值由后端返回。

如果没有值，页面显示 `-`。

类型中还定义了：

| 字段 | 含义 |
|---|---|
| `metric_value` | 当前指标值 |
| `threshold` | 告警阈值 |

但当前表格没有展示 `metric_value` 和 `threshold`。

## 十一、按钮和操作

### 1. 刷新

按钮：**刷新**

位置：页面右上角。

效果：

- 重新加载告警列表。
- 加载中按钮会显示 loading 状态。

### 2. 确认

按钮：**确认**

可点击条件：

- 只有状态为 `open` 的告警可以点击。

点击后：

1. 前端调用确认接口。
2. 请求体中带上：`reason: "admin ack"`。
3. 成功后提示：`已确认告警`。
4. 页面自动重新加载告警列表。

接口：

`/admin/kb/alerts/{alertId}/ack`

### 3. 解决

按钮：**解决**

可点击条件：

- 状态不是 `resolved` 的告警可以点击。
- 状态为 `open` 或 `acknowledged` 都可以点击。

点击后：

1. 前端调用解决接口。
2. 请求体中带上：`reason: "admin resolve"`。
3. 成功后提示：`已解决告警`。
4. 页面自动重新加载告警列表。

接口：

`/admin/kb/alerts/{alertId}/resolve`

### 4. 操作失败

如果确认或解决失败，页面会弹出错误提示。

默认错误文案为：

`更新告警状态失败`

如果接口返回了具体错误信息，会优先显示具体错误。

## 十四、常见流程

### 流程 1：查看当前是否有告警

1. 进入 **告警中心**。
2. 查看 **Alerts** 表格。
3. 如果显示 `当前没有治理告警`，说明当前接口返回为空。
4. 如果有数据，优先看 `级别` 和 `状态`。

### 流程 2：处理新告警

1. 进入 **告警中心**。
2. 找到状态为 `open` 的告警。
3. 查看标题、类别、级别和 Metric。
4. 如果已经有人开始关注，点击 **确认**。
5. 处理完成后，点击 **解决**。

### 流程 3：优先处理高风险告警

1. 进入 **告警中心**。
2. 优先查看 `severity` 为 `high` 的告警。
3. 再查看 `medium`。
4. `low` 可以根据团队规则稍后处理。
5. 注意：`critical` 虽然类型存在，但当前页面没有特殊颜色，需要手动识别文字。

### 流程 4：确认告警是否已解决

1. 进入 **告警中心**。
2. 查看 `状态` 列。
3. 如果是 `resolved`，说明已解决。
4. 如果是 `acknowledged`，说明已确认但还没解决。
5. 如果是 `open`，说明还未确认。

---

## 十五、注意事项

1. 当前页面没有筛选控件，只展示接口返回的前 20 条告警。
2. 当前页面没有分页控件，即使接口返回了 `total`、`page`、`page_size`，前端也没有展示分页。
3. 当前页面没有详情入口，很多字段不会显示，例如摘要、阈值、指标值、创建时间、请求 ID。
4. “确认”会发送固定原因 `admin ack`。
5. “解决”会发送固定原因 `admin resolve`。
6. 点击“确认”或“解决”后，页面会自动刷新列表。
7. `critical` 级别在类型中存在，但当前颜色逻辑没有单独处理。
8. 如果操作按钮是灰色不可点，通常是因为当前状态不允许该操作。
9. 如果页面显示空列表，可能是确实没有告警，也可能是接口、权限或分页范围问题。

## 十六、术语速查

| 术语 | 简单解释 |
|---|---|
| 告警 | 系统发现的风险或异常提醒 |
| 治理告警 | 和质量、稳定性、成本、容量、审计相关的管理类提醒 |
| Category/类别 | 告警属于哪一类，例如成本、容量、审计 |
| Severity/级别 | 告警严重程度，例如 low、medium、high、critical |
| Status/状态 | 告警处理进度，例如 open、acknowledged、resolved |
| Open | 新告警，还没确认 |
| Acknowledged | 已确认，有人知道并关注了 |
| Resolved | 已解决 |
| Metric | 告警关联的指标名 |
| Threshold | 阈值，超过或低于它可能触发告警 |
| Request ID | 请求编号，用来定位一次具体请求 |
| Trace ID | 链路编号，用来追踪一次完整调用链路 |
| Contract Gaps | 前后端字段契约差异提示 |
